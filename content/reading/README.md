# 阅读线源文件

`content/courses/` 放的是**课程**（有可运行代码、有动手题，走 `verify_course.py`）。
这里放的是**阅读线**：一条有顺序的专题线，条目是普通 markdown，不要求能跑代码。

目录名 → 分类 slug，一条线一个目录：

```
content/reading/network/00-总览.md
content/reading/network/01-一次访问.md
```

| 字段 | 说明 |
| --- | --- |
| `title` | 条目标题，库里的唯一可读标识 |
| `category` | 分类 slug（线与条目都靠它归位） |
| `order` | 线内站序，从 0 开始 |
| `minutes` | 预计阅读时长，作者自查用 |
| `status` | 只写 `published` |

正文里可以用的围栏块与课程相同（`quiz` / `learning-path` / `code-tour` / `code-map`），
区别只是**不强制**有 `<!-- run -->`。

## 文风（用户口径：通俗易懂）

写给"能写代码但没系统学过这门课"的人看，不是写给同行评审。

- **先给结论，再讲原因。** 每节第一句就是这一节要回答的问题或答案，不要铺垫。
- **一句话说透一件事。** 长句拆短；一个句子只装一个主语、一个动作。
- **术语第一次出现必须用大白话解释**，并且给一个具体到能想象的东西（"端口就是楼层号，IP 是楼的门牌"）。
- **能用比喻就用比喻，但比喻后面要补一句真实机制**，否则比喻会变成新的误区。
- **不写"很重要""非常关键"这类空话**，直接说它解决什么问题、不做会怎样。
- **每节至少一个具体例子或一条可执行的命令**，不靠抽象描述。
- **少用"因此/综上所述/毋庸置疑"**，那是论文腔。

## 内容纪律（重要）

- **正文必须自己写。** 不以任何第三方文章为底稿做"改写、缩写、换词、调序"——那是演绎作品，
  仍然需要授权，且本项目是公开仓库、线上站点公开可访问，等于二次发布。
- **可以借鉴的是选题与顺序**：主题清单、章节颗粒度属于思想，不受版权保护。
- **不要抄图。** 结构图、流程图、示意图都是原创美术作品；需要图就自己用
  drawio / mermaid 画，或只用文字与表格表达。
- **外部资料只做两件事**：核实事实（以 RFC、官方文档、内核文档、教材为准），
  以及在小节末尾给一条「延伸阅读」链接。链接是正当引用，也保留了对原作者的导流。
- 引用具体数据要能落到来源：协议字段看 RFC，行为看官方文档，不要凭印象写数字。
