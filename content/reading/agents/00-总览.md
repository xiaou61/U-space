## 这条线是干什么的

这条线不教你训练模型，也不比较哪个框架好用。它回答的是**把大模型从"聊天框"变成"能干活的程序"时，真正会卡住你的问题**：

- 一次调用答不好，是因为模型不行，还是因为任务本来就需要多步？
- 模型怎么知道该调哪个工具、传什么参数？
- 为什么同一个问题，第二轮它就"忘了"第一轮说过什么？
- 它答得挺像回事，但怎么证明它真的变好了？

## 一个前提：你已经会调 API

这条线假设你已经能用某个大模型 API 发一次请求、拿到回复。**所有结论都以"用 API 做产品"为背景**，不涉及预训练、微调、GPU 集群，也不要求你会某个具体框架。

如果你还没建立"模型看到的是什么"这个基本认知，建议先读「人工智能」那条线的第一篇（token 与上下文）——本线后面讲上下文工程时会反复用到它。

## 五篇的走法

1. **Agent 到底是什么**：先分清"调一次模型"和"让模型自己决定下一步"的界线在哪，以及这条界线为什么值钱、代价是什么；
2. **ReAct 与规划**：模型怎么做到"想一步、做一步、看结果再改主意"，以及它常见的翻车方式；
3. **工具与 MCP**：模型怎么真的动手——工具描述为什么就是提示词，以及工具多了会怎样；
4. **记忆与上下文**：模型本身没有记忆，所谓"记住"全是你自己存了再塞回去；
5. **评测与上线**：怎么用可重复的方式判断它变好了，以及上线前必须装哪几道护栏。

## 一条主线

这五篇其实在讲同一件事：**Agent 的难点不在模型，在工程**。

模型负责"下一步大概该做什么"，剩下的全是你的责任——给它哪些工具、喂它哪些上下文、允许它走到第几步、出错时怎么兜底、怎么知道它做对了。这些没有一样是换个更大的模型就能自动解决的。

读的时候带着一个具体功能想：你希望它替谁做什么、失败了会怎样。这比记概念有用。
