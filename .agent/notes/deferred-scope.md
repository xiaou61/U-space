# 被划到范围外的能力（暂缓、推迟、否决）

## 背景

Paideia 的产品定位是「千人千面的 AI 个性化学习平台」。截至 2026-10-10，已交付的是地基（WORK-001 骨架、WORK-002 前端组件化、WORK-003 账号与认证）与正在做的只读内容库（WORK-004 知识库）。

在 WORK-004 的连续讨论里逐项裁决了一批能力「本版不做」。2026-10-10 用户问「不做这些都留到哪里了」，实测发现：这些能力有的登记在计划工作项里、有的在项目级暂缓清单里，但**有一批只活在某一份需求的「非目标」一句里，没有任何承接**——包括掌握度与学习路径这一块产品命门。本篇把范围外的东西集中登记一次，避免它们只以"备忘一句"的形式存在。

## 问题

「不做」其实是两种，混在同一句「非目标」里会出事：

- **推迟**：确定要做，只是排在后面。它需要一个未来的归属，否则会忘。
- **否决**：权衡后决定不做。它需要留下理由，否则会被反复提起。

现状是两者都被写成同一句「本版不做」，于是既看不出什么时候该做，也看不出当初为什么不做。

## 备选方案

**为每个范围外能力建一个空壳工作项。** 最强的一面是生命周期 Skill 原生支持、`status`/`resume`/`validate` 全都认它，不需要任何新约定。未选：工作项的开启权在用户手里（用户在 WORK-001 期间明确驳回过 Agent 自行开项），而且空壳工作项会污染「当前有哪几个活动工作项」这个查询结果——一堆 `draft` 会让人分不清哪个真在推进。

**写进 `.agent/INDEX.md`。** 最强的一面是最容易找到，索引本来就是导航入口。未选：INDEX 自己写明「只做模块导航，不复制阶段或任务状态」，而这份清单的核心信息恰恰是状态（已计划／暂缓／已否决），放进去等于让导航页承担状态，正是它被设计来避免的事。

**放进 `.agent/memory.md`。** 最强的一面是它是跨任务长期记忆，本来就要被恢复流程读取。未选：memory.md 保存的是「一句可检索的结论」，不是一张需要逐项维护状态的表；清单会不断变化，塞进去会让记忆条目变成流水账。

**留在各工作项的「非目标」里。** 最强的一面是零新增工件，且范围外的定义与那份需求天然在一起、不会不同步。未选：这正是当前状态，而它已经暴露出问题——WORK-004 的「非目标」无法表达「练习与作答什么时候该做、由谁接」，跨工作项的能力（如掌握度）也不属于任何单一工作项。

## 决策与理由

放在**本篇单个决策说明**里，按「一个能力被明确划到范围外」这一主题记录，不拆成多篇、不建索引。

- 这是生命周期 Skill 明确列出的该写决策说明的情形之一（「一个能力被明确划到范围外，需要留下理由，避免反复被提起」）。
- 每一项写清**状态**（已计划／推迟／暂缓／已否决／未裁决）、**现在记在哪**、**何时该重审**。有触发条件的写触发条件。
- 「已计划」的三项（WORK-005／006／007）仍以 `.agent/changes/WORK-004-知识库/requirements.md` 文末的范围草稿为准，本篇不复制它们的范围描述，只登记存在与依赖关系。

**WORK-005 的需求讨论已开始（2026-10-12）**，其前置（WORK-004）已完成，不再阻塞。讨论中的裁决与待裁决项先记在这里，正式建项时据此起草：

- **已裁决（用户 2026-10-12）**：精简结果**缓存**的形态是「每条目每人一行」式存储；**可见性由生成者在生成时自行选择**（公开／只给自己）——即谁付费谁决定要不要分享；消费者可以把自己的**显示范围**收窄为「只看我的」，但只能在已公开的范围内收窄，不能取到别人的私有结果。默认可见性待定（见下）。
- **待用户裁决**：① 缓存的默认可见性（默认公开／默认私有）；② API Key 的存放与生命周期（只存浏览器／浏览器+服务端会话内存／服务端加密落库——最后一条会推翻已定的"Key 不落库"）；③ 助手壳第一期的能力边界（只精简／精简+单轮提问／提前做多轮）；④ 是否提供平台兜底 Key（否则没配 Key 的人第一期完全用不到 AI，且要决定是否允许他们读别人的公开摘要）；⑤ AgentScope 在 WORK-005 就引入，还是等到 WORK-006。
- **Agent 拟收口（有异议可推翻）**：默认 DeepSeek 端点与模型且可改；`max_tokens` 给足以避开"思考 token 吃满导致静默空响应"；提示词版本进缓存键；第一期不做流式；新建 `paideia-ai` 模块 + 薄端口，业务代码不碰框架类型。

**WORK-006 的需求讨论已开始（2026-10-12）**，其前置（WORK-005）已完成并上线。讨论中的裁决与待裁决项先记在这里，正式建项时据此起草：

## 代价和后果

- **本篇不是生命周期 Skill 的原生工件**：`validate`、`status`、`resume` 都不认识它，不会替我们检查它是否过期，维护靠人。这是选它而不是建工作项的代价。

## 什么情况下该重审

- 发现本篇与已批准工件或真实源码**不一致** → 以后者为准并修正本篇；
