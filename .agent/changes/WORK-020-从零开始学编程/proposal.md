# 提案 · 从零开始学编程（首期 Python・Java）

## 摘要

把「从0学X」做成平台的**一条基准原语——学习线**：一串有序的站，每站是一篇知识库条目。线上先立三条：Python 从零、Java 从零、源码解读。学习线之上才是内容：两门语言各 12 课，按调研过的顺序、误区清单和真实可跑的代码重写，源文件放仓库、一条命令幂等导入。

原语只加两个可空列和一个投影端点，不建"线"表：

1. **`knowledge_categories.line_kind`**（`course` / `reading` / NULL）——线是分类的标记，名字与顺序沿用分类自己的 `name/slug/sort_order`；
2. **`knowledge_entries.sort_order`**（可空）——线的站顺序；没声明就退回既有的 `(published_at, id)`，存量条目一条不改；
3. **`GET /learning/lines`**——按分类投影出线清单，`/learn` 与入口都从这里渲染。

在此之上补三样现在没有的东西：

- **服务端学习记录**——这一课学到哪、哪几题做对、是否通过、什么时候该复习；
- **导师型 AI**——新增 `TUTOR` 行为，先要思路、分级给提示、不贴完整答案，并且**知道你的学情**；
- **学习首页 `/learn`**——不再写死两门课，而是遍历全部线：进度、下一课、今天该复习什么。

复用已有的六种交互块（学习路径、架构地图、走读、练习、小测、运行），不新增渲染器、不建第二套内容系统。**验收标准里有一条是"新加一条线不改一行代码"**——这是可扩展性的唯一硬证据。

## 为什么现在做

现在线上的知识库是 e2e 种子：三条几百字的条目加一条源码解读样板。它能证明管线通，但没有任何一条内容值得读。同时平台已经攒齐了做课程所需的一切能力，却没有一处在教人**从零到能写代码**：

| 已有能力 | 现在服务于 | 缺的那一步 |
| --- | --- | --- |
| 知识库（分类/条目/关系/搜索） | 零散的参考资料 | 没有顺序，没有"这门课有 12 课" |
| 六种交互块（WORK-014/015） | 一篇源码解读样板 | 没有内容去填它们 |
| AI 助手（WORK-005/006/010） | 通用问答、面试、点评 | 没有"导师"行为，也不知道你学到哪 |
| 自评（懂/不懂） | 单条内容的印象 | 不等于"这一课会了" |
| 代码沙箱（WORK-015） | 源码解读里的运行题 | 课程里没有可运行的练习 |
| 积分与计费（WORK-009） | 所有 AI 调用 | 没有按"学习动作"组织的提示 |

一句话：**能力都在，内容与闭环不在。**

## 为什么是"学习线"而不是"一个课程功能"

用户把它定位成基准：**「从0学X」是一个基础，源码解读要能以它为基准扩展**。这句话落到代码上有两种做法，只有一种真的可扩展：

| 做法 | 加第三门语言 | 加一个源码解读专题 | 加一个"算法从0学" |
| --- | --- | --- | --- |
| 做一个"课程"功能，课在代码里定义 | 改前端卡片 + 改枚举 | 另开一套专题逻辑 | 再来一套 |
| **线是分类的标记，页面按清单渲染** | 建分类 + 写 md + 跑脚本 | 给现有分类打 `reading` 标记 | 建分类 + 写 md + 跑脚本 |

第二种的关键不是"少写代码"，而是**加东西的时候不需要碰已经跑通的任何一行**。这也是为什么线不建表：线需要的三样（名字、slug、顺序）分类里本来就有，多一张表只是多一处会不同步的真相。

顺带把源码解读收进来：它本来就是一条线（有 `learning-path`、有进度、有交互块），只是没人给它起过名字。本项只给它打一个标记，就能出现在同一套入口和进度里——**这是"可扩展"最先兑现的一次**。

## 调研结论（决定这份提案长什么样）
### 课程顺序

四条独立来源（Python 官方教程、CS50P、MOOC.fi、Exercism）把"学语言的顺序"收敛到同一条骨架：

> 变量/类型 → 运算 → 条件 → 循环 → 函数 → 集合与字符串 → 文件/异常 → 类与对象 → 继承/接口 → 小项目

两条线的差异在**门槛位置**：Python 到"文件+异常+模块"（第 8 课附近）就能写小工具；Java 必须跨过类、引用语义、集合与受检异常，才谈得上写项目。这直接决定了两门课第 12 课分别是什么（Python：模块/venv/测试；Java：小项目 + 并发入门）。

Python 官方教程明确写着它面向"会编程的人"，所以**不能把官方目录当零基础课表**；零基础要把"环境、运行、读输入"独立成第 1 课，这也是 CS50P 与 MOOC.fi 的做法。

### 学习机制（哪些值得做）

| 机制 | 证据 | 本项怎么做 |
| --- | --- | --- |
| 提取练习 | 读两遍 vs 读+测，一周后 40% vs 61% | 每课必有小测与练习，且小测放在讲解之后、小结之前 |
| 样例渐隐 | 完整样例 → 挖空 → 空白，效果优于直接做题 | `code-tour`（完整）→ `code-challenge`（填空/排序）→ 可选 `run`（空白编辑器） |
| Parsons 题 | 显著省时，学习增益相当 | `order` 题型作为"从读到写"的桥 |
| 掌握学习可降级 | Khan 的五级且会降 | 通过判定按最近得分算；重置会真的掉回未通过 |
| 到期复习 | Duolingo HLR | 1/3/7/21 天阶梯，读取时计算到期 |
| AI 护栏 | 无护栏：练习 +48% 但撤掉后考试 **-17%**；有护栏：+127%，撤掉后 0% | `TUTOR` 先要思路、四级提示、默认不给完整解 |

**不做**的游戏化：streak、心、宝石、排行榜。它们解决回访，不解决学会；而且与"公开仓库、零用户起步"的现实不匹配。

### 竞品机制（只借可复用的）

| 产品 | 值得借 | 明确不借 |
| --- | --- | --- |
| Exercism | iteration = 反馈绑定到具体一次提交 | 人工 mentor 队列（没有供给） |
| Codecademy | checkpoint 是可执行断言；"看答案"要留痕 | 内嵌完整 IDE |
| Brilliant | 先预测、再操作、后揭晓 | 拖拽式图形题引擎 |
| Duolingo | 到期复习队列、强度可视化 | 心/宝石/连胜惩罚 |
| Khan Academy | 掌握度能升能降、混合测验 | 视频课程 |
| Boot.dev | 只奖励完成练习，不奖励"看过" | XP/等级/角色 |

## 推荐方案

### 内容形态

```
knowledge_categories
  从零开始 (from-zero, line_kind=NULL)          ← 只是分组
    ├─ Python 从零开始 (python-from-zero, line_kind=course)   1 总览 + 12 课
    └─ Java 从零开始   (java-from-zero,   line_kind=course)   1 总览 + 12 课
  源码解读 (source-reading, line_kind=reading)                既有内容，打标记
```

每课正文是固定八节（REQ-002），中间嵌 `code-tour` / `code-challenge` / `quiz`，可选 `run`。总览条目嵌一个 `learning-path`。

课程源文件：

```
content/courses/python/00-总览.md
content/courses/python/01-环境与第一行代码.md
...
content/courses/java/12-小项目与并发入门.md
```

frontmatter 带 `order`（→ `sort_order`）、`minutes`、`prerequisite`、`category`、`status`。导入脚本走既有管理端 API（`/api/v1/knowledge/admin/...`），所以不需要新的写接口，也不需要管理员手抄。

**加一条新线的完整步骤**（不含这一条，可扩展性就是空话）：

```sh
# 1. 新建分类并标 line_kind=course（管理端点两下，或一次性 SQL/脚本）
# 2. 在 content/courses/go/ 下按同一套八节写 00-总览.md、01-....md
# 3. 跑导入
node scripts/import-course.mjs --dir content/courses/go
```

没有任何一步需要改 `.java`、`.tsx` 或迁移。

### 学习记录

一张表 `learning_progress`：`(user_id, entry_id)` 唯一，存分数、状态、通过时间、复习阶段与到期时间。通过判定在服务端（REQ-010）。

端点（学习者侧，全部 `authenticated`）：

| 端点 | 用途 |
| --- | --- |
| `GET /api/v1/learning/lines` | 线清单 + 每线的进度统计（`/learn` 与入口的唯一来源） |
| `GET /api/v1/learning/progress` | 全部记录（供条目页与统计） |
| `GET /api/v1/learning/entries/{id}` | 单课（条目页初始化） |
| `PUT /api/v1/learning/entries/{id}` | 上报分数（合并：取更高分、更远步骤） |
| `DELETE /api/v1/learning/entries/{id}` | 重置本课 |

线的"下一课""N/12""到期复习"都在 `GET /lines` 里一次算完，前端不再自己拼顺序。

### AI 导师

- `Harness.TUTOR`，提示词单独一个类（既有纪律：一个 harness 一个类，穷尽 switch）。
- 请求上下文里注入**服务端取到的学情**（`ConversationPrompt` 加一段），前端无从伪造。
- 新增只读工具 `learning_progress`，让通用助手也能答"我学到哪了"。
- 课程条目页的「问 AI」预填后使用 `TUTOR`；其它页面仍是 `ASSISTANT`。

### 入口

`/learn` 页 + 首页「从零开始」卡片（`key: 'learn'`，参与身份排序）。课程总览与单课仍走既有 `/knowledge/entries/{id}`，不复制一套阅读页。

## 备选方案与否决理由

| 备选 | 否决理由 |
| --- | --- |
| 新建独立的 `learn` 后端模块 + 课程/课时/题目三张表 | 与知识库重复：分类层级、正文、关系、检索、渲染、预览、自评全部要重做一遍；而课程需要的顺序用 `sort_order` + `learning-path` 就能表达 |
| 再建一张 `learning_lines` 表 | 线需要的三样分类里都有；多一张表就多一处要同步的真相，且要迁移存量分类 |
| 把课程序列传成按 `published_at` 排的约定，不加列 | 加一条线时无法精确控制顺序；管理端插入一条内容就会打乱课号。加一个可空列是更小、更明确的做法 |
| 前端写死"Python/Java 两张卡" | 加第三门就要改前端，且源码解读接不进来——这正是用户要否决的做法 |
| 课程内容直接写进 SQL 迁移 | 24 课是几万字 markdown，SQL 转义不可评审、不可 diff、改一个字要新迁移；且生产迁移里塞内容等于把内容变成 schema |
| 用第三方课程平台（如嵌入 Codecademy 内容） | 内容不受控、许可证不清、与知识库/助手/进度无法联动 |
| 进度继续只存 `localStorage` | 跨设备丢失、AI 无法知道学情、掌握度与复习无法成立 |
| 每门语言做一个独立 Agent | 与 WORK-010 已裁的"一个用户一个 agent、按场景换行为"冲突；每轮多一次调用即双倍成本 |
| 一期就上自适应出题/知识追踪模型（BKT/FSRS） | 没有历史数据训练或校准；固定题库 + 固定阶梯先跑通，数据攒够再换 |

## 这条原语还能长出什么

按"要不要改代码"分两栏，避免把可扩展性说成万能：

| 想加的东西 | 需要什么 | 改代码？ |
| --- | --- | --- |
| Go / SQL / 数学 / 算法从零学 | 建分类（`kind=course`）+ 写 md + 跑导入 | 否 |
| 把现有任意一个专题分类变成线 | 标 `line_kind` + 排 `sort_order` | 否 |
| 同一门课加课、换课、调顺序 | 改 md / 改 `order` + 重新导入 | 否 |
| 换一门课的上课方式（如"只读不练"的专题） | 正文不写练习块即可，进度判定会落在 `in_progress` | 否（但"通过"语义要另定） |
| 新的交互块（比如公式、图表） | 在 `@paideia/ui` 加一个 renderer | 是，一次 |
| 新的入口分组（不只"从零开始/专题"） | `line_kind` 加值 + 一处分组映射 | 是，一次 |
| 线级别的证书 / 结课证明 | 新表 + 端点 + 页面 | 是，独立小项 |
| 跨线组合课、分支选修 | 数据模型改（线不再是单链） | 是，而且要重新设计 |

**结论**：只要还是"一条有序的线、站是一篇条目"，加多少都是零代码；一旦要改**呈现形态或结构**，就必须改代码——这是诚实的边界，写进已知缺口第 5 条。

## 风险

| 风险 | 处置 |
| --- | --- |
| 内容量大（24 课），一次写完后质量参差 | 机器化门禁（结构 + 真跑代码）挡住错误；按语言分两批提交，先 Python 后 Java |
| `code-tour`/`quiz` 的 JSON 上限（20 步、10 题、2000 字解释）限制单课深度 | 单课按 20 分钟切，超出就拆课；上限不动 |
| 导师提示词可能仍给完整答案 | 单测断言"首次回复不含完整代码块"；提示词分级写死在 TUTOR 类里 |
| 线上沙箱未开导致运行题不可见 | 课程设计上不依赖运行题；`run` 只在能力可用时出现 |
| 进度表与注销级联遗漏 | 迁移加外键 + 补注销级联测试（既有清单里逐表核对） |
| 导入脚本误改既有条目 | 只按 `category + title` 匹配本项分类下的条目，绝不更新其它分类；先 dry-run |
| 加了 `line_kind` 后旧分类被误显示成线 | 默认 NULL；只有显式标记的分类才是线；`/learn` 用 `line_kind IS NOT NULL` 过滤 |
| 新加线的"零代码"只是口头承诺 | AC-017 用 `git status` 证明没有任何源码改动；跑不通就说明原语还没立住 |
