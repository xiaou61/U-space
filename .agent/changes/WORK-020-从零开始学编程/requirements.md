### 调研事实（2026-10-19 联网核实）

**课程结构**：官方与主流课程的顺序高度一致，两条线的骨架都是
变量/类型 → 运算 → 条件 → 循环 → 函数 → 集合/字符串 → 文件/异常 → 类与对象 → 继承/接口 → 小项目。
Python 官方教程明确说它面向"会编程的人"（`https://docs.python.org/zh-cn/3/tutorial/index.html`），零基础不能照搬；
CS50P 的周次是 Functions → Conditionals → Loops → Exceptions → Libraries → Unit Tests → File I/O → Regex → OOP → Et Cetera（`https://cs50.harvard.edu/python/weeks/`）；
MOOC.fi Python 把类与对象放在第 8 部分、继承放在第 10 部分（`https://programming-26.mooc.fi/`）；
Java 侧 dev.java 的 Language Basics → OOP → Generics 顺序（`https://dev.java/learn/`），MOOC.fi Java 的类在第 4 部分、继承/接口在第 9 部分、泛型在第 12 部分（`https://java-programming.mooc.fi/`）；
**Boot.dev 没有 Java 课程**（`https://www.boot.dev/courses`），Java 线不能照它的路径。

**学时**：Python 语法入门 24–30 小时、能写小项目 30–60 小时（Codecademy/Boot.dev/CS50P），Java 语法入门 17–20 小时、能写小项目 70–140 小时（Codecademy/MOOC.fi）；Java 的门槛明显更高，因为必须跨过类/引用语义/集合/受检异常。来源见上。

**学习机制证据**：
- 提取练习（测试效应）：读两遍 vs 读一遍+测一遍，一周后保持率约 40% vs 61%（Roediger & Karpicke 2006，`https://journals.sagepub.com/doi/10.1111/j.1467-9280.2006.01693.x`）。
- 间隔重复：按"到期时间"排复习，而不是用户自选（Duolingo HLR，`https://research.duolingo.com/papers/settles.acl16.pdf`）。
- 交错练习只对**易混同类**有效，对单词类反而有害（Brunmair & Richter 2019，g=0.42 / 单词类 g=-0.39）。
- 样例学习与渐隐：先给完整样例，再逐步挖空，最后空白编辑器（Sweller & Cooper 1985；Renkl et al.）。Parsons（行序题）比从零写显著省时且学习增益相当（Ericson et al. 2017，`https://dl.acm.org/doi/10.1145/3141880.3141895`）。
- 掌握学习：等级必须能**降级**，且要用混合测验防"单课刷熟"（Khan Academy mastery，`https://support.khanacademy.org/hc/en-us/articles/5548760867853`）。
- **AI 护栏决定成败**：Bastani et al., PNAS 2025 的 RCT 里，无护栏的通用 ChatGPT 让练习 +48%、撤掉 AI 后考试 **-17%**；加了"先让学生写卡点、先给最小提示、指出错误、绝不给完整答案"护栏后，练习 +127%、撤掉后 0%（`https://www.pnas.org/doi/10.1073/pnas.2422633122`）。
- 单段教学内容应短：edX 690 万次观看的中位观看时长不超过 6 分钟（Guo et al. 2014，`https://up.csail.mit.edu/other-pubs/las2014-pguo-engagement.pdf`）。

**竞品机制**：Exercism 的 iteration 编号（反馈绑定到具体版本）、Codecademy 的 checkpoint 断言（"看答案"要留痕）、Brilliant 的"先预测后揭晓"、Duolingo 的到期复习队列（只借机制，不借心/宝石/streak）、Khan 的五级掌握度。来源见 `proposal.md` 的调研表。

**新手高频误区**（前 15 条，课程必须覆盖；全部来自官方文档）：

| # | 语言 | 误解 → 正确说法 |
| --- | --- | --- |
| 1 | Python | 默认参数 `[]` 每次调用新建 → 只在定义时求值一次，可变默认值被所有调用共享 |
| 2 | Python | `is` 与 `==` 差不多 → `is` 比身份，`==` 比值；驻留是实现细节 |
| 3 | Python | `b = a` / `list(a)` 就完全独立 → 浅拷贝，内层仍共享，需要 `deepcopy` |
| 4 | Python | 缩进只是好看 → 缩进是语法 |
| 5 | Python | `17 / 3` 得 5、`0.1+0.2==0.3` → `/` 永远返回 float，整除用 `//`，浮点比较用 `math.isclose` |
| 6 | Python | 循环里的 lambda 记住当时的 `x` → 闭包调用时才读，全部看到最后一个值 |
| 7 | Python | 遍历列表时可以安全 `remove` → 应遍历副本或构建新集合 |
| 8 | Java | 两个内容相同的 String 用 `==` 是 true → `==` 比引用，内容用 `equals` |
| 9 | Java | String 的方法会改原串、`final` 等于不可变 → String 不可变；`final` 只锁引用 |
| 10 | Java | Java 是引用传递 → 一律值传递，对象传的是引用的副本 |
| 11 | Java | static 方法里能用实例变量与 `this` → 不能，static 属于类 |
| 12 | Java | `String[]` 当 `Object[]` 用是安全的 → 数组协变，写入时抛 `ArrayStoreException` |
| 13 | Java | 所有异常都必须 catch/throws → 只有 checked 异常受约束 |
| 14 | Java | `Integer` 装箱比较都一样 → `-128..127` 必须同对象，范围外不保证，比较用 `equals` |
| 15 | Java | 运行时能拿到 `List<String>` 的类型参数 → 泛型擦除，运行时不保留实参 |

来源：Python 官方 tutorial / FAQ / reference（`https://docs.python.org/3/tutorial/controlflow.html`、`https://docs.python.org/3/faq/programming.html`、`https://docs.python.org/3/library/copy.html`）；JLS 与 Oracle 教程（`https://docs.oracle.com/javase/specs/jls/se21/html/jls-5.html`、`https://docs.oracle.com/javase/tutorial/java/javaOO/arguments.html`、`https://docs.oracle.com/javase/tutorial/java/generics/erasure.html`）。

## 目标

- **先立原语，再立内容**：平台要有「学习线」这一层——一串有序的站，每站是一篇知识库条目，线上有一类的名字与用途（从零课程、源码解读……），进度、复习、AI 上下文都按线成立。**新增一条同构的学习线只动内容，不改代码。**
- 一个零基础的人从首页进「从零开始」，能在**一条明确的顺序**上把 Python 或 Java 学到"能独立写一个小项目"，每课 20 分钟左右。
- 每课都**必须动手**：至少一个非执行练习（填空/排序/找 bug）与一个小测；有能力时再给可运行题。
- 学过的痕迹**存在服务端**：换浏览器、换设备都看得到；AI 能据此知道你学到哪、哪课薄弱。
- 课程页面上的 AI 是**导师**，不是答案机：先问你思路，再逐级给提示，不直接贴完整答案。
- 内容可维护：课程是仓库里的 markdown 源文件，一条命令幂等导入；改内容走 PR，不再手抄进后台。

## 非目标

- **不做视频、动画引擎、证书、排行榜、streak/积分游戏化**。只借"到期复习队列"这一条机制。
- **不做任意人投稿课程**、评论、课程交易。课程由作者维护。
- **不做自动判分的主观题**（作文/设计题），也不做"任意代码自动评分"；执行题的判定仍是用例比对。
- **不新建独立课程模块或第二套内容存储**；不复刻知识库的编辑/发布。
- **一期不做自适应出题**（按掌握度自动生成新题），只做固定题库 + 到期复习。
- **一期不做更多语言/学科**（Go、SQL、数学等）——结构要允许，但内容不写。
- **不做"学习线"的后台可视化编辑器**：新增线走"写 markdown + 跑脚本"，管理端仍按分类/条目编辑。可视化编排是将来一条独立的小项，不在这里预埋。
- **不做跨线组合**（比如"Python + 算法"混编成新课），也不做线的分支/选修。线是单链。
- **不追溯把旧条目自动升级成线**：只有正文里有 `learning-path` 或分类被显式登记为线的，才算线；其余条目保持"零散内容"。
- **不改知识库条目的正文形态**：仍然是 markdown，不引入新表存"课时"。
- **不推翻现有 `localStorage` 进度**：它继续负责"上次读到第几步"的即时恢复；服务端负责"这一课学完了没有"。

## 用户与工作流程

**学习者（零基础）**
1. 首页「从零开始」→ `/learn`：两张课程卡（Python / Java），各显示"已通过 N / 12"与"继续第 K 课"。
2. 点 Python → 课程总览条目（`learning-path` 块）：12 站，显示每站未开始/进行中/已通过。
3. 点第 3 课 → 条目页：目标 → 为什么 → 讲解（配代码）→ 跟读（逐步高亮）→ 常见误区 → 动手 → 小测 → 小结与下一课。
4. 做错时点「问 AI」：预填"我在第 3 课的小测第 2 题选了 B，为什么错？"，用户按发送后进入**导师模式**：先问你怎么想的，再给一级提示。
5. 答完小测、做完练习 → 服务端记为通过；首页出现"继续第 4 课"。
6. 第二天再进 `/learn`，出现"今天该复习：第 2 课、第 5 课"（按 1/3/7/21 天阶梯）。

**作者（维护课程）**
1. 改 `content/courses/python/03-....md`，本地跑 `python scripts/verify_course.py` 验证代码与结构。
2. 跑 `node scripts/import-course.mjs`：缺的分类自动建、已有条目按标题更新、顺序与关系按 frontmatter 落库。
3. 管理端预览任意一课，确认渲染一致。

## 功能需求

### 学习线（可扩展的基准原语）

- **REQ-025 学习线 = 分类 + 一个线类别**：一条学习线就是知识库里的一个分类（顶层或子树根），站是它下面的条目。分类上加一个**可空**的 `line_kind`（`course` 从零课程 / `reading` 源码解读 / NULL = 普通分类）；线的名字、slug、顺序沿用分类既有的 `name / slug / sort_order`。**不新建"线"表**：线是分类的一个标记。
- **REQ-026 线的两种形态共存**：一条线可以自带一个**总览条目**（正文里有 `learning-path`，站显式写 `entryId`），也可以**只有条目列表**（站顺序由 `sort_order` 推出、总览自动生成）。源码解读已有一条 `learning-path`，必须被登记成 `reading` 线而不是被复制一遍。
- **REQ-027 站的顺序唯一且可声明**：条目上加一个**可空**的 `sort_order`（同线内唯一，正数）。服务端按 `sort_order` 排序；**没有 `sort_order` 的线退回 `(published_at, id)`**（既有条目一条不改）。排序规则只有一处实现。
- **REQ-028 新增一条线不改代码**：新增一条同构的线只需：① 建分类并标 `line_kind` ② 写 markdown ③ 跑导入脚本。**不改后端、不改前端、不改迁移**——入口与卡片由线清单自动生成（REQ-019/029）。验收以"真的新加一条线并跑通"为准（AC-017）。
- **REQ-029 线级的进度与入口**：`/learn` 不再是"两门写死的课"，而是**遍历所有 `line_kind` 非空的线**；`GET /api/v1/learning/lines` 返回线清单（含进度统计、站数、总时长）。`line_kind` 决定它出现在哪个入口分组（`course` → 从零开始；`reading` → 源码解读），前端不写死分类 id。

### 课程内容

- **REQ-001 课程落位**：知识库顶级分类「从零开始」（`from-zero`）下两个子分类「Python 从零开始」（`python-from-zero`）与「Java 从零开始」（`java-from-zero`）。每门语言 = 1 个课程总览条目 + 12 课，共 26 个条目。**不新增内容表**。
- **REQ-002 单课固定结构**：每课正文必须依次包含 `## 这一课你要会`、`## 为什么`、`## 讲解`、`## 动手`、`## 检查一下`、`## 常见误区`、`## 小结` 七节；`## 讲解` 至少有一个 `<!-- run -->` 标记的可运行示例（紧跟 ```text 期望输出）；`## 动手` 含至少一个 `code-challenge`；`## 检查一下` 含一个 3 题 `quiz`；`## 常见误区` 至少两条。
  **为什么不用 `code-tour`**：它的 schema 要求 `repo@commit` + 仓库内路径 + 许可证，那是为"固定 commit 的开源代码"设计的。课程代码是我们自己写的、随内容一起改，硬填一个 permalink 只会得到指向不存在文件的假链接。`code-tour` 保留给将来真正引用开源实现的课（那时才有真 commit）。
- **REQ-003 课程总览**：每门语言的第一个条目是总览，含一个 `learning-path` 块（12 站，`entryId` 指向本课，带 `minutes`）；正文说明"为什么按这个顺序、卡住了怎么办、学完能做什么"。
- **REQ-004 语言大纲**：按下列 12 课交付，顺序不得随意调整（依据见调研事实）：
  - Python：① 环境与第一行代码 ② 运算与条件 ③ 循环 ④ 函数 ⑤ 列表与元组 ⑥ 字典与集合 ⑦ 字符串与格式化 ⑧ 文件读写 ⑨ 异常 ⑩ 类与对象 ⑪ 继承与多态 ⑫ 小项目（模块/venv/测试入门）。
  - Java：① 编译运行与变量 ② 运算符与条件/switch ③ 循环与方法 ④ 数组与字符串 ⑤ 类、对象、构造器、封装 ⑥ static、值传递与引用 ⑦ 继承、多态、抽象类、接口 ⑧ 集合与泛型 ⑨ 异常 ⑩ 文件 I/O ⑪ JUnit 与 Maven ⑫ 小项目与并发入门。
- **REQ-005 误区覆盖**：15 条高频误区必须各自落到至少一课（映射见 `tasks.md` 的内容矩阵）；每课写 2–3 条，格式固定为"你以为 / 其实 / 怎么验证"。
- **REQ-006 代码可运行**：每课至少有一个**完整可运行示例**，用 `<!-- run -->` 标记一个 fenced 代码块，紧跟一个 ```text 期望输出块；`scripts/verify_course.py` 逐课真实执行并比对输出。Python 示例不得依赖第三方库；Java 示例必须是单个可编译的 `Main` 类。
- **REQ-007 版本与术语**：正文使用中文，术语首次出现给英文；示例代码以 Python 3.12 / Java 21 为基线，不使用预览特性；引用的官方文档给出版本（如 `docs.python.org/3/`）。
- **REQ-008 内容导入**：课程源文件放 `content/courses/**`（frontmatter：`title`、`category`、`order`、`minutes`、`prerequisite`、`status`）。`scripts/import-course.mjs` 通过管理端 API 幂等导入：分类按 slug 建、条目按"分类内标题"匹配后更新、按 `order` 依次发布（保证上一篇/下一篇顺序）、关系按 `prerequisite` 建。重复执行不产生重复条目。

### 学习记录与掌握度

- **REQ-009 服务端学习记录**：每个用户每课一行，记录：最远走读步骤、每个练习/小测的得分与总数、状态（`in_progress` / `passed`）、首次通过时间、复习阶段与下次复习时间、更新时间。**只接受本人数据**；条目必须存在且已发布。
- **REQ-010 通过判定**：由服务端从分数计算，不信任客户端传状态：至少有一个小测与一个练习记录、且每一项 `score / total ≥ 0.8` 才为 `passed`；否则为 `in_progress`。首次通过写 `passed_at` 并排第一次复习。
- **REQ-011 复习队列**：按通过后的 1 / 3 / 7 / 21 天四档安排；再次通过时阶梯前进一档（到顶不动）。**不引入后台任务**：到期列表在读取时按 `review_due_at <= now` 计算。
- **REQ-012 课程进度**：`/learn` 与课程总览显示"已通过 N / 12"和"下一课"；某一课 `passed` 后下一课状态由"有记录"驱动（不锁课，允许跳读）。
- **REQ-013 继续学习**：首页显示服务端最近一课与"下一步"；服务端不可用时退回本地 `recentReading`，不让整块消失。
- **REQ-014 重置**：条目页提供"重置本课进度"（只清本人该课记录），二次确认；重置后总览与首页同步变化。

### AI 联动

- **REQ-015 导师行为**：新增 `Harness.TUTOR`。规则：**先让学习者说出自己的思路或提交一次答案**；提示分四级（概念提醒 → 定位到行/选项 → 下一步伪代码 → 才给完整答案）；指出具体错误并解释为什么；默认不给完整解；坚持要看时要求先写下思路。课程条目页打开的对话默认使用该行为。
- **REQ-016 学情进上下文**：导师的请求必须携带本课学习记录（状态、各小测/练习得分、最近一次更新时间），不只带正文。数据由服务端按 `user_id` 取，前端不能伪造。
- **REQ-017 学情可查询**：新增工具 `learning_progress`（工具集 `learning`），返回当前用户各门课的通过数、最近学习、薄弱课（得分最低的已学课）。通用助手与该工具同一套归属规则：**只读调用者自己的数据**。
- **REQ-018 预填不发送**：每课的「问 AI」只打开面板并预填（包含课号、小节、具体题号/选项），用户按发送前不产生任何上游请求与积分扣减。

### 入口与界面

- **REQ-019 课程入口**：新增 `/learn` 页；首页新增「从零开始」卡片（参与身份排序，`key: 'learn'`），指向 `/learn`。**`/learn` 的卡片由线清单生成**（REQ-029），不是两张写死的卡；线的数量与名字变了，页面跟着变。
- **REQ-020 条目页接入**：课程条目页在渲染正文前取一次本课记录，作为同步进度端口的初值；阅片/小测的提交写回服务端（合并策略：取更高的分与更远的步骤）。非课程条目行为不变。
- **REQ-021 窄屏与可访问性**：`/learn` 与课程总览在 360px 下不横向溢出；课程卡有稳定 `data-testid`；状态不只靠颜色表达。

### 健壮性与兼容

- **REQ-022 沙箱缺席可降级**：`run` 题型在沙箱不可用时只显示代码与用例；课程**不得**依赖运行题才能通过（每课必须有非执行练习）。
- **REQ-023 坏内容不炸页**：块 JSON 非法时只降级该块（既有行为），课程结构检查在导入前拦下。
- **REQ-024 既有行为不变**：非课程条目、笔记、助手回答的渲染与计费不变；现有 e2e 全绿。

## 质量要求

- **内容正确**：示例代码真实执行通过；小测答案唯一且可从本课内容推出；行序题只有一种合法顺序；引用的事实能追到官方文档。
- **可维护**：课程源文件按语言分目录、按 `order` 编号；导入脚本幂等；结构检查一条命令跑完 24 课。
- **性能**：条目页只增加一次进度请求；`/learn` 一次请求取完两门课统计（不在前端 N+1）；进度写回合并 + 去抖，不做逐帧写。
- **安全**：进度端点只认令牌里的用户；不接收 `user_id`；条目 id 走存在性校验；工具与导师上下文都按 `user_id` 过滤。
- **隐私**：学习记录属于个人数据，注销时随账号级联删除（纳入现有注销级联清单）。
- **可访问性**：键盘可完成课程导航与全部练习；状态有文字；`prefers-reduced-motion` 下无强制动效。

## 约束与依赖

- 课程是**知识库内容**：沿用既有分类/条目/正文/关系/自评/搜索/附件；不新建课程表，**也不新建"学习线"表**——线是分类的投影（见 REQ-025）。
- 首期只新增**一张表**（`learning_progress`）与两组可空列（`knowledge_categories.line_kind`、`knowledge_entries.sort_order`），不新建"线"表；不引入消息队列事件。
- 沙箱是否在线上开启由部署决定；课程不依赖它。
- 课程内容公开给已登录学习者（沿用现有鉴权），不做免登录课程页。
- AI 调用按 WORK-009 的积分规则计费；导师提示词按"一个 harness 一个类"的既有纪律。
- 内容里不得出现真实凭据、服务器地址或个人信息。
- **可扩展性是可验收约束，不是口号**：任何"线"的新增都必须做到零代码（REQ-028/AC-017）。若某个改动必须先改代码，就说明它不在"线"这一层，应在需求里退回重画。

## 验收标准

- **AC-001 课程齐全**：两门课各 12 课 + 1 个总览；分类、顺序、关系正确；`/learn` 能进入两门课。
- **AC-002 结构达标**：结构检查脚本对 26 个条目全绿（7 节按序、可运行示例、练习、3 题小测、≥2 条误区）。
- **AC-003 代码可跑**：`verify_course.py` 执行 24 课的全部可运行示例，输出与期望一致，退出码 0。
- **AC-004 总览可用**：课程总览显示 12 站与状态；点某站进入对应课；有记录时显示进行中/已通过。
- **AC-005 通过判定**：答对全部小测与练习后，服务端状态变 `passed`；只答对一半仍是 `in_progress`；刷新后状态不丢。
- **AC-006 跨设备**：同一账号换一个浏览器（不同 `localStorage`）打开课程，通过状态与"下一课"一致。
- **AC-007 复习队列**：把某课的 `passed_at` 改到 2 天前，`/learn` 出现"今天该复习"；未到期的不出现；再次通过后阶梯前进。
- **AC-008 导师不直接给答案**：问"第 5 课练习怎么做"，回复先要求思路或给一级提示，**不含完整可粘贴答案**；连续追问四级后才可能给完整解。
- **AC-009 学情可答**：问"我学到哪了/我哪几课最弱"，助手返回与实际记录一致的数字与课名（不是泛泛而谈）。
- **AC-010 预填不发送**：点「问 AI」后面板打开且输入框有内容；网络面板无上游请求、积分不变。
- **AC-011 导入幂等**：导入脚本连续跑两次，第二次新建 0、更新 0（或仅时间戳），条目总数不变。
- **AC-012 沙箱缺席**：关闭沙箱时运行按钮不渲染，课程仍可完成并通过。
- **AC-013 隔离与隐私**：A 用户看不到 B 的进度；注销账号后该用户的 `learning_progress` 行被删除。
- **AC-014 既有功能**：学习者端与管理端既有 e2e 全绿；非课程条目渲染不变。
- **AC-015 适配**：360px 下 `/learn`、课程总览、条目页无横向溢出；键盘可完成小测与练习。
- **AC-016 线清单由内容驱动**：`GET /learning/lines` 返回的线来自分类，不是前端常量；把某条线在分类表里的 `sort_order` 改掉，`/learn` 的顺序跟着变（界面重载即可，不改代码）。
- **AC-017 新增一条线零代码**：在测试环境新建一个分类 + 3 个条目（带 `order`），跑导入脚本；`/learn` 自动出现第三条线、能进入、能做题、能记录通过。全过程**没有改任何 .java / .tsx / 迁移**（用 `git status` 证明）。
- **AC-018 源码解读被认成一条线**：既有 `source-reading` 分类在 `/learn` 或入口里以 `reading` 类别的线出现，站数等于其 `learning-path` 的站数；不重复建分类、不复制条目。
- **AC-019 无 `order` 的线不变**：给一条没有 `order` 的分类（既有零散条目）请求线视图，站序仍等于 `(published_at, id)`，与改动前一致。

## 实现选择

以下取舍由 Agent 根据已确认边界与仓库模式给出，签字时可推翻；推翻要改这一节。

| # | 选择 | 理由 |
| --- | --- | --- |
| 1 | **课程 = 知识库分类 + 26 个条目**，不建课程表 | 分类、条目、正文、关系、检索、渲染、预览全部已有；建第二套内容系统只会分叉 |
| 11 | **学习线是分类的一个可空标记，不建 `learning_lines` 表** | 线的三要素（名字、slug、有序站集合）分类里全有；多一张表就多一处要同步的真相 |
| 12 | **站的顺序用条目可空 `sort_order` 声明，缺失退回 `(published_at,id)`** | 既有条目一条不改；声明过的线可精确控制顺序，没声明的线保持现状 |
| 13 | **`/learn` 与入口按线清单渲染** | 写死两门课的话，加第三门就要改前端；线清单是唯一入口真相 |
| 14 | **`line_kind` 与 `sort_order` 都可空、默认 NULL** | 迁移不碰任何存量行；两个新能力对旧数据是"零语义" |
| 2 | **复用 6 种围栏块**，不新增渲染器 | 走读/地图/练习/小测/运行都已实现并有单测；课程只需要内容与编排 |
| 3 | **进度上服务端（一张表）**，本地只保留"上次读到第几步" | 跨设备与 AI 学情都必须服务端；`localStorage` 无法支撑掌握度与复习 |
| 4 | **通过判定在服务端从分数算**（≥80%），不接受客户端的 `passed` | 客户端只报分数；阈值一处实现，避免前端各算一套 |
| 5 | **复习用固定阶梯 1/3/7/21 天、读取时计算** | 不引入调度器、后台任务或新依赖；一期足够，将来可换 FSRS |
| 6 | **新增 `Harness.TUTOR`**，不给每个身份配一个 Agent | 与 WORK-010 已定的"一个用户一个 agent、按场景换行为"一致 |
| 7 | **学情由服务端注入提示词 + 提供工具** | 前端传的学情可伪造；服务端按 `user_id` 取才是事实 |
| 8 | **内容用 `content/**` markdown + 导入脚本** | 24 课件用 SQL 或后台手抄都不可维护；markdown 可 diff、可评审 |
| 9 | **`<!-- run -->` + 期望输出块做机器化内容校验** | "代码真的能跑"必须可验证，不能只靠作者自觉 |
| 10 | **不启用沙箱也能学完** | 线上 Docker 状态未确认；运行题应是加分项而非必经路 |

## 假设

- 线上管理端可用，且能用一个管理员账号完成导入（凭据只从环境变量读，不进仓库）。
- 课程面向**零基础**读者：不假设会命令行、不假设懂 Git。
- 每课 20 分钟左右是"读 + 做"的合计，不含额外查资料。
- 学习者已登录（整端登录门已存在）。
