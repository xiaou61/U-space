## 术语与边界

本项出现几个容易各自理解的词，先定死口径：

| 术语 | 定义 | 不是 |
| --- | --- | --- |
| **关卡实训** | 挂在某一条学习轨道某一关里的 SQL 题，做完计入该关通过判定 | 不是独立课程，不产生新的轨道 |
| **自由练习** | 一个可随时打开、自己写 SQL 的页面，**不计入任何进度** | 不是题库，没有"对错"以外的评价 |
| **数据集（dataset）** | 一组建表 + 插数的 SQL，题目在它之上执行 | 不是"测试用例"（那是输入输出的一个点），一个数据集可被多题共用 |
| **判题口径** | 「什么算答对」的规则，按题声明 | 不是"标准答案文本" |
| **反模式（antiPattern）** | 一段**看起来对但实际错**的 SQL，用于检验题目质量 | 不是错误提示文案 |
| **参考解（reference）** | 生成期望结果的**查询本身**，不是手写的结果表 | 不是唯一正确写法 |

最后两条是本项的关键：**期望值由参考解在数据集上跑出来**，不手写；**反模式必须被判错**，否则这题没设计好。

U-05 是排序依据：凡是「让题目更可信、更不容易被凑巧答对」的工作优先于「让界面更好看」或「支持更多 SQL 特性」。

## 目标

1. MySQL 课从「只能读和答选择题」变成「能真的写 SQL 并立刻看到结果、知道对不对」。
2. 题目本身可检验：每道题都能证明（a）参考解与另一种正确写法都能通过，（b）典型错误写法会被判错。
3. 学习者有一条不依赖关卡的自由练习路径，且不必先走完课程。
4. 判题不误杀正确写法——SQL 一题多解是常态，不是例外。

## 非目标

- **不做 MySQL 之外的 SQL 方言**（PostgreSQL、SQLite 等）：一门课一套执行环境，混着做会和课程内容对不上。
- **不做数据库图形化客户端**（表结构树、可视化建表、ER 图编辑）：那是另一个产品的量级。
- **不做多用户共享数据库或协作**：每次运行都是独占的干净实例。
- **不做 SQL 性能评分/排名**：只判结果对不对，不判"写得快不快"。
- **不做自由练习的历史保存与分享**：一期不存用户写的 SQL（与 `code_runs` 不存源码同一条纪律）。
- **不改 WORK-015 的 Java/Python 执行路径**：原有 `run` 题型行为一字不变。

## 用户与工作流程

### 关卡实训

学习者在 `/learn/mysql-from-zero` 的第 03 关（排序分页）读到「分页排序末尾要补主键」，下方是一道 `write` 题。编辑器里有一段初始 SQL，右边是数据集说明（有哪些表、多少行）。点「运行」→ 看到结果表格与逐数据集通过情况 → 对了就计入本关挑战分。

### 自由练习

学习者从导航进 `/practice/sql`，左侧选一个示例库（一期只有「订单系统」四张表），中间写 SQL，右侧看结果与执行耗时。不计分、不计入进度、不出现在任何报告里。顶部显示今日剩余次数。

### 沙箱不可用时

`paideia.sandbox.enabled=false` 或镜像缺失：**所有需要执行题型的按钮不渲染**，只显示代码与题面；选择题（预测结果、排错诊断）照常可做，关卡仍可通过。这与现有 `run` 题型的降级口径一致。

## 功能需求

### 执行能力

- **REQ-001**：沙箱支持 `sql` 作为第三种语言，语言白名单与镜像映射按配置扩展；未知语言仍拒绝。
- **REQ-002**：一次 SQL 运行 = 一个**一次性 MySQL 实例**（容器内），启动时载入该题指定的数据集，运行结束后实例销毁，用户之间与用户前后两次之间不共享任何状态。
- **REQ-002a**：**允许多语句**（U-07）：`BEGIN`/`COMMIT`/`ROLLBACK` 与 DDL 都在允许范围。一次运行返回**多个结果集**，按语句顺序排列，展示时标出每个结果集来自第几条语句。
- **REQ-003**：返回**结构化结果**（每个结果集的列名与行值），同时保留一份供展示的文本形式；不能用「拼成 stdout 让前端解析」当唯一契约。
- **REQ-004**：执行必须同时具备三道上限：库层 `max_execution_time`、容器墙钟硬杀、返回行数与结果字节上限。任何一道触发都要返回明确原因，不能静默截断成"成功"。

### 判题口径（本项的核心）

- **REQ-005 按结果判、不按文本判**：比对的是**结果集**，不是 SQL 字符串。因此 `JOIN`、子查询、`EXISTS`、窗口函数等等价写法一视同仁。
- **REQ-006 归一化必须可配、不能一刀切**：
  - 列名：默认忽略顺序（按列名对齐），题目可要求严格；
  - **行序：默认忽略，但排序类题目必须能声明为严格**——否则「排序、分页」这一整课无法出题；
  - `NULL`：统一为显式的空标记，不能与空字符串混同；
  - 定点数：按数值比较，`92.5` 与 `92.50` 视为相等；
  - 日期时间：按同一格式归一后比较；
  - 浮点：**禁止出现在判题列**（`DOUBLE` 的误差会让比较不稳定），题目数据一律用 `DECIMAL`。
- **REQ-007 多数据集**：每道可执行题至少 **2 个数据集**（1 个公开示例 + 至少 1 个隐藏）。隐藏数据集的存在是为了让「把答案硬编码进去」的写法失败。
- **REQ-008 期望值由参考解生成**：题面存的是**参考查询**，期望结果由它在各数据集上真实执行得出；不手写结果表（手写必然与数据集脱节）。
- **REQ-009 每题必须附「反模式」与「另一种正确解」**：
  - 反模式：典型错误写法（对应本课某一节误区），**必须至少在一个数据集上被判错**；
  - 另一种正确解：与参考解写法不同但结果相同，**必须在所有数据集上被判对**。
  - 这两条由内容门禁自动断言，任一不成立则该题不合格。
- **REQ-010 判定位置不变**：仍在客户端。服务端只执行与返回结构化结果，不认识"正确答案"。

### 题型

- **REQ-011** 五种题型，其中三种不需要执行：

| 题型 | 考什么 | 是否需要沙箱 | 判题依据 |
| --- | --- | --- | --- |
| `sql-write` | 从需求写出查询 | 是 | 结果集比对（REQ-005/006） |
| `sql-fix` | 识别并修正一处典型错误 | 是 | 修好的语句在全部数据集上结果正确，且**原语句至少在一处不正确** |
| `sql-predict` | 读懂语句会返回什么 | 否 | 与给定结果/选项比对 |
| `sql-diagnose` | 看执行计划或报错，判断原因 | 否 | 选项比对 |
| `sql-blank` | 语法与关键字记忆 | 否 | 填空比对（复用现有 `fill`） |

- **REQ-012**：每课**必须至少有一道不需要执行的题**。理由与现有课程纪律相同：沙箱可能关闭，课程不能因此整关卡死。
- **REQ-013**：每道可执行题必须声明 `goal`（这题在考什么认知，一句话）与 `trap`（对应本课哪一节误区）。门禁检查两者非空。

### 关卡与自由练习

- **REQ-014**：MySQL 课 12 关各至少一道可执行题，且题目的 `trap` 必须对应该课「常见误区」里已写的一条——不允许出现课里没讲却拿来考的坑。
- **REQ-015**：自由练习页路由 `/practice/sql`，**只提供一个示例库**（订单系统四表，U-08）：数据集选择、SQL 编辑、运行与结果表格；**不写入任何进度**，不进入任何统计与报告。本次会话内用户可以建表（每次都是干净实例，无害），但页面以写查询为默认流程、不引导建表。
- **REQ-016**：SQL 用**独立的日配额 20 次**（U-09），与 Java/Python 的 50 次分开计算；自由练习与关卡实训共用这一份 SQL 配额。页面显示剩余次数；额度不足时明确告知本次未执行，不计入成功。

### 配额与降级

- **REQ-017**：复用 `code_runs` 审计表，`language='sql'`；不新增表。SQL 的 `code_hash`/`code_length` 口径与现有语言一致。
- **REQ-018**：能力探测端点返回的语言列表必须真实反映"镜像在不在"，不能只报配置开关——否则前端会渲染一个必然失败的按钮。

## 质量要求

- **题目可信度优先于题量**：宁可 12 关各 1–2 道经过反模式检验的题，也不要 5 道没验过的。这条直接来自 U-05。
- **判题逻辑只有一个真相来源**：前端判题与内容门禁脚本必须对同一份数据得出相同结论；两份实现在仓库里并存时，必须有一个共同的语料测试把它们钉在一起（否则必然漂移）。
- **单次运行对宿主的占用可预测**：mysqld 初始化后的常驻内存与冷启动耗时要实测后写进配置，不能拍数字。
- **失败必须说得清**：语法错误、超时、超限、超配额、沙箱不可用，五种情况的返回与展示各不相同。

## 验收标准

- **AC-001**：`sql` 语言在沙箱能力探测里出现，且只在镜像真实可用时出现；不存在的语言仍被拒绝。
- **AC-002**：一次 SQL 运行在干净实例里完成，同一用户连续两次运行看不到上一次建的表或改的数据。
- **AC-003**：返回结果含列名与行值；多语句时返回多个结果集；超行数上限时返回明确的超限原因而不是截断后的成功。
- **AC-004**：语法错误、库层超时、容器墙钟超时、结果超限、配额耗尽五种情况各有互不相同的返回状态，且前端展示可区分。
- **AC-005**：对同一道题，参考解与题面声明的「另一种正确解」在全部数据集上被判通过（证明不误杀等价写法）。
- **AC-006**：每题声明的「反模式」至少在一个数据集上被判错（证明题目能区分真错与假对）。
- **AC-007**：把答案硬编码（例如直接 `SELECT 487.50`）的写法，在隐藏数据集上被判错。
- **AC-008**：行序声明为严格的题目，把结果顺序打乱会判错；声明为忽略的题目，顺序打乱不影响判定。
- **AC-009**：MySQL 12 关每关至少一道可执行题，且每课至少一道不需执行的题；两者的存在性由门禁脚本检查。
- **AC-010**：每道可执行题的 `goal` 与 `trap` 非空，且 `trap` 能在该课「常见误区」里找到对应条目（文本可核）。
- **AC-011**：自由练习页可写可跑可看结果，且**不产生任何 `learning_progress` 写入**（用数据库断言，不靠肉眼）。
- **AC-012**：沙箱关闭时，可执行题的运行按钮不渲染，课程仍可读到结尾，选择题仍可作答并计入通过判定。
- **AC-013**：`code_runs` 里出现 `language='sql'` 的审计行，且**不含源码**（只有哈希与长度）。
- **AC-014**：前端判题与门禁脚本对同一批语料给出相同结论（有语料化测试，不是口头保证）。
- **AC-015**：SQL 的日配额独立于其它语言：跑满 20 次 SQL 后第 21 次被拒，但同一天仍可运行 Java/Python（证明两档互不影响）。
- **AC-016**：多语句运行返回多个结果集且顺序与语句一致；`ROLLBACK` 之后的查询看不到回滚前的改动（证明事务语义在沙箱里是真的）。

## 实现选择

以下由 Agent 依既有边界与仓库模式决定，签字时可整体否决或逐条改：

1. **镜像**：自建一个已完成初始化的 MySQL 镜像（避免每次运行都跑一遍 `mysqld --initialize`，那是 3–6 秒的主要来源），按 digest 钉住；基础镜像用 `mysql:8.0` 官方镜像而不是 Alpine 变体，理由是官方镜像的初始化路径最可控。
2. **容器内启动方式**：`--skip-networking` + 只走 unix socket，数据集与用户 SQL 均经 stdin 传入，沿用 WORK-015 的「分帧」思路，不放宿主文件。
3. **显式收紧的危险开关**：`secure_file_priv` 指向一个不可写目录、`local_infile=0`、禁用 `LOAD DATA`；这些在启动参数里写死，不靠默认值。
4. **结果契约**：`/api/v1/sandbox/run` 的响应新增可选 `tables` 字段（列名 + 行），`stdout` 仍给一份人类可读的表格文本；不新增端点。
5. **判题的共享真相**：把「结果集比对」写成一份**语料 + 两份实现的对照测试**（前端 TS 与门禁 Python），语料是 `tests/sql-judge/corpus.json`；任一侧改动都要跑一次该对照测试。
6. **数据集存放**：与课程同源，放 `content/courses/mysql/datasets/*.sql`，题目在 frontmatter 同级目录的 `cases/*.json` 里引用数据集名。
7. **自由练习的数据集**：复用「订单系统」四表这一份，不另建示例库。
8. **难度与配额**：SQL 单次上限比 Java/Python 宽（内存 512m、超时 20 秒），日配额单独 20 次（U-09）。实测依据：预初始化启动 4.4–4.7 秒、常驻 348MB，均写在 design.md。
9. **多语句的结果展示**：一次运行返回的结果集数组按语句顺序编号；`BEGIN`/`COMMIT` 这类不产生结果集的语句不占位，但其影响体现在后续语句的结果上。

## 假设

- 服务器剩余可用内存（约 7G）足以支撑并发 2 个 SQL 容器，且不与 Firecrawl 的 6G 上限冲突；这一点在实施时用实测复核，若冲突则降低 `maxConcurrency` 或错峰。
- 学习者主要用桌面浏览器写 SQL；移动端只保证"能看题面与结果"，不保证编辑体验。
- 现有 `code-challenge` 围栏块能容纳新题型而不破坏老内容（老的四类 `kind` 保持不变即可）。
