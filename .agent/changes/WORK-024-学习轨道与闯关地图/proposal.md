# 提案 · 学习轨道与闯关地图

> 补账件，反向记录已实现方案。方案于 2026-10-20 定下并落地。

## 摘要

把「从零开始」从知识库里拆出来，给它自己的导航层：**两张表（轨道 + 关卡）+ 两个读端点 + 一个 upsert 写端点 + 两个前端页面**。关卡正文仍复用 `knowledge_entries`，所以渲染、quiz、进度、复习排期全部白捡。

## 为什么值得做

WORK-020 的做法是给知识库分类打一个 `lineKind` 标记，于是"学习线"只是浏览入口里的一个筛选条件。结果是：

- 课程和文章混在同一个列表里，看不出"这是一条要一路走完的路"；
- 没有关卡感，也没有关卡之间的依赖——分不清哪一篇是下一篇的前置；
- 用户原话是「要闯关/图谱那种、线一个一个关联」，分类标记给不出这个。

## 三种做法

| 做法 | 优点 | 缺点 |
| --- | --- | --- |
| 给分类标记加更多属性（顺序、前置） | 零新表 | 顺序与前置是**边**不是**节点属性**；塞进分类表等于让人手填邻接关系，且分类树已经有父子层级，两套层级会打架 |
| **轨道 + 关卡两张表（选定）** | 顺序、章节、前置依赖各有字段；正文复用 entry | 多两张表、多一个导航层要维护 |
| 完全独立的课程内容体系（不碰 knowledge_entries） | 结构与内容彻底解耦 | 渲染器、quiz 块、进度、复习排期四件事各写一遍；内容迁移成本高 |

选第二条的决定因素是**正文不用搬家**：`knowledge_entries` 已经有 markdown 渲染、`quiz` / `code-challenge` 围栏块、`learning_progress` 的通过判定与复习排期。新造一套正文体系等于把四件现成的东西重写一遍，而本项真正缺的只是"导航"这一层。

## 关键取舍（三处，都有代价）

### 1. 锁只看直接前置，不做递归

地图上有连线表达顺序，递归判定会让"跳着学"变成不可能——用户会想先看后面那关是不是自己需要的。

**代价**：可以绕过前置直接点进第三关。这是明知的放松。

### 2. 难度是关卡属性，不是轨道属性

同一条"Java 从零开始"里既有入门语法也有并发深入，把难度挂在轨道上会丢掉这个区分。

**代价**：24 个课程文件要么各自写 `level`，要么按章节推默认值。选了后者，所以新加课程如果落在没有约定的章节里，默认落到 `beginner`。

### 3. 前端连线用纯 CSS，不引图库

关卡地图是章节分组的横向卡片流，"前置"用相邻节点的折线表示。

**代价**：非相邻关卡之间的依赖画不出来（当前内容里没有这种）。
