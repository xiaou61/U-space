# AI 精简与悬浮助手提案

需求已由 xiaou61（CTO）于 2026-10-12 09:43:33 签署。本提案按需求给出的边界给出**一个推荐方案**，并在「备选方案」里写下没有选的路与理由；真正的选型分歧集中在「待决定事项」，那些**由用户裁决**。

## 摘要

新增一个业务模块 `paideia-ai`，把模型调用整个收在薄端口之后（AgentScope 只出现在实现里，业务代码不碰它的类型）。本项交付**一件事**：对当前知识条目生成一份**带小标题的结构化精简卡片**，由用户在悬浮壳里点按钮触发，用**用户自己的 baseUrl 与 API Key**、经后端代理调用；结果可复用，**可见性由生成者在生成时选择**；每次真实调用的 token 用量返还给用户。

学习者端加一个**贯穿全站的悬浮助手壳**（含凭据设置与结果卡片），不新增页面级导航结构之外的入口。

数据上新增两张表：**用户模型凭据**（加密落库）与**精简结果**（每条目每人一行 + 可见性 + 内容版本 + 模型 + 提示词版本）。

## 推荐方案

### 1. 模块与端口

- 新增 Maven 模块 `paideia-ai`（在 `backend/pom.xml` 与 `paideia-app/pom.xml` 注册，共三处），包根 `io.github.xiaou61.ai` 放对外契约，内部实现在子包；与其他模块一样由 Spring Modulith 在构建期校验边界。
- 对外只暴露一个薄端口，例如 `EntrySummarizer`，输入是"条目正文 + 用户凭据句柄"，输出是"结构化卡片 + 用量"。**AgentScope 的类型不出现在端口签名里**（D-09 的既有要求），因此将来换实现或升级框架都不动业务代码。
- 命名沿用既有习惯：`paideia-ai`（模块）／`@paideia/assistant`（前端包）。

### 2. 调用路径：AgentScope 的最小用法

- 用 AgentScope 的 **chat model + formatter** 直接发一次请求，**不启用 agent 运行时**（不需要工具、记忆、多轮）。这正是"只有一套 AI 栈"的好处：依赖只加一次。
- 结构化输出走 AgentScope 对 OpenAI 系（含 DeepSeek）的**合成工具回退路径**，并**显式**设置 `nativeStructuredOutputWithTools(false)`：本项没有工具调用，这条设置不会有副作用，但它把"将来加工具时撞上 DeepSeek 那条限制"这件事变成一次显式声明而不是一个偶然。
- 卡片字段（小标题 + 内容）在端口层做**字段级校验**：缺字段、类型不对、正文为空 → 按失败处理，**不缓存**、不照原样渲染。上游返回空内容也走这条失败路径——这一条是刻意的：DeepSeek 在 `max_tokens` 被思考 token 吃满时会**静默返回空**，如果不判空就会把空结果写进缓存，然后所有后来者都拿到空白卡片。

### 3. 凭据：加密落库

- 一张表按用户一行：`user_id`、`base_url`、`model`、`api_key_cipher`、`api_key_last4`（仅供界面回显"已配置 ····ABCD"，**不回显明文**）、`created_at`/`updated_at`。
- 加密用 **AES-GCM**，每条随机 12 字节 IV 与 IV 一起存；主密钥（32 字节）只从环境变量读入，**缺失时启动失败并说清原因**（不降级成明文）。
- Key **不进日志、不进错误响应、不出现在任何接口返回**：日志与异常里出现该字段要按缺陷处理，接口只回 last4。
- 解密失败（换过主密钥等）→ 明确提示"凭据无法解密，请重新填写"，不是 500。

### 4. 缓存与可见性

- 结果表按**每条目每人一行**存，键含 `entry_id + content_hash + model + prompt_version`（`content_hash` 取正文的 SHA-256；正文一改哈希就变，旧结果自然不再命中——比用 `updated_at` 更直接，也不依赖"任何 UPDATE 都会刷时间戳"这个隐式前提）。
- 读取顺序：先找**当前用户可见**的结果（自己的，或他人标为公开的）→ 命中就返回，**不调模型**，用量记 0 并标明"本次未产生调用"；没有才调用。
- 可见性由**生成者**在生成时选择，默认公开（需求「实现选择」已写明理由）；消费者只能把显示范围收窄为"只看我的"。
- 结果行记录**来源**（谁的、公开还是私有），界面上标出"你自己生成的"／"来自其他学习者"。

### 5. SSRF 防护（信任边界，不做成可选项）

- 用户填的 baseUrl 会变成**服务端出站请求**，因此保存与调用前都要校验：必须 `https`、禁止用户名密码片段、禁止非标准端口之外的意外形态、**解析出的 IP 不得落在回环／内网／链路本地／云元数据网段**。
- 校验发生在**真正发起连接之前**，并且对重定向做限制（禁止跟随到新的主机）。
- 已知残余风险：**DNS rebinding**（先解析成公网 IP 通过校验，再解析到内网）。见「风险与缓解措施」。

### 6. 限流与可观测

- 按用户做**应用内固定窗口限流**（单实例部署，见需求「假设」）：每分钟与每日两个额度，超限返回明确错误码。
- 可抓取指标以日志与 Actuator 可读形式暴露：调用次数、缓存命中次数、失败分类（上游超时／鉴权失败／结构化校验失败／SSRF 拒绝）。
- 提示词作为代码常量并带**版本号**，进缓存键：改提示词即产生新结果，不复用旧的。

### 7. 前端

- 新增 `packages/assistant`：接口客户端、结构化卡片组件、悬浮壳组件（含凭据设置与"只看我的"开关）。**必须同步登记 `globals.css` 的 `@source`**（有自动化检查兜底）。
- 悬浮壳挂在学习者端的外壳层（`apps/app`），因此**全站常驻**；在非条目页只显示"打开一条内容后可用"的状态，不做跨页上下文推断。
- 桌面壳与 Web 共用 `apps/app` 产物，因此两端行为一致，无需分别实现。

## 范围

**包含**：`paideia-ai` 模块与薄端口、两张表与迁移、凭据的加密存取、SSRF 校验、按用户限流、AgentScope 最小调用与结构化输出、缓存与可见性、用量返回、悬浮壳与结构化卡片、前端设置、测试与回归。

**不包含**（需求「非目标」已定）：多轮对话／记忆／工具／自主行为、个人笔记与分享、平台兜底 Key、成本记账、向量检索、流式输出、按学习者状态定制摘要。

## 备选方案

**加密与主密钥：引入 Jasypt 或 Spring Vault。** 前者能省掉自己写加解密，但它解决的问题（配置文件里的明文）与本项不同——我们的密文在**数据库行**里、每条带独立 IV，库只会增加一个不透明的依赖。未选。Vault 要额外部署一个组件，与"单实例自托管、服务器上没有 Docker"的现状冲突。未选。

**用 datakey 两级加密（每条凭据一把数据密钥，由主密钥包裹）。** 强的一面是轮换主密钥时只需重包数据密钥、不必重解全部密文。未选理由：本项凭据数量是"用户数个位数"，轮换代价可忽略，两级结构带来的复杂度不划算。**触发重评**：凭据数量到千级或需要定期轮换主密钥时。

**结构化输出不走框架能力，自己拼提示词让模型吐 JSON。** 强的一面是少一层框架魔法、行为完全可见。未选理由：JSON 解析失败要靠自己兜，而 AgentScope 的合成工具回退路径本身就是"强制工具调用"，在这件事上比裸提示词更稳；且 D-09 已定用这套栈。

**绕过 AgentScope，直接用 JDK HttpClient 调 OpenAI 兼容接口。** 强的一面是依赖最少、体积最小，本项确实只需要一次 POST。未选理由：D-09 已裁决只用 AgentScope；且 WORK-006 的多轮与记忆必须由它承担，先自建一套再拆掉是纯粹的重写。**代价**：接受一个 GA 仅三个月、仓库一年内 891 个未关 issue 的框架（见「风险」）。

**缓存键用 `entries.updated_at` 而不是正文哈希。** 强的一面是少算一次哈希、与既有列表查询一致。未选理由：它依赖"任何正文改动都会刷新时间戳"这个隐式前提，而哈希把"内容没变就不该重新生成"写成显式事实；哈希的成本可以忽略。

**结果存在进程内存里而不是落库。** 强的一面是零迁移、零表设计。未选理由：可见性模型要求"别人的公开结果我能看到"，跨用户跨会话共享必须持久化；重启即失效也会让"省钱"这件事站不住。

**悬浮壳改成独立页面。** 强的一面是上下文明确、实现更简单。未选理由：用户要的就是"到了这个界面就能下拉提醒"的常驻形态；另开页面等于让学习者为了用一次精简离开正在读的内容。

## 仓库影响

- **后端**：新增 `paideia-ai` 模块（三处注册）；新增迁移一个文件，**编号取当时的可用值**（当前是 `V4`，编号不写死在文档里——既有教训是并发会话会占用编号）；`SecurityConfiguration` 加 `/api/v1/ai/**` 的登录后可用规则（**不需要角色限制**：这是登录用户自己的额度，不是管理操作，但仍要显式写出这条规则以免落进"默认拒绝"的例外里）。
- **前端**：新增 `packages/assistant`（含 `.tsx` → 登记 `@source`）；`apps/app` 外壳挂载悬浮壳 + 一条设置入口；不新增应用面。
- **工件**：`always.md` 的决策清单要**修改**「Key 不落库」为加密落库，并新增两条常驻规则（凭据加密与主密钥管理、代理端点的 SSRF 边界）；`technology-options.md` 若因本项新增选型（加密方式、限流手段）则补一条 D 项。
- **部署**：服务器上新增一个环境变量（主密钥）；`.env` 之类的本地占位示例可提交，值不进仓库。

## 交付拆分

1. **骨架与表**：`paideia-ai` 模块、薄端口、迁移（凭据表 + 结果表）、模块边界校验通过。
2. **凭据**：AES-GCM 加解密与主密钥装配（缺失即启动失败）、保存/读取/删除接口、last4 回显、日志与错误响应不泄密的检查、SSRF 校验。
3. **生成与复用**：AgentScope 最小调用、结构化输出与字段校验、空结果不入缓存、缓存命中与可见性判定、用量返回、按用户限流。
4. **前端**：`packages/assistant`（客户端 + 卡片 + 悬浮壳 + 设置）、`apps/app` 挂载、来源与用量标注、`@source` 登记。
5. **验证与回归**：`mvn -B verify`、前端 typecheck/单测、三端 e2e、既有四项边界检查、桌面产物仍不含管理端。

## 风险与缓解措施

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| **DNS rebinding 绕过 SSRF 校验** | 服务端被诱导访问内网 | 校验解析结果之外，**按已解析的 IP 直连并带上 Host/SNI**（或至少禁止重定向、每次连接前重新校验并拒绝解析结果变化的目标）。**若不能做到，把这条例为已知残余风险并写进测试报告**——不假装它被解决了 |
| 主密钥丢失 / 泄露 | 全体用户凭据不可用或全泄露 | 主密钥只在环境变量；缺失即启动失败；解密失败降级为"请重新填写"；文档写清轮换步骤与"轮换即全体重填"的代价 |
| 空结果被写进缓存 | 后来者都拿到空白卡片 | 端口的字段校验把空内容判为失败；**失败结果一律不落缓存** |
| `max_tokens` 被思考 token 吃满 | 静默空响应（不报错） | 显式下限；并把"上游返回空"当作可识别的失败分类计入指标 |
| 结构化输出字段漂移 | 卡片渲染出半成品 | 字段级校验 + 明确错误码；校验失败不缓存，可重试一次 |
| AgentScope 年轻（GA 三个月、891 未关 issue） | 升级或缺陷成本不可控 | 只用最小面（chat + formatter，不用运行时）；薄端口隔离，替换不动业务代码 |
| 用户凭据在传输/日志中泄露 | 安全事故 | 接口不回显明文、日志脱敏、错误响应不含上游原始报文；测试里安排"刻意制造上游失败"的用例 |
| 限流被绕过（多标签页/并发） | 出口被滥用 | 按用户而非按连接计数；固定窗口 + 并发上限 |
| 缓存共享被误读为"平台免费 AI" | 预期管理失败 | 界面上标明来源与"本次未产生调用"；设置里有"只看我的" |

## 待决定事项

以下几条**由用户裁决**；其余实现细节按本提案执行。

1. **加密方式**：应用层 AES-GCM（推荐，标准库、无新依赖）／引入 Jasypt／自建两级 datakey。
2. **主密钥来源与轮换约定**：环境变量（推荐，与既有 `DEEPSEEK_API_KEY` 的注入方式一致）／其它；以及"轮换即全体重填"是否可接受。
3. **限流手段**：应用内固定窗口自建（推荐，单实例够用）／引入 Bucket4j 或 Resilience4j／不设额外限流只靠上游 429。
4. **SSRF 处置强度**：只校验解析结果 + 禁重定向（较小改动，承认 DNS rebinding 残余风险）／**按解析后 IP 直连**（更彻底，实现更绕）。这条直接决定 AC-007 写到多严。
5. **凭据设置界面的位置**：悬浮壳内的设置弹窗（推荐，就近且不新增路由）／学习者端独立的设置页。
6. **token 用量是否落库**：只随本次响应返回（推荐，最小面）／也存进结果行，便于将来做用量统计与"当初这条花了多少"的回显。
