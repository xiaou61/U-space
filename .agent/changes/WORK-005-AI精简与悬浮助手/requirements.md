# AI 精简与悬浮助手需求

2026-10-12 起草，同日报 xiaou61（CTO）批准并签署。本项的范围最早记在 `WORK-004` 需求文末的「拆分后的后续工作项」，用户 2026-10-12 就其中若干开放项逐条裁决后正式建项。

## 已确认事实

（本节的标题**不能加括号后缀**：生命周期校验器按 `## 已确认事实` 精确匹配，加了后缀会被判成"缺少决策分层章节"。事实确认于 2026-10-12。）

- 仓库**没有任何 AI 代码或依赖**：`backend/` 7 个模块（`paideia-platform`／`-web`／`-persistence`／`-security`／`-account`／`-knowledge`／`-app`）里既无 `agentscope` 也无 `openai`／`deepseek` 字样；前端各包同样没有。生产迁移只有三个文件（账号两张表 → 知识库五张表）。
- **可用的内容与身份都已就绪**：WORK-004 已交付知识条目、正文渲染与学习者端条目页；当前用户身份只能取 `CurrentUser.subjectId()`／`role()`，接口层不接受客户端传 userId。
- **D-09 已裁决**：AI 接入只用 **AgentScope Java**（不叠加 Spring AI），模型供应商定为 **DeepSeek `deepseek-flash`**；Boot 4.1.1 的兼容性尖刺已通过。四个必须自建的能力是限流、提示词版本、可抓取指标、成本记账——**成本记账本项可省**（BYOK，见用户决定）。
- DeepSeek 侧实测约束（`.agent/references/agentscope-and-deepseek-2026-10.md`）：
  1. **思考 token 会吃掉 `max_tokens`**，给不够时**静默返回空内容**（不是报错）。
  2. **没有 DeepSeek 专用 starter**，走 OpenAI 兼容 formatter。
  3. **工具调用与结构化输出不能在同一次调用里并用**（DeepSeek 会优先满足 `response_format` 而跳过工具调用）。
- 结构化输出在 AgentScope 上对 OpenAI 系是**回退路径**（框架注入合成工具、强制工具调用带回数据），不是 provider 原生 schema。
- 思考模式下**流式会分两类事件**：`ThinkingBlockDeltaEvent` 与 `TextBlockDeltaEvent`——前端渲染必须分开处理，否则思考内容与正式回答混在一起。
- **密钥边界**：开发用的 DeepSeek Key 存于本机 Windows 凭据管理器（`Codex/quick-server/paideia-deepseek`），应用侧计划用环境变量注入。本仓库**公开**，任何 Key、连接串、服务器地址都不得进入被跟踪的文件。
- **D-15 的"缓存"是通用缓存基础设施（多级缓存、失效与穿透策略）暂缓**，与本项的"模型产物复用"不是一回事：本项不引入通用缓存层，只解决"同一条目的精简结果存下来复用"。
- 前端目前没有任何"助手"形态的界面；学习者端整体要求登录。

## 用户决定

以下由用户在 2026-10-12 的讨论中逐条裁决。

1. **精简结果的可见性由生成者在生成时选择**：「公开」或「只给自己」。**谁付费谁决定要不要分享**；消费者只能把自己的**显示范围**收窄为"只看我的"，**不能**取到别人标为私有的结果。
2. **API Key 存服务端、加密落库**（每人一行，主密钥由环境变量注入）。
   **这一条修改了既有裁决**：WORK-004 需求文末记的是"Key **不落库**、不进日志、不出响应"。落库这一半按本项裁决改为**加密落库**；另两条（**不进日志、不出响应**）不变，且本项要按"落库"这一新事实补齐主密钥管理与泄露应对（见「质量要求」）。
3. **助手壳第一期只做精简**：没有对话输入框。多轮、记忆、工具与自主行为属 WORK-006，本项不提前做。
4. **纯 BYOK，不提供平台兜底 Key**：模型成本由用户自己承担，平台不出钱。**没配 Key 的用户仍然能读别人公开的结果，但不能触发生成**。
5. **AgentScope 在本项就引入**（不等 WORK-006）：只有一套 AI 栈。业务代码**不得直接依赖其类型**，必须收在薄端口之后——这条沿用 D-09 的既有要求。
6. 沿用 WORK-004 已记的范围：对当前内容生成精简／总结；用户在客户端自填 **baseUrl 与 API Key**，请求经**后端代理**（浏览器直连自定义 baseUrl 会被 CORS 挡，且 Web 与桌面须同一套代码）；助手壳**贯穿学习者端**且能取当前内容上下文；精简结果**可以缓存**；**不含** Agent 运行时。
7. **精简产物是「带小标题的结构化卡片」**，不是一段自由文本。
8. **触发方式只给按钮**：打开条目**不自动生成**——自动生成会无条件消耗用户自己的额度。
9. **每次调用的 token 用量返还给用户**（BYOK 下用户自己付费，看得见才透明）。

## 实现选择

以下由 Agent 在已确认边界内收口，影响数据或用户可见行为的逐条列出（有异议可直接推翻）。

- **默认可见性取「公开」**：纯 BYOK 下"公开池"是没配 Key 的人唯一能看到的内容来源；默认私有会让缓存几乎不起作用（只省自己的重复点击）。
- **缓存按「每条目每人一行」存**，键含**条目 + 内容版本 + 模型 + 提示词版本**：正文一改旧结果即失效；读取时先找有权限看到的行，命中就不再调模型（与全共享同样的省钱效果）。
- **结果行要记来源并在界面上标出**（"你自己生成的"／"来自其他学习者"）：不标的话，同一条目两次点出不同内容会被误读成"模型不稳定"。
- **`max_tokens` 给足**，避开"思考 token 吃满导致静默空响应"；默认模型与端点内置为 DeepSeek，可在设置里改。
- **第一期不做流式**：摘要是短产物，一次性返回足够；流式留给 WORK-006 的对话（届时还要分开渲染思考与正文两类事件）。
- 新建 `paideia-ai` 模块 + 薄端口，业务代码不碰 AgentScope 类型。
- **"结构化卡片"用结构化输出取回**：AgentScope 对 OpenAI 系（含 DeepSeek）走的是"合成工具 + 强制工具调用"的回退路径，不是 provider 原生 schema。本项**没有工具调用**，所以不会撞上"工具与结构化输出不可并用"那条 DeepSeek 限制；但设计里要显式固定 `nativeStructuredOutputWithTools(false)` 并写明原因，免得将来加工具时踩。
- **超长正文按段落截断**到上限（具体上限在设计里定），并在卡片上标注"已按前 N 字生成"——静默截断会让人以为模型漏读了。
- **命中缓存时用量显示为 0**，并标明"本次未产生调用"；否则用户会以为又花了一次钱。

## 背景

WORK-004 让平台第一次有了可读的内容，但**内容是静态的**：学习者看到的正文由管理员写在管理端，平台对"这个人读到哪、卡在哪"一无所知。本项引入平台的第一处模型调用，用最小的一件事——**把当前条目精简成一段好读的摘要**——验证三件基础设施：外部模型怎么接、用户自带的凭据怎么安全地存与用、模型产物怎么复用。

它同时是"千人千面"的第一块拼图：这条链路上跑通之后，WORK-006 才有多轮与记忆可谈，WORK-007 才有"AI 生成的总结可以落进个人笔记"可谈。

## 目标

- 学习者在条目页能一键得到**当前条目的精简结果**，表现为贯穿学习者端的常驻悬浮助手壳（点开可看、可重新生成），而不是又一个独立页面。
- 用**用户自己的 Key 与模型**完成调用，请求经后端代理转发；用户的 Key 在服务端加密保存，**不出现在日志、错误响应与任何接口返回**里。
- 精简结果**可复用**：同一条目同一内容版本不必反复调用模型；复用的可见范围由生成者在生成时选择。
- 与 WORK-006 的边界清晰：本项只有一次调用、没有会话、没有记忆、没有工具。

## 非目标

- **不做多轮对话、不做记忆、不做工具调用、不做任何"自主"行为**——全部属 WORK-006。
- 不做个人笔记与分享（WORK-007），精简结果本项不落进笔记体系。
- 不提供平台兜底 Key，不承担用户的模型成本，**不做成本记账**。
- 不做向量检索与语义记忆。
- 不做流式输出。
- 不做"按学习者状态定制摘要"（掌握度、笔记都还没到能用的程度）。
- 不做模型产物的审核、举报与下架流程（WORK-007 的分享要举报，本项结果只在平台内可见）。

## 用户与工作流程

**学习者（首次）**

1. 打开任一条目 → 悬浮壳可见（未配 Key 时壳内提示"配置你自己的模型 Key 后可用"）。
2. 在壳内或设置里填入 **baseUrl + API Key**（可选模型名与参数）。
3. 点「精简」→ 后端用该 Key 调用模型 → 结果在壳里显示，并标明来源。
4. 生成时选择这条结果**是否公开**。

**学习者（再次）**

- 打开已精简过的条目 → 壳里直接给出结果（命中缓存，不调模型）；标注是自己生成的还是他人公开的。
- 设置里可把显示范围收窄为"只看我的"。

**管理员**

- 本项**不新增管理界面**：模型凭据是每个用户自己的，管理员与学习者在这一层没有区别。

## 功能需求

- **REQ-001**：学习者能对当前条目触发一次精简，并在悬浮壳中读到结果。
- **REQ-002**：请求经后端代理转发到用户配置的 baseUrl，**浏览器不直连**模型供应商。
- **REQ-003**：用户可自行填写 baseUrl、API Key（与可选模型名）；凭据在服务端**加密保存**，接口与日志中**不出现明文**。
- **REQ-004**：精简结果可复用——同一条目、同一内容版本、同一模型与提示词版本，命中已有结果时**不再调用模型**。
- **REQ-005**：结果有可见性（公开／私有），**由生成者在生成时选择**；读取遵循"私有仅本人可见、公开人人可读"。
- **REQ-006**：未配置凭据的用户**可读**已公开结果，**不可触发生成**（给出明确提示而不是报错）。
- **REQ-007**：条目正文变更后，旧结果不再命中（按内容版本失效）。
- **REQ-008**：上游失败（超时、限流、空响应、鉴权失败）有**明确且不泄露上游原始报文**的提示。

## 质量要求

- **凭据安全**：加密落库的主密钥只从环境变量读入，不进仓库；主密钥缺失时**启动失败并说清原因**，而不是静默降级为明文；解密失败（例如主密钥换过）时提示用户**重新填写**，不是 500。
- **不泄露**：Key 与上游原始响应不得出现在日志、错误响应、前端回显与任何接口返回里。
- **SSRF 防护**：baseUrl 由用户给出而请求由**服务端**发出——必须限制为 https、且拒绝解析到回环／内网／链路本地／云元数据地址的目标。（属信任边界，不作为可选项。）
- **限流**：按用户限制调用频率与并发（BYOK 不代表可以无限打我们的出口）；超限返回明确错误码。
- **提示词版本**：提示词作为代码常量并带版本号，进缓存键；改提示词即产生新结果而不是复用旧的。
- **可抓取指标**：调用次数、命中缓存次数、失败分类——以日志/Actuator 可读的形式暴露（本项不做完整可观测栈）。
- **既有纪律**：SQL 只在 mapper、时间存 UTC、标识符小写 snake_case；模块边界由 Spring Modulith 构建期校验；前端颜色只有 `globals.css` 一个来源；新增含 `.tsx` 的包要登记 `@source`。

## 约束与依赖

- **依赖 WORK-004**（已完成）：条目与正文、学习者端条目页、当前用户身份。
- **框架**：AgentScope Java（D-09），业务代码经薄端口使用，不直接依赖其类型。
- **供应商**：DeepSeek `deepseek-flash` 为默认；用户可改 baseUrl 与模型。
- **部署**：单实例自托管，一个 jar 同时供前端静态与 API；服务器上无 Docker。
- **公开仓库**：任何凭据、连接串、服务器地址不得进入被跟踪的文件；本地敏感配置只放被忽略的文件。

## 验收标准

- **AC-001**：学习者在条目页触发精简能拿到结果并在悬浮壳中显示（端到端检查）。
- **AC-002**：Key 落库为密文；接口响应、日志与错误信息中均不出现明文（自动化检查，含刻意制造上游失败）。
- **AC-003**：同一条目重复请求命中已有结果时**不产生第二次模型调用**（自动化检查，以调用计数或桩替身证明）。
- **AC-004**：标为"只给自己"的结果，其他用户读不到；标为"公开"后其他用户能读到且同样不触发新调用（自动化检查）。
- **AC-005**：未配置凭据的用户能读到公开结果、触发时得到明确提示且不产生调用（自动化检查）。
- **AC-006**：条目正文修改后旧结果不再命中（自动化检查）。
- **AC-007**：baseUrl 指向回环／内网／非 https 时被拒绝，且请求确实未发出（自动化检查）。
- **AC-008**：`pnpm -r typecheck`、`pnpm -r test` 与既有边界检查（`workspace-boundaries`、`tokens`、`source-coverage`、`contrast`）继续通过；桌面产物仍不含管理端。
- **AC-009**：精简结果是带小标题的**结构化字段**（有字段级校验），不是一段自由文本；缺字段或字段类型不对时按失败处理而不是照原样渲染。
- **AC-010**：每次真实生成后界面能看到本次 token 用量；**命中缓存时用量显示为 0 且标明"未产生调用"**（自动化检查）。

## 假设

- 首版使用规模小（单实例、用户数十级），限流与并发用应用内手段即可，不引入分布式限流。
- 用户填的 baseUrl 是**兼容 OpenAI 协议**的 HTTPS 端点。
- 条目正文长度在常规范围内（单条几百到几千字）；超长正文的处理方式见「待确认问题」。
- 精简是**无状态的一次调用**：不携带会话历史、不引用用户私有数据（自评、笔记都不参与）。
