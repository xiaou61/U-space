### 调研事实（2026-10-17 联网核实）

| 产品 | 做到什么程度 | 对本项的取舍 |
| --- | --- | --- |
| **walk-the-code**（MIT） | 配置驱动的代码走读：行级注释按内容哈希镜像、Mermaid 图**按行高亮节点**、guided tour、练习、知识小测、localStorage 进度、可编辑并可选执行 | 与本项最接近。学**行级注释 + 引导走读 + 图与代码联动 + 进度**；不学它的本地服务器执行 |
| **VisuAlgo** | 24 个可视化模块；内置**题目生成器与自动判分**；可换用自己的输入；e-Lecture 模式 | 学**即时判分与练习**；不学算法动画库（我们不讲算法课） |
| **Python Tutor / TraceCode / CodeFlow / CodersNote** | 逐行执行，同步展示**变量、堆、调用栈、输出、流程图** | 学**状态快照的呈现形式**；不学执行（真实 repo 跑不起来，要沙箱） |
| **CodeBoarding / CodeSee / Sourcetrail** | 代码库自动生成**可交互架构地图**，可下钻组件、看依赖、叠 tour（CodeSee 已下线） | 学**地图即导航**；不学自动索引（维护与幻觉成本） |
| **CodeCrafters** | "从零实现 Redis / Git / SQLite"，带测试框架逐步验收 | 学**动手练习**；不学完整脚手架（要跑代码） |
| **DeepWiki** | 任意 repo 自动 wiki + 概念到代码实体的对照图 + Q&A | 学**概念→代码的对照**；不学自动生成 |
| **Hello 算法 / 小林coding** | 500 幅动画图解 + 14 语言可运行代码 / 图解八股 | 学**图解密度与"一图讲一个机制"**；不学动画引擎 |
| **Distill / Explorable Explanations** | 交互式文章：**先预测、再操作、后揭晓** | 学**预测式阅读**（成本极低、学习效果最好的一招） |

**共同结论**：同类产品没有一个是"只看逐步高亮"的。真正拉开差距的是五件事——**地图与代码联动、状态可视化、预测后再揭晓、动手练习、进度**。首版只有"走读 + 小测"，所以显得单薄。

## 目标

- 一个专题不是一篇文章，而是一条**可走、可玩、可验**的学习路径：地图 → 走读 → 状态 → 练习 → 小测 → 追问。
- 读者每一刻都知道"我在整张图的哪里、这一步在做什么、我有没有真懂"。
- 读完留下**可继续的进度**：下次能接着上次那一步，首页有「继续学习」。
- 内容可维护、可追溯：每段代码锚定固定 commit，许可证清楚；坏内容不炸页面。
- 不新增后端模块、数据表或外部服务依赖。

## 非目标

- **不做任意 repo 的自动索引/自动生成 wiki**（DeepWiki 的地盘；内容仍需人工核）。
- **不做代码执行沙箱**（Sandpack / Pyodide / WebContainers / 本地 runner）：真实 repo 不可运行，安全与运维成本不成立。
- **不做 Python Tutor 式自动逐行执行**：v1 用作者编写的状态快照，不做运行时解释器。
- **不建表、不加后端端点、不改管理端 CRUD**：正文仍是 `knowledge_entries.body`。
- **不做跨设备进度**（v1 只存本地；服务端进度是把来的独立小项，见「待确认问题」）。
- **不做用户投稿、评论、收藏、排行榜、证书**。
- **不做动画引擎**（排序/树/图的可播放动画）；v1 用**分步状态快照**表达变化。
- **不做 Mermaid**：地图用作者给的节点与边自己画；需要流程图先用图片。Mermaid 待量体积后再议。
- **不做跨设备/跨设备同步**、不做学习数据上报。

## 用户与工作流程

**读者**：首页「源码解读」→ 专题总览（一条学习路径，显示每站状态）→ 进入一站 → 先看**架构地图**（点击节点跳到对应走读步骤）→ 按步走读（有些步骤先让你**猜一下**，答完才揭晓）→ 关键步骤看**状态快照**（变量/调用栈/堆/输出怎么变）→ 做一道**动手练习**（选对空白处的代码/把行序排对/找出 bug 行）→ 做 3 道小测 → 有疑问点「问 AI」→ 离开时进度自动保存 → 下次从首页「继续学习」回到上次那一步。

**作者**：管理端新建条目 → 选「源码解读」分类 → 正文里写说明与围栏块 → 预览里逐块检查（含错误提示）→ 发布。代码片段从固定 commit 复制，页脚自动带出处与许可证。

## 功能需求

### 内容与结构

- **REQ-001 专题落位**：`源码解读` 作为知识库的顶级分类；一篇 = 一个机制；**不新增表、不新增后端接口**。
- **REQ-002 学习路径块**（`learning-path`）：把若干条目组织成有序的"站"，显示序号、标题、预计时长与本站状态（未开始／进行中／已完成）；点击进入条目。**路径是作者写的，不是从关系图推断的**。
- **REQ-003 架构地图块**（`code-map`）：作者给出节点（id、名称、分组、所属文件/行、可选的走读步骤索引）与边；渲染为**可交互的图**：悬停高亮相邻边、点击节点跳到对应走读步骤或条目。布局由作者给的 `layer` 与 `order` 决定（不引入布局库），窄屏可横向滚动。
- **REQ-004 地图与走读双向联动**：同一条目内，地图与走读通过共同的块 id 关联。点击地图节点 → 走读跳到对应步骤并滚动到可见位置；走读切换步骤 → 地图高亮当前步骤对应的节点。**两者在同一个页面内共享状态**，不是两次独立渲染。

### 走读

- **REQ-005 走读块**（`code-tour`）：支持步骤序列；每步有标题、起始行号、代码、语言、`focus` 行、解释。渲染为"代码 + 解释"的逐步视图：真实行号、`focus` 行高亮、上一步/下一步、步骤进度、键盘左右键、窄屏上下堆叠。
- **REQ-006 预测式步骤**：步骤可选带一个 `predict`（问题 + 2–4 个选项 + 正确项 + 揭晓文案）。**答对或答错都先不给解释**，只在作答后揭晓；同时提供「直接看解释」的逃生口（键盘与读屏可用）。
- **REQ-007 状态快照**：步骤可选带 `state`，包含 `vars`（名字/值）、`stack`（调用栈帧）、`heap`（对象 id、标签、字段）、`output`（程序输出）。渲染为**可读的状态面板**，与当前步骤同步；缺失时不显示该面板（不占位）。
- **REQ-008 出处与许可**：每个走读块显示 `repo@commit`、文件路径、行范围、许可证，并提供指向该 commit 的 GitHub permalink；`repo`/`commit`/`file` 校验后才拼 URL。

### 练习与检验

- **REQ-009 动手练习块**（`code-challenge`）：支持三种题型——**填空**（每个空从选项里选）、**排序**（把打乱的行排回正确顺序）、**找 bug**（点出错误的那一行）。判定在客户端完成并即时给出结果与解析；**不执行代码**。
- **REQ-010 小测块**（`quiz`）：1–10 题，每题题干、2–6 选项、正确项、解析；点选即时判对错并显示解析；显示本块得分。
- **REQ-011 进度记录（本地）**：按条目记录每个走读块的**最远步骤**、每个练习/小测的**得分与是否完成**、以及更新时间；页头显示本站完成度；离开再回来能恢复；提供「重置本站进度」。**只存 `localStorage`，不上传**。
- **REQ-012 继续学习**：首页显示最近学习的 1–3 站与完成度，点击直接回到该条目（并在能恢复时回到上次步骤）。

### 与 AI 联动

- **REQ-013 AI 预填**：走读每一步提供「问 AI」、状态面板提供「解释这个状态」、篇末提供「让 AI 考考我」与「换个讲法」。点击后**只打开助手并预填一句话，不自动发送**；提示词包含条目标题、步骤序号、文件与行号。管理端预览不显示这些按钮。
- **REQ-014 AI 能答当前内容**：提问后助手能引用本条目正文；不要求新增后端能力（现有请求已携带 `entryBody`）。

### 渲染与健壮性

- **REQ-015 语法高亮**：代码块使用 Shiki（`@streamdown/code`）；只允许白名单语言（至少 `javascript/typescript/tsx/jsx/java/python/go/rust/c/cpp/sql/bash/json/yaml`）；未知语言退回纯文本；**懒加载**，不进入应用主包。
- **REQ-016 降级与错误边界**：任一块的 JSON 非法、字段缺失、越界、超限时，**只降级该块**为可读提示 + 原始文本；页面其余部分正常；控制台无未捕获异常。
- **REQ-017 预览一致**：管理端预览与学习者页面用同一套渲染与同一份 schema；同一段正文在两处结构一致。
- **REQ-018 入口与发现**：首页 `QUICK_LINKS` 增加「源码解读」，并可从知识库分类页进入；入口有稳定的 `data-testid`。
- **REQ-019 零运行时外部依赖**：阅读路径**不请求 GitHub API**、不拉取远程源码；代码片段随正文内置；permalink 只是普通链接。
- **REQ-020 不改变既有行为**：不带新块的条目/笔记/助手回答渲染结果不变；现有 e2e 全绿。

## 质量要求

- **内容正确**：行号与固定 commit 的源文件一致；`focus` 指向真实行；permalink 的行范围与展示一致；预测题与练习题有唯一正确答案。
- **可维护**：所有块的 schema 与上限集中在一个模块；作者写错时错误信息指出第一个不满足的字段；有一份作者指南。
- **性能**：切换步骤只更新组件本地状态，不重新解析整篇 markdown；Shiki 只在真要渲染代码时加载；主包体积不增加。
- **安全**：代码按文本渲染，不执行 HTML；解释走同一套净化 markdown 且**不递归启用自定义块**；外链协议与主机名白名单。
- **可访问性**：键盘可完成走读、预测、练习、小测；焦点可见；对错不只靠颜色；读屏可读；`prefers-reduced-motion` 下无强制动画。
- **适配**：360px 宽度下不横向溢出（代码区自身可滚动）；地图可横向滚动并可键盘聚焦节点。

## 约束与依赖

- **许可证**：v1 优先 MIT / Apache-2.0 / BSD。GPL/AGPL 仓库（Linux、Redis 等）只允许极小片段并标注出处，或只链接不内嵌；落地前逐篇确认。
- **依赖**：v1 只新增 `@streamdown/code`（Shiki）。**不装 react-flow / d3 / mermaid**；地图用 SVG 手写。
- **不改后端**：不新增表、迁移、端点；正文仍存 `knowledge_entries.body`；进度只在本机。
- **内容可公开**：条目是已发布内容，沿用现有鉴权（登录后可读）；不做免登录分享。
- **正文长度**：一篇走读可能到几十 KB；助手每轮都会带上整篇正文，内容要按"一个机制"切短。

## 验收标准

- **AC-001 路径可用**：一条 `learning-path` 渲染出有序站点与状态；点击进入对应条目；本地有进度时显示"进行中/已完成"。
- **AC-002 走读可用**：点「下一步」后高亮行与解释同时切换；代码行号等于源文件真实行号（固定样例断言）。
- **AC-003 地图联动**：点地图节点 → 走读跳到对应步骤；反向切步骤 → 地图高亮对应节点（组件测试断言两个方向）。
- **AC-004 预测生效**：未作答时看不到解释；作答后看到对错与解释；「直接看解释」可用且不影响后续步骤。
- **AC-005 状态面板**：带 `state` 的步骤显示变量/栈/堆/输出，切步骤后内容随之变化；不带时不出现空面板。
- **AC-006 练习判定**：三种题型各自的正确/错误路径都能给出结果与解析；排序题不依赖拖拽也能完成。
- **AC-007 小测与得分**：每题即时反馈；块末显示"答对 N / 总数"。
- **AC-008 进度保存**：走到第 N 步离开、重新打开 → 恢复第 N 步；练习与小测得分保留；「重置本站进度」后回到初始状态。
- **AC-009 继续学习**：首页显示最近学习条目与完成度；点击进入该条目。
- **AC-010 预填不发送**：点「问 AI」打开助手并填入包含"标题 + 第 N 步 + 文件:行"的提示；**用户按发送前不产生任何上游请求**。
- **AC-011 AI 能答当前步骤**：提问后回答能引用该篇内容（集成测试断言请求携带 `entryBody`）。
- **AC-012 坏块不炸页**：五类块各自的非法输入都只降级自身；页面其余部分正常；无未捕获异常。
- **AC-013 出处可核**：块底部显示 `repo@commit`、路径、行范围、许可证；permalink 精确等于 `https://github.com/{repo}/blob/{commit}/{file}#L{a}-L{b}`。
- **AC-014 高亮与体积**：白名单语言有语法着色；未知语言纯文本；主包体积不因 Shiki 增加。
- **AC-015 预览一致**：管理端预览能看到与学习者页相同的五种块结构。
- **AC-016 入口可达**：从首页点「源码解读」进入专题；e2e 完成一次导航。
- **AC-017 零外部请求**：打开走读条目时没有发往 GitHub 的请求。
- **AC-018 适配与可访问**：360px 下不横向溢出；键盘可完成走读与三种练习；焦点可见；`prefers-reduced-motion` 下无强制动画。
- **AC-019 既有行为不变**：不带新块的条目/笔记渲染结果不变；现有学习者端与管理端 e2e 全绿。
- **AC-020 样板内容成立**：至少一篇样板满足内容口径（一个机制、5–12 步、≥1 个预测、≥1 个练习、3 题、3 个误解、面试追问、许可证已核）。

## 实现选择

以下取舍由 Agent 根据已确认边界与仓库模式给出，签字时可推翻；推翻要改这一节。

| # | 选择 | 理由 |
| --- | --- | --- |
| 1 | **长在知识库上**：一个分类 + 五种围栏块；不建独立模块/表 | 分类、条目、正文、图片、目录、前后篇、自评、关系、AI 检索都已存在 |
| 2 | **块用 JSON 围栏**，schema 集中在 `@paideia/ui` 的 `renderers/` | `CustomRenderer` 只给 `code` 字符串；JSON 可校验、可机器生成 |
| 3 | **只在文档模式启用**（`streaming=false`） | 流式回答里模型输出的块不应被当组件执行 |
| 4 | **走读与地图共用一个页级上下文**（`SourceReadingProvider`） | 双向联动必须共享状态；用 context 而不是全局 store，退出页面即释放 |
| 5 | **地图手写 SVG + 作者给 `layer/order`** | 不引布局库；分层图足够表达"请求从哪到哪"；布局可控、体积为零 |
| 6 | **状态快照由作者编写**，不做执行器 | 真实 repo 不可运行；快照能覆盖教学设计，成本低一个数量级 |
| 7 | **练习客户端判定**，不跑代码 | 三种题型都是确定性判定；无沙箱、无网络 |
| 8 | **进度用 `localStorage`，v1 不上传** | 不建表、不加端点；已有本地持久化先例。跨设备是独立小项 |
| 9 | **Shiki 用 `@streamdown/code`，语言白名单** | 官方插件、双主题、语法包按需加载 |
| 10 | **不装 Mermaid / react-flow / d3** | 地图与流程用 SVG + 图片；少三个依赖与三份样式 |
| 11 | **AI 只预填、不自动发送** | 自动发送会在用户没确认时花积分 |
| 12 | **首页入口 + 专题总览条目** | 首页已有 `QUICK_LINKS`；总览用 `learning-path` 块，不新建路由 |
| 13 | **内容先做 1 篇样板，不做批量导入** | 内容成本是瓶颈；先把"一篇合格"的标准跑通 |

## 假设

- 读者具备基础编程能力；一站 20–40 分钟能读完。
- 作者是管理员；内容可信，但渲染器仍按"不执行 HTML"处理。
- v1 选题集中在 MIT/Apache-2.0/BSD 的常用项目。
- 作者愿意写状态快照与练习；若某站不需要，这些字段可省略（不强制每步都有）。

## 待确认问题

**范围已扩容，需要你重新签署。** 两个问题会影响 v1 边界：

1. **进度要不要上服务端**：v1 建议**只存本地**（零后端）。若你要"换设备也能接着读、首页能统计学习时长"，需要一张进度表 + 端点，我可以加进 v1（代价是一条迁移、一组接口与集成测试），也可以留到 v1.5。
2. **练习要不要"跑代码"**：v1 建议**不跑**（填空/排序/找 bug，客户端判定）。真正的"写代码并运行"需要沙箱，是另一个量级的工作。
3. **Mermaid 要不要进 v1**：建议不进。地图已经可交互；顺序图 v1 用图片，v1.5 再量 Mermaid 体积。
