## 目标

- 学习者能在平台内读到**以真实开源项目为对象、按步骤走读**的源码解读；每一步都看得到对应代码、解释与出处。
- 读完不是"看完一篇文章"，而是**有互动**：能逐步推进、能即时做题、能就当前这一步追问 AI、能标记"懂了／还不懂"。
- 内容**可维护、可追溯**：每一段代码都能回到固定 commit 的具体行；许可证与出处清楚。
- 不引入新的后端模块、数据表或外部服务依赖。

## 非目标

- **不做任意 repo 的自动索引/自动生成 wiki**（DeepWiki 的地盘；内容仍需人工核）。
- **不做代码执行沙箱**（Sandpack / Pyodide / WebContainers）：真实 repo 不可运行，安全与运维成本不成立。
- **不做 Python Tutor 式逐行执行**：v1 用人工编写的代码片段与解释，不做运行时状态机。
- **不建新表、不加后端端点、不改管理端 CRUD**：正文仍然是 `knowledge_entries.body`。
- **不做用户投稿、评论、收藏、排行榜**。
- **v1 不做 Mermaid**（先量体积，见「实现选择」）；v1 的架构图用图片。
- **不做跨设备阅读进度**；走读进度只在当前页面状态里。

## 用户与工作流程

**读者**：首页看到「源码解读」入口 → 进入专题分类（按语言/主题）→ 打开一篇（先看架构图与"这篇讲什么"）→ 点「开始走读」，左侧代码、右侧解释，逐步推进 → 某一步没看懂，点「问 AI」，助手带着整篇正文回答 → 读完做 3 道小测 → 在条目底部标记「懂了／还不懂」→ 之后从「我的自评」回到这篇复习。

**作者**：管理端新建条目 → 选「源码解读」分类 → 正文里写说明与围栏块（`code-tour` / `quiz`）→ 用同一页的「预览」确认与学习者看到的一致 → 发布。代码片段从固定 commit 复制，页脚自动带出处与许可证。

## 功能需求

- **REQ-001 专题落位**：`源码解读` 作为知识库的顶级分类，下面按语言/主题建子分类；每篇是一个普通知识条目。**不新增表、不新增后端接口**。
- **REQ-002 走读块**：支持 `code-tour` 围栏块。数据至少包含 `repo`、`commit`、`license`、`file`、`steps[]`；每个 step 含 `title`、`line`、`code`、`language`、`focus[]`、`explain`。渲染为"代码 + 解释"的逐步视图：真实行号、当前步骤的 `focus` 行高亮、上一步/下一步、步骤进度、键盘左右键可切换、窄屏上下堆叠。
- **REQ-003 出处与许可**：每个走读块显示 `repo@commit`、文件路径、行范围、许可证，并提供指向该 commit 的 GitHub permalink；链接只允许 `https://github.com/...`。
- **REQ-004 降级**：JSON 非法、字段缺失、`focus` 越界、代码过长、语言未知时，**降级为可读的普通代码块/提示**，页面其余部分照常渲染；任何一个坏块都不能让整篇白屏或抛到控制台。
- **REQ-005 小测块**：支持 `quiz` 围栏块，1–10 道题；每题有题干、2–6 个选项、正确项与解析；点选后即时给出对错与解析。**结果不落库**，刷新即重置。
- **REQ-006 语法高亮**：代码块使用 Shiki（`@streamdown/code`）；只允许白名单语言（至少 `javascript/typescript/tsx/jsx/java/python/go/rust/c/cpp/sql/bash/json/yaml`）；未知语言退回纯文本；高亮必须**懒加载**，不进入应用主包。
- **REQ-007 与 AI 联动**：走读的每一步提供「问 AI」，篇末提供「让 AI 考考我」与「换个讲法」。点击后**只打开助手并预填一句话，不自动发送**。预填内容包含当前条目标题、步骤序号、文件与行号。管理端预览不显示这些按钮。
- **REQ-008 入口**：首页 `QUICK_LINKS` 增加「源码解读」，并可从知识库分类页进入；入口必须有稳定的 `data-testid` 供 e2e。
- **REQ-009 预览一致**：管理端预览与学习者页面用同一套渲染；同一段正文在两处产生的结构一致（走读块、测题块都能预览）。
- **REQ-010 适配与可访问性**：窄屏可用；所有交互可键盘完成；焦点可见；按钮/区域有可读的 `aria-label`；动效遵循 `prefers-reduced-motion`；对错反馈不能只靠颜色。
- **REQ-011 无运行时外部依赖**：阅读路径**不请求 GitHub API**、不拉取远程源码；所有代码片段随正文内置；permalink 只是普通链接。
- **REQ-012 内容口径**：一篇只讲**一个机制**；建议 5–10 步；3 道小测；至少 3 个"常见误解"；一段"面试会怎么追问"。AI 可以起草，但**行号与结论必须人工核对**；每篇必须确认许可证。
- **REQ-013 不改变既有行为**：现有知识库条目、笔记、助手回答的渲染与 e2e 不受影响；不带 `code-tour` / `quiz` 的正文渲染结果不变。

## 质量要求

- **正确**：代码行号与固定 commit 的源文件一致；`focus` 指向真实行；permalink 的行范围与展示一致。
- **健壮**：坏数据只影响它自己那个块；解析器是纯函数，有明确的上限（步数、代码行数、解释长度）。
- **性能**：切换步骤只更新组件本地状态，不重新解析整篇 markdown；Shiki 只在页面真的要渲染代码时加载；主包体积不增加。
- **安全**：代码按文本渲染，不执行 HTML；`explain` 走同一套经过净化的 markdown 渲染，且**不递归启用自定义块**；外链协议与主机名白名单。
- **可维护**：schema 与校验规则集中在一个模块；作者写错时有明确报错；有一份作者指南。
- **可访问**：键盘、焦点、读屏标签、非颜色反馈。

## 约束与依赖

- **许可证**：v1 优先 MIT / Apache-2.0 / BSD。GPL/AGPL 仓库（Linux、Redis 等）只允许极小片段并标注出处，或只链接不内嵌；落地前逐篇确认。
- **依赖**：v1 只新增 `@streamdown/code`（Shiki）。**Mermaid 不装**，先量体积再定（见「实现选择」）。
- **不改后端**：不新增表、迁移、端点；正文仍存 `knowledge_entries.body`。
- **内容可公开**：条目是已发布内容，沿用现有鉴权（登录后可读）；不做免登录分享。
- **正文长度**：一篇走读可能到几十 KB；助手每轮都会带上整篇正文，内容要按"一个机制"切短。

## 验收标准

- **AC-001 走读可用**：一篇含 `code-tour` 的已发布条目能渲染出步骤；点「下一步」后高亮行与解释同时切换；代码行号等于源文件的真实行号（用固定样例断言）。
- **AC-002 坏块不炸页**：非法 JSON、缺 `steps`、`focus` 越界、超过上限的块 → 显示可读降级内容，页面其余部分正常，控制台无未捕获异常。
- **AC-003 出处可核**：块底部显示 `repo@commit`、路径、行范围、许可证；permalink 为 `https://github.com/{repo}/blob/{commit}/{file}#L{a}-L{b}`，行范围与展示一致。
- **AC-004 小测即时反馈**：选对/选错立即给出不同结果与解析；刷新后回到未作答状态。
- **AC-005 高亮生效且可降级**：白名单语言有语法着色；未知语言显示纯文本；构建产物里主包体积不因 Shiki 增加。
- **AC-006 预填不发送**：「问 AI」打开助手并把包含"条目标题 + 第 N 步 + 文件:行"的提示填入输入框；在用户按发送前**不产生任何上游请求**。
- **AC-007 AI 能答当前步骤**：在走读页提问后，回答能引用该篇内容（集成测试断言请求携带 `entryBody`；e2e 断言问到步骤标题时回答不答非所问）。
- **AC-008 入口可达**：首页有「源码解读」入口，点击进入专题分类；e2e 从首页完成一次导航。
- **AC-009 预览一致**：管理端预览里能看到与学习者页相同的走读块与测题块结构。
- **AC-010 适配与可访问**：360px 宽度下走读块堆叠且不横向溢出；键盘左右键可切换步骤；焦点可见；`prefers-reduced-motion` 下无强制动画。
- **AC-011 零运行时外部请求**：打开走读条目时，e2e 断言没有发往 GitHub 的请求。
- **AC-012 既有行为不变**：不带新块的条目/笔记渲染结果不变；现有学习者端与管理端 e2e 全绿。
- **AC-013 内容模板成立**：至少一篇样板条目满足 REQ-012 的结构（一个机制、5–10 步、3 题、3 个误解、面试追问、许可证已核）。

## 实现选择

以下取舍由 Agent 根据已确认边界与仓库模式给出，签字时可推翻；推翻要改这一节，不是改设计。

| # | 选择 | 理由 |
| --- | --- | --- |
| 1 | **长在知识库上**，做一个分类 + 两种围栏块；不建独立模块/表 | 分类、条目、正文、图片、目录、前后篇、自评、关系、AI 检索都已存在；另起一套会把它们全部重做一遍 |
| 2 | **围栏块用 JSON**（`code-tour` / `quiz`） | `CustomRenderer` 只给 `code` 字符串；JSON 无歧义、可校验、可机器生成；YAML/自定义 DSL 要多写一个解析器 |
| 3 | **只在文档模式启用**（`streaming=false`） | 助手流式回答里不应把模型输出的 `code-tour` 当组件渲染；文档模式才是作者写的内容 |
| 4 | **Shiki 用 `@streamdown/code`，语言白名单** | 官方插件、双主题、语言按需加载；白名单避免把 200+ 语言语法打进产物 |
| 5 | **v1 不装 Mermaid**；需要图先用图片 | 体积/首屏影响未测；图片管线（上传 + 灯箱）已经能用。等量完再决定 v1.5 是否加 |
| 6 | **AI 只预填、不自动发送** | 自动发送会在用户没确认时花积分；预填保留了"我问"的主动性 |
| 7 | **小测与走读进度不落库** | 没有"学习记录"表；v1 不为此建表。刷新重置是可接受的 |
| 8 | **入口放首页 `QUICK_LINKS` + 知识库分类页** | 首页已有三张卡的现成结构；不必新做一个专题首页 |
| 9 | **内容先做 1 篇样板，不做批量导入** | 内容成本是真正的瓶颈；先把"一篇合格"的标准跑通，再复制 |

## 假设

- 读者具备基础编程能力；一篇 20–40 分钟能读完。
- 作者是管理员；内容可信，但渲染器仍按"不执行 HTML"处理。
- v1 选题集中在 MIT/Apache-2.0/BSD 的常用项目；GPL/AGPL 的选题要么不做，要么只链接。
- 模板结构（一个机制、5–10 步、3 题）是内容建议，不是运行时强制；只有 schema 是强制的。

## 待确认问题

**没有阻断批准的问题。** 三个实现取舍已按推荐值写入，签的时候可以推翻：

1. **Mermaid 放 v1 还是 v1.5**：建议 **v1.5**，先量 `@streamdown/mermaid` 的体积与首屏影响。若"可视化强"必须包含可缩放架构图，说一声，我把它提前并补一条体积验收。
2. **第一篇样板选哪个项目**：建议 **React**（与我们前端栈一致，读者最容易对照）或 **Spring Boot**（后端读者多）。不影响工件，实施时定。
3. **每篇是否必须有 3 道小测**：建议**有**。它是"互动"里成本最低、收益最直接的一块；若你希望先只做走读，也可以把测题块放到第二批。
