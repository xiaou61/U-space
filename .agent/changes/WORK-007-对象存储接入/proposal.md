# 提案 · 对象存储接入

## 一句话

把附件存储从"只有本地磁盘一个实现"变成**同一份构建里两个实现、由一处配置切换**，并把读路径改成**预签名直读**；生产切到 S3（自建 RustFS）。

## 为什么这样做

用户 2026-10-15 的原话是「对象存储我其实也是做成插件这种，就是我以后想换的话是可以随时换的这种，可扩展性高一点的」。

今天的事实是：`FileStorage` 端口在、注释里连 S3 的映射都预留好了，**但至今只有 `LocalFileStorage` 一个实现**——也就是说"可换"目前是**声明**。本项要交付的是把这句话变成**可验收的事实**：同一批用例在两种实现上都跑过。

## 方案骨架

1. **实现选择靠配置，不靠代码分支**：`paideia.knowledge.storage: local | s3`（默认 `local`，保持现状不变）。两个实现都注册为 bean，由 `@ConditionalOnProperty` 二选一。**换实现 = 改一行配置 + 重启**（用户裁决 5 明确选了这一档；不做运行时不重启热切——存储位置会变，热切需要额外的一致性设计，收益不抵风险）。
2. **新增 `S3FileStorage implements FileStorage`**，语义与本地实现**逐条对齐**：
   - `put(内容, contentType)` → key = 生成的 UUID，`PutObject` 带上 `ContentType`（端口注释里"contentType 给 S3 做对象元数据"的预留正好用上）
   - `read(id)` → `GetObject` → bytes；对象不存在 → `Optional.empty()`（与本地实现同一语义："文件没了"不是异常）
   - `delete(id)` → 先 `HeadObject` 判断存在，存在才删、返回 true；不存在返回 false（S3 的 delete 本身幂等且不报不存在，**必须 head 一下才能在语义上对齐端口**）
   - **id 仍是 UUID、仍是实现生成、仍不可枚举**（读端点免鉴权，这条不能松）
3. **端口的第四个方法（唯一一处接口变化）**：
   ```java
   default Optional<String> presignedGetUrl(String id, Duration ttl) { return Optional.empty(); }
   ```
   本地实现不覆写 → 空 → 维持"后端把字节流给你"；S3 实现覆写 → 给出有签名的直读 URL。**用 default 方法而不是抽象方法**：端口因此仍然只有三个必答的方法，"能不能直读"是能力而不是义务。
4. **读路径：`GET /api/v1/knowledge/files/{id}` 变成 302 到预签名 URL**（当实现给出了 URL 时），否则保持原样流字节。
   - 选 302 而不是"前端另调一个接口拿 URL"：**契约与正文 markdown 都不动**——正文里存的是 `/api/v1/knowledge/files/{uuid}`，浏览器跟随 302 即可。改动面最小，前端零改动。
   - 安全规则**一个字不改**：该端点仍只放行 GET，仍靠"id 不可枚举"当凭据，只是把"凭据"从"猜不到 id"扩成"猜不到 id + 短时效签名"。
5. **正文与附件的 URL 形状不变**，所以既有 e2e（上传→正文引用→学习者端看到图）仍然有效，只是中间多了一跳 302。

## 关键取舍（每条都写清代价）

| 取舍 | 选择 | 代价 |
| --- | --- | --- |
| 换实现的方式 | 配置 + 重启 | 切换不是"零停机"；生产切换要走一次重启 |
| 直读 vs 代理 | 直读（用户裁决 3） | **对象存储必须对公网开放**（见下），且预签名 URL 有有效期——用户把 URL 复制给别人，过一会就失效 |
| 端口是否加抽象方法 | 加一个 **default** 方法 | 端口从三个方法变成"三个必答 + 一个可选能力"；**这是接口变化，必须记在设计里** |
| 对象存储端口开放 | S3 API 对公网开、**控制台关掉**、桶私有 | 这台机器上任何非 80/443/8080 端口都是公网可达的（早前实测），所以"开放"和"只开这一个口"是同一件事；靠强凭据 + 短时效签名 + 无匿名策略兜住 |
| 回滚 | 改回 `local` + 重启 | S3 期间上传的附件在切回本地后会 404——**这是有损回滚**，必须在部署说明里写明；本项数据量极小（当前 0 条），风险可接受 |

## 不做

- 不做运行时不重启热切（裁决 5）。
- 不做多桶/多区域/跨区域复制、不做生命周期归档、不做 CDN。
- 不做附件的公开读（桶永远私有：**没有匿名策略**，直读一律靠签名）。
- 不动 `knowledge_files` 表（元数据仍在 MySQL；本项只挪字节）。
- 不给 admin/学习者端加"选择存储后端"的界面（那是运维配置，不是用户选项）。

## 需要用户确认的一件事（本提案唯一的对外影响）

**预签名直读要求对象存储对浏览器可达**，所以要把 RustFS 从"只监听 127.0.0.1"改成"监听公网口"。这是**把一个新的服务暴露到互联网**，属于对外的影响面变化，我需要你明确点头。配套加固我会一起做：

- **关掉控制台**（`RUSTFS_CONSOLE_ENABLE=false`）——只暴露 S3 API，不暴露管理界面；
- 桶**私有**、无匿名策略：任何一次读取都必须持有效签名；
- 凭据是 24/40 位十六进制随机串，只存在 `/etc/rustfs/rustfs.env`(600)；
- 预签名有效期给短（默认 15 分钟）；
- 仍**不动** ufw 与云安全组（这台机器上非 80/443/8080 的端口本来就通）。

若你不接受这个暴露面，等价效果的另一条路是**后端代理 + 缓存头**（浏览器仍会缓存，省掉大部分重复流量），我按你的选择改设计——但那就不是"直读"了。

## 交付物

- 代码：`S3FileStorage`、配置项与装配、端口的 default 方法、控制器的 302 分支。
- 服务器：RustFS systemd 服务（**已就绪**，当前回环监听）+ 正式运行时切到公网监听 + 控制台关闭。
- 测试：既有附件用例在两种实现下都跑过（**"换得动"的证明**）+ S3 实现的 round-trip 集成测试。
- 文档：部署形态、切换与回滚步骤（含"回滚是有损的"这条）。
