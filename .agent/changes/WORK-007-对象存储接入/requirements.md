## 已确认事实

**复核时间**：2026-10-15，逐条对照源码。

| 项 | 事实 |
| --- | --- |
| 端口 | `FileStorage`（`paideia-knowledge/.../internal/file/`）：`put(byte[] content, String contentType) → id`、`read(id) → Optional<byte[]>`、`delete(id) → boolean`。id 是**不透明标识**，调用方不得解析；实现必须保证不可枚举（因为读端点免鉴权） |
| 端口的 S3 准备度 | 接口注释里明写：`contentType` 是嗅探所得、**「实现可以拿它去做对象元数据（S3 就需要）」**——当初就是照 S3 留的接缝 |
| 实现 | 现已两个：`LocalFileStorage`（文件名 = UUID，先写 `.part` 再 `ATOMIC_MOVE`）与 `S3FileStorage`；id 校验抽成 `FileIds` 单点共用 |
| 元数据位置 | **在 MySQL、不随本项搬**：`knowledge_files(id CHAR(36) PK, original_name, content_type[嗅探], size_bytes, uploader_id, created_at)`。本项只挪**字节** |
| 读端点 | `GET /api/v1/knowledge/files/{id}` **免鉴权**（全项目仅两处之一，另一处是公开分享），安全配置里**只放行 GET**（`SecurityConfiguration.java:142`）；写入在 `/api/v1/knowledge/admin/files`（需管理员） |
| 配置 | `paideia.knowledge.storage: local(默认) \| s3`，`FileStorageConfiguration` 按它二选一装配 |
| 部署现状 | 服务器**没有 Docker**；RustFS 已 systemd 化（数据 `/var/lib/rustfs/data`、配置 `/etc/rustfs/rustfs.env` 600）；附件读写 → 生产走 S3 + 预签名直读 |

**天花板（D-15）**：原先是**单实例本地盘**。多实例部署（或需要多副本）时必须换共享存储——`FileStorage` 端口就是为此留的，本项已把它从**声明**变成**事实**（同一批用例两种实现都跑过）。

## 实现选择

记录理由，不反复交回用户。

| 选择 | 理由 |
| --- | --- |
| 同一份构建、两个实现，**改配置 + 重启**切换 | 用户决定 5。不做运行时不重启热切——热切要多一套状态迁移与并发处理，收益只是省一次重启 |
| id 校验抽成 `FileIds` **单点共用** | 读端点免鉴权，两个实现必须同一把尺子；这是换实现时最容易丢的那条安全前提 |
| **桶不自动建** | 配错桶名会静默写进另一个桶，那个错极难查——宁可启动就失败 |
| 装配 **fail fast**（缺凭据、`redirect-cache >= presign-ttl` 都启动失败） | 后者会让浏览器拿着已过期的签名去取，症状是"偶尔图片裂"，极难定位 |
| 读路径 **302 到预签名 URL**，302 带 `max-age=3600, private` | 签名有 TTL，302 缓存必须短于它；正文与前端零改动 |
| 元数据留 MySQL，**只挪字节** | 改元数据位置会把"换存储"变成"改数据模型"，收益为零 |
| 端口加 `default presignedGetUrl(...)`，本地实现**不覆写** | 本地实现该能力缺省、行为不变；端口的必答项仍是三个 |

## 验收标准

- **AC-1 可换性**：同一批附件用例在 `local` 与 `s3` 两种实现下**都不改测试代码地通过**。
- **AC-2 契约不变**：正文里的 `/api/v1/knowledge/files/{id}` 形状不变；该端点仍**只放行 GET**。
- **AC-3 不可枚举**：id 仍是 UUID，且两个实现**共同**校验。
- **AC-4 元数据不搬家**：`knowledge_files` 表结构与写入路径不变。
- **AC-5 生产可用**：线上附件可上传、可在学习者端渲染。
- **AC-6 回滚路径明确**：改回 `local` + 重启可回到现状，且文档写明**有损**。
- **AC-7 暴露面受控**：控制台关闭、桶无匿名策略、凭据只在 600 文件里。
- **AC-8 配置错误 fail fast**：`s3` 缺凭据、或 `redirect-cache >= presign-ttl` 时**启动即失败**。

## 风险与代价

- 新增常驻服务的内存与运维开销（4 核 / 16GB 的机器上，对象存储进程不是零成本）；实测 RSS 145–170MB，systemd 限额 64MB 常驻。
- **RustFS 极新**（GA 约 1 个月）且未能独立核实生产案例——数据放进去再换出来是有成本的。退路是切回 `local`（**有损**）。
- 读路径改为预签名直读后，**浏览器那层长缓存基本失效**（每次都是新签名 URL），已用"签名 TTL 7 天 + 302 缓存 1 小时"折中。
- 对象存储对公网开放是一个新暴露面，加固项见 AC-7。
