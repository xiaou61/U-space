# 提案 · 八股文专区

## 摘要

每天从牛客的 Java 面经合集抓帖子，过滤掉非技术帖，让 AI 从正文里**挑出一道技术题并写出解析**，按题目指纹去重后存进知识库的「八股文 · 面经真题」分类。学习者从知识库正常浏览即可看到，无需新页面。

## 为什么这条路能成（实测，不是推断）

| 环节 | 实测结果 |
| --- | --- |
| 抓 | `POST gw-c.nowcoder.com/api/sparta/job-experience/experience/job/list`，body `{"page":1,"pageSize":20,"jobId":639}`。**列表直接带完整正文**（`momentData.content`），不必逐条抓详情页 |
| 增量 | 该合集每天 3~7 条新帖（page1 覆盖约 2 天） |
| 匿名 | 无 Cookie 无 token 可读；连发 6 次不限流 |
| 生产可达 | `codenest-online` 上直接请求 200 / 0.54s |
| 过滤 | 14 篇面经里规则直判技术帖 2 篇；决策模型对首条 P(tech)=0.829 |
| 抽题 | 提示词压到"一道题 300 字内"后：**4.1s / 665 tokens / finish=stop / 合法 JSON** |

## 三种做法，为什么选"接入知识库"

| 做法 | 优点 | 缺点 |
| --- | --- | --- |
| **存 knowledge_entries（选定）** | 渲染、quiz 块、全文检索、自评、复习排期全现成 | 需要给条目加两列 |
| 新建一套面经表 + 独立页面 | 数据模型更贴语义 | 等于把渲染/检索/自评各写一遍，四份新代码 |
| 只在管理端给个导入按钮 | 最省事 | 不是"每天自动"，仍是人工 |

选接入知识库的决定因素是**复用面**：一条抓来的题目要能被搜索、能被自评、能被复习排期，这三件事知识库已经做完了。

## 风险

| 风险 | 严重度 | 缓解 |
| --- | --- | --- |
| **牛客改内部接口** | 高 | 抓取收在 `EssaySource` 端口后，换源只改一个实现类；失败不抛给调度器，只记日志 |
| **AI 抽题把个人信息带进正文** | 高 | 提示词三条硬约束 + `render()` 不拼原文，只拼"题目 + 我们写的解析 + 来源链接" |
| **输出被 token 上限截断** | 高（已实测触发） | 提示词压到一道题 300 字内；`MAX_TOKENS=16384`；截断时 JSON 解析失败 → 该帖计失败、不入库 |
| 抓来内容质量差 | 中 | 默认进草稿（`publish-directly: false`），人过一眼再发 |
| 每天烧额度 | 中 | `max-questions-per-run=40` / `max-posts-per-run=10` 双闸 |
| 分类不存在 | 低 | 跳过并记日志，**不自动建分类** |

## 与项目规则的冲突检查

- 不新增 Maven 依赖（JDK 自带 `HttpClient`）。
- 需要迁移 → 已按"新增一列不改旧迁移"的纪律写 V24（V22 曾因改迁移导致线上起不来）。
- 抓取地址走配置，不进业务代码硬编码。
- 不碰用户积分体系（平台行为无 userId，见 design 的取舍说明）。
