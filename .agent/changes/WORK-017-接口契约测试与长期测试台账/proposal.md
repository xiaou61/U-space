# 接口契约测试与长期测试台账方案

## 问题重述

"改了接口就一定重测"这句话无法靠纪律兑现：人会忘、跳过会被误读成通过、部署脚本默认不跑测试。本项要买的是一个**结构性保证**：接口集合一旦与登记不符、边界一旦退化，构建就红。

## 方案比较

### 方案 A：手写 60 个接口的逐条用例

每条路由一个测试方法，覆盖成功、失败、边界。

- 优点：粒度最细，语义最直观。
- 缺点：60 个方法 × 维护成本；新增接口时**没有任何机制强迫你写第 61 个**——恰恰是本项要解决的问题。放弃。

### 方案 B：OpenAPI 快照 + 契约比对（springdoc + 提交 openapi.json）

生成文档、提交快照、字段变化即红。

- 优点：能同时得到对外文档与客户端生成的基础。
- 缺点：springdoc 3.1.1 的父 POM 基于 Boot 4.1.0（当前 4.1.1），**未实际装配验证**；`ApiResponse` 统一包络与 `byte[]`/SSE/302 这几类响应会让生成结果与真实契约有偏差；快照 diff 会把"注释改一行"也判成变更。**不作为 P0**，列二期。

### 方案 C（选用）：运行时路由枚举 + 一张清单 + 通用拒绝矩阵

- 从 Spring 的 `RequestMappingHandlerMapping` 枚举**运行时真正注册**的路由（不是扫源码正则），与代码内清单做集合相等。
- 清单额外携带 `access`，用来驱动角色矩阵；`@RequestBody`、`consumes` 从 handler 方法**运行时推导**，不手写。
- 通用矩阵只跑无副作用路径：匿名 401、越权 403、畸形体 400/415、响应头。

- 优点：新增接口不登记 = 构建红，这正是需求；零新依赖；不依赖注释；错误信息直接给出缺失的 `METHOD /path`。
- 缺点：清单需要人工维护（但漏登记会红，成本变成一次机械填空）；不能替代业务语义测试（由既有 143 条承担）。

**结论**：选 C，A 的语义覆盖由既有集成测试承担，B 推迟。

## 线上冒烟的形态

三条候选：

1. **Postman/Newman**：第二个真相源，必然与代码漂移。放弃。
2. **curl 脚本**：能跑，但断言弱、失败信息差、无结构。
3. **Playwright `request`（选用）**：已装、已有 `E2E_BASE_URL` 约定、失败信息好、可复用环境变量约定。

约束：登录一次复用令牌（线上有失败限流）；**不复用 UI 的 storageState 去调 `/auth/refresh`**（refresh 轮换会把 UI 那条作废）；默认只读。

## 台账形态

三条候选：

1. 每次运行覆盖一份 `latest.md`：实现最省，但历史不可回溯，违反"长期任务"。
2. 写入工作项 `testing/report.md`：工作项一结束、代码一改就 `stale`，只能重写。放弃。
3. **每次运行一个文件，追加不覆盖（选用）**：文件名带时间戳，`ls` 即时间线；不做汇总文件（汇总必漂移）。

## 闸门

- **CI**：GitHub Actions，MySQL service container + `mvn -B verify` + 前端 typecheck/单测。公开仓库免费，且是唯一能拦住"本地忘了跑"的机制。
- **部署**：`release.ps1` 默认跑后端测试，另给 `-SkipTests` 逃生口；健康检查后追加**服务端只读探针**（health / 匿名 401 / 未知路径 404 / 首页 200）。需要身份的完整冒烟仍由本地命令显式执行——因为脚本里**刻意不含任何服务器地址与凭据**。
- **不静默跳过**：与既有规则冲突的一条要修正——`.agent/rules/always.md` 明确写"未配置口令时相关用例跳过、构建不因此失败"。本项**不改这条既有规则**，改为：CI 里设置口令并断言 `skipped == 0`；本地无口令时仍跳过，但台账必须记录 `skipped>0`，且部署闸门在 CI 通过后才算数。

## 风险

| 风险 | 处理 |
| --- | --- |
| 清单变成第二个真相源 | 只登记 `method/pattern/access` 三项，其余运行时推导；集合比较保证不漏 |
| 通用矩阵误打到写路径 | 矩阵只跑拒绝路径，永不发送合法业务数据 |
| 线上冒烟误写生产库 | 默认只读；写路径需 `ALLOW_ONLINE_MUTATION=1` |
| CI 与本地抢同一个测试库 | CI 用容器内的独立实例；本地指向 `paideia_test` |
| 台账泄露敏感信息 | 提交前扫描；只写 `local`/`online`，不写地址与账号 |
