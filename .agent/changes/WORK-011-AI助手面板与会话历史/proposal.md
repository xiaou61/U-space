# 提案 · AI 助手面板重做与会话历史

## 一句话

把助手外壳从"右下角小浮窗"改成**右侧可停靠、可调宽、可收起的常驻工作区**，并补上**会话恢复与切换**（后端加一个带归属校验的读消息端点）。

## 备选方案

### A. 右侧停靠 + 可调宽 + 可收起（建议）

**做法**：面板 `fixed right-0` 通高停靠，左缘一条 4px 拖拽把手（360–520px，默认 384）；收起后只留一个窄条按钮；展开/宽度/当前会话存本地。宽屏下面板打开时给内容区加等宽 `padding-right`，让居中的阅读列整体左移而不是被压窄。

**优点**：正是调研给出的形态（侧栏 360–420、可收成窄栏、状态持久化、不盖主操作）；改动集中在 `@paideia/assistant` 包内 + 一处内容区 padding，**不动 `AppShell` 的结构**。
**缺点/代价**：面板占位会让阅读列左移，屏幕不够宽时需要降级（REQ-006）。

### B. 保留右下浮窗，只加尺寸与美化

**优点**：改动最小。
**缺点**：**没有解决用户的原始不满**（"至少不是只固定到右下角的"），且调研把这种形态直接列为反模式。**不满足 REQ-001/002/004。**

### C. 独立整屏对话页（离开当前内容页）

**优点**：空间最大，历史列表最舒展。
**缺点**：丢掉"边看边问"这个本项最有价值的点（WORK-006 的裁决就是"助手任意处可开、条目只是可选上下文"）。**不满足 REQ-008/009 的语境。**

## 决策

**选 A。** 理由：它是唯一同时满足"不是右下角小浮窗""正文不被压垮""状态要持久"三个约束的形态，而且与调研的规格逐条对得上；改动面集中在助手包内，不需要重排整站布局。

## 代价（已告知并接受）

- 面板停靠后，窄屏（< 1024px）不能永久占位，必须降级成覆盖式/底部抽屉——**面板形态在不同视口下不一致**，这是刻意的取舍（REQ-006）。
- 会话列表一期只做"时间倒序 + 所属条目提示"，**没有搜索**（用户决定 3）。
- 当前会话 id 存本地：换浏览器/清缓存后回到"最近一条会话"，而不是"上次正在看的那条"。
