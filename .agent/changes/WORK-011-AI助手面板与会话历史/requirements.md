- **2026-10-16 登记并起草**。用户四条原话：「这个 AI 助手，能不能就变成一个可以调节尺寸，然后高级一点的，就是界面美化一下。至少不是只固定到右下角的」「对话的话也没有历史记录可以查看，按理来说应该是固定回到上次的，然后用户想要到新开对话才新开的，你这个弄的不太好呢」「你去联网搜搜其他产品，最新看看人家这种是怎么做的」。

- 前置：WORK-009 已完成上线（积分与平台凭据），本项沿用其面板内的「积分」标签页。

## 已确认事实

**复核时间**：2026-10-16，逐条对照源码。

| 项 | 事实 |
| --- | --- |
| 面板现在是固定浮窗 | `assistant-shell.tsx`：`fixed right-4 bottom-4 z-40`、`w-80`（320px）、`max-h-[70vh]`；展开与否只在组件状态，**刷新或换页就丢** |

| 会话与消息是落库的 | `ai_conversations`（`user_id`、`entry_id`、**滑动过期 `expires_at`**、`updated_at`）、`ai_messages`（`conversation_id`、`role`、`content`、`token_usage`、`created_at`） |

| 前端客户端缺两件事 | `packages/assistant/src/client.ts` 只有 `createConversation` / `sendMessage`，**没有 `conversations()`（列表）也没有读消息** |
| 既有 e2e | `apps/app/e2e/assistant.spec.ts` 共 27 条，依赖 `assistant-launcher` / `assistant-shell` / `assistant-tabs` 等 testid |

## 用户决定

| # | 问题 | 裁决 |
| --- | --- | --- |
| 1 | 面板形态 | **可随处拖动的浮动对话框**（2026-10-16 用户看过"右侧停靠"版后改向，原话：「他不能就是随心所欲的拖动吗，任意区域都可以，然后打开一个小小的对话框这种的…而不是固定到某个界面」；并反馈入口"不太明显"）：**位置与尺寸都可拖、都存本地**，入口要显眼。**先前按调研选的"右侧停靠"作废**——那份材料讲的是 B2B 后台（用户在那儿是"处理一条记录"，面板该贴住对象），与阅读界面"随手问一句再把它拖开"的场景不同 |
| 2 | 会话恢复 | 打开面板**自动回到最近会话**（有当前条目时优先该条目绑定的会话）；**「新开对话」必须是显式动作** |
| 3 | 一期不做会话搜索 | 会话有 7 天滑动 TTL，搜索价值低；且要动全文检索。调研里的"搜索命中正文/高亮那一条"留作后续 |

**调研材料**（2026-09《Ambient AI Copilots vs Chat Widgets》+ AI UX Playground 的 Conversation History Search）：侧栏 360–420px、可收成窄栏、**折叠状态持久化**、**不要每次导航自动弹开**、不要盖住画布主操作、键盘可切换、移动端用底部抽屉；**"侧栏默认不是聊天记录：先给结构化卡片，聊天输入放底部做追问"**。反模式点名两条正是现状：全局聊天**不绑对象**、只有流水账**没有结构化结果**。

## 目标

- 面板从"右下角小浮窗"变成**右侧可停靠、可调宽、可收起的常驻工作区**，状态跨刷新保持。
- **会话不再随面板收起或换条目而消失**：打开就是上次那一段，想另起才新开。
- 会话能在**列表里切换**，历史消息能真正读回来（后端补一个带归属校验的读端点）。

## 非目标

- **不做**会话搜索（见用户决定 3）。
- **不做**会话重命名 / 归档 / 删除。
- **不做**跨设备同步会话（本就服务端存，但本期不新增设备语义）。
- **不改**上游调用、计量与积分逻辑（WORK-009 已定）。
- **不做**助手在移动端的完整设计（只做"不出现永久占位侧栏"的降级）。
- **不做**多 Agent / 身份化（WORK-010 的范围）。

## 用户与工作流程

**读某条内容时随手问**：进入条目页 → 右侧面板停在那里（若之前是打开的）→ 直接问，上下文还是这条内容 → 关掉面板去别处 → 回来打开面板，**刚才那段对话还在**。
**想换个话题**：点顶部「新开对话」→ 面板变空白，旧会话仍在列表里，随时能点回去。
**查阅**：打开会话列表 → 看到自己最近若干会话（带所属条目与时间）→ 点一条，消息随之切换。

## 功能需求

- **REQ-001 浮动可拖动、可调尺寸**（2026-10-16 用户改向，见「用户决定」1；本条原写「右侧停靠可调宽」，已订正）：面板是**浮在页面上的小对话框**，**位置与尺寸都拖拽可改**（默认 384×560，宽 320–720、高 360–900），并**始终夹回可视区**（至少留 16px 可见）。
- **REQ-002 可收成窄条**：收起后只留一个窄条/按钮，正文回到全宽。
- **REQ-003 状态持久化**：展开与否 + 宽度存本地；**刷新后保持**，且**不因为导航而自动弹开**。
- **REQ-004 不压垮正文**：浮动即**覆盖**，所以**没有「内容让位」这回事**——不设根 CSS 变量、`AppShell` 不为它留 padding。正文列宽度不因面板而变。
- **REQ-005 键盘**：一个快捷键开关面板（键位属实现选择）。
- **REQ-006 窄屏降级**：视口不足时不做永久占位侧栏（改为覆盖式或底部抽屉）。
- **REQ-007 读会话消息端点**：`GET /api/v1/ai/conversations/{id}/messages`，**归属一律 SQL 校验**；不存在 / 不是本人的 / 已过期**同一条错误**；返回条数受 `ConversationWindow` 的库上限约束。
- **REQ-008 恢复最近会话**：打开面板时恢复最近会话并渲染其消息（含每条的角色、正文、用量；思考过程沿用既有折叠规则）。
- **REQ-009 显式新开**：只有点「新开对话」才建新会话；**换条目不再静默把当前会话丢掉**——有条目绑定时切到该条目的会话，没有则新建。
- **REQ-010 会话列表与切换**：能列出自己的会话（时间倒序，带所属条目提示）并切换。
- **REQ-011 保质既有行为**：流式期间收起面板仍然中断上游（不许继续计费）；「记住这条」/「存进笔记」/「积分」面板不变。

## 质量要求

- **越权面不变宽**：读消息端点的归属校验与既有一致（找不到就 404，不区分原因）。
- **不无限拉**：历史条数按既有上限截断。
- **不破坏既有 e2e**：面板 testid 保持可用（`assistant-launcher` / `assistant-shell` / 标签页），27 条助手 e2e 仍全过。
- **无障碍**：拖拽与收起是原生可达控件（键盘可操作），面板有 `aria-label`。

- 后端只加端点，**不改表**（`ai_conversations` / `ai_messages` 已够用）。

## 验收标准

- **AC-001 可拖动/可调尺寸且持久**：拖位置与尺寸后刷新，两者都保持。
- **AC-002 收起状态持久**：收起成入口按钮后刷新仍是收起；进入其它页面**不自动弹开**。
- **AC-003 键盘开关**：快捷键能开关面板。
- **AC-004 恢复上次会话**：关掉面板 → 重新打开，**上一次的消息还在**（不是空白）。
- **AC-005 显式新开**：点「新开对话」后是空白新会话；旧会话仍能在列表里找到并切回。
- **AC-006 列表切换**：会话列表能列出并切换，消息随之变化。
- **AC-007 越权回归**：用他人会话 id 读消息 → **404**；未登录 → 401。
- **AC-008 窄屏降级**：窄视口下面板转为覆盖式（不做永久占位侧栏），正文列宽度不变。
- **AC-009 既有面不回归**：27 条助手 e2e 全过；流式中收起仍中断。

## 假设

- 面板宽度与展开状态存浏览器本地（`localStorage`）即可，不做服务端偏好同步。
- 会话列表一期不分页（受 TTL 7 天与既有限制，量级很小）。

## 实现选择

实现层的取舍（签字时未单列，2026-10-18 按实际实现补记）：

| # | 选择 | 为什么 |
| --- | --- | --- |
| 1 | 面板**位置与尺寸**都存本地（`paideia:assistant-panel` 存 `{open,x,y,w,h}`），每次读出来都**夹回可视区** | 用户要的是"随心所欲拖动"；窗口变小或换屏幕后旧坐标可能落到屏幕外，读取时夹一次比写入时校验更可靠 |
| 2 | 本地会话键用**三态**：不存在 / 空串 / id | 少了这个区分，"点了新开 → 收面板 → 再打开"会把刚丢开的那条又拉回来 |
| 3 | 「收起」= **卸载**（不是隐藏） | 复用既有的"卸载即 abort 上游"纪律，不必为收起另写一条中断路径；代价是收起后没有 DOM 可保留 |
| 4 | 恢复上次会话**一旦用户动过就作废**（`touchedRef`） | 恢复是异步的（先列会话、再拉消息），用户可能在这几十毫秒里已点发送；不设这道闸会把在飞的那一轮 abort 掉（实测报 `signal is aborted without reason`） |
| 5 | 读历史的条数上限**复用库里的保留上限**（`maxStoredMessages`） | 库里本来就只留这么多，另设上限只会让"界面能看到的"和"库里有的"不一致 |
| 6 | 窄屏不占位、改覆盖式；快捷键取 `Ctrl/Cmd+J` | 窄屏没有空间做永久占位；键位属实现选择，选了业界最常用的那组 |
| 7 | `prepare` **不加 `@Transactional`**（2026-10-17 改） | 加了的话，积分预留抛 402 会把已写入的用户消息一起回滚，界面乐观画出的气泡刷新即丢。代价是"写消息 + 滑动续期"不再原子（续期失败只会让会话按原过期时间到期） |
