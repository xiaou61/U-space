# SQL 工作台、数据集与 AI 联动需求

## 本项状态与本轮变化

- **2026-10-23 建项起草（draft）**。用户原话：「这个SQL练习我其实真的没看明白是啥意思」→「要把这个表可视化起来」「执行的命令也要可视化」「类似于VSCode的界面，代码补全也是需要的」「能联动的全部联动」「AI可以现场出题，也可以让AI去给你生成集合数据」「SQL配额其实我感觉不需要有配额吧」。
- 本轮只起草四件工件，不改代码。**唯一的代码改动是修掉一个既有缺陷**（见「已确认事实」最后一行），它已单独提交，不在本项实施范围内。
- 本项把 `/practice/sql` 从「一个临时查询窗口」升级成 SQL 工作台，并把 SQL 接入助手上下文。

## 实现选择

| 编号 | 选择 | 理由 |
| --- | --- | --- |
| I-01 | 编辑器用 **CodeMirror 6**（`@codemirror/lang-sql` 按 schema 补全），**只在 SQL 页懒加载** | 补全靠 schema 自动完成，Monaco 在这件事上反而要多写胶水；体积约 200–300 kB，必须不进主包 |
| I-02 | 数据集元信息进表、**内容进对象存储**（复用 `FileStorage`），不塞数据库 blob、不继续往 classpath 加 | 社区数据集会有成千上万份；blob 会让备份与迁移变重；对象存储端口已就绪 |
| I-03 | `SqlDatasets.sql(key)` 必须改成 `sql(userId, key)` | 现有签名里没有用户，任何人猜到 key 就能跑别人的私人数据集。**这是本项唯一的真安全边界** |
| I-04 | schema 元信息在数据集**入库时抓一次存起来**，页面与补全只读缓存 | 每次打开页面起容器去 `SHOW TABLES` 是 3 秒 + 一次配额，不可接受 |
| I-05 | 上传与 AI 生成的数据集都必须**在沙箱里真导入一次**才允许保存 | 不干跑的话用户会拿到一个永远起不来的数据集，且第一次发现是在别人用的时候 |
| I-06 | 执行计划可视化只做 `EXPLAIN FORMAT=TREE`，**不做逐行单步** | MySQL 的算子级单步要 optimizer trace 或 performance_schema，重且依赖版本；TREE 的输出直接就是结果集，现有解析器能读 |
| I-07 | EXPLAIN 与用户 SQL **在同一次运行里跑**（`/sandbox/run` 加开关），不另发一次请求 | 再发一次就要再起一个容器，白等 3 秒 |
| I-08 | AI 出题的期望值**在沙箱里真跑参考 SQL 得到**，不靠模型自觉 | 结果对不对必须是实测，不能是模型说对 |
| I-09 | AI 不获得「执行 SQL」的工具；它把改好的 SQL **填回编辑器**，由用户点运行 | 内部助手只放行只读工具；跑一次 SQL 要 3 秒和一次配额；与 WORK-006「自主只建议不动作」同一口径 |
| I-10 | 只新增一个只读工具 `sql_describe_dataset`（给 key 返回表结构） | schema 可能有几十张表，整段塞进上下文既贵又浪费；按需取符合现有 `find_tools` 分层 |
| I-11 | 结果图表**让用户手动选 X/Y 轴**，不自动猜 | SQL 结果集是任意形状，自动判断永远会猜错 |
| I-12 | 社区数据集用「先发布后审核 + 举报下架」，照搬 `note_reports` 的四状态形状 | 与既有治理手段一致；发布前人工审核会让上传变成瓶颈，而社区数据集的错误后果是"内容不当"，不是"系统损坏" |

## 已修复的既有缺陷（不在本项实施范围）

- **隐藏数据集泄露**（2026-10-23 修复并已提交）：`/sandbox/status` 的 `datasets` 曾返回全部 key，练习页把 `orders-hidden-a` 渲染进下拉框，任何登录用户选中跑一句 `SELECT *` 就能看到隐藏集全部数据。修法是 `SqlDatasets` 区分 `keys()`（运行与校验用）与 `publicKeys()`（下发用），控制器只报后者；运行端点仍认全部 key（题面本来就明文写着它）。回归测试 `SqlDatasetsTest` 三条锁住边界。

## 需求

### 编辑器与可视化

- **REQ-001**：`/practice/sql` 的编辑区换成 CodeMirror 6，支持 SQL 语法高亮、行号、括号匹配、多行缩进，并**按当前数据集的 schema 提供补全**（表名、列名、SQL 关键字）。编辑器**必须懒加载**：未进入该页时不下载其代码。
- **REQ-002**：结果区按语句分卡（`statementIndex`），每张卡支持列排序、类型右对齐、`NULL` 弱化显示、超过 200 行时分页、复制为 CSV。
- **REQ-003**：提供**表结构可视化**：侧栏列出当前数据集的表与列（含类型、主键、可空），并可切换成 ER 图显示表间关系。外键缺失时允许显示数据集作者手工标注的关联。
- **REQ-004**：提供**执行计划可视化**：对当前 SQL 显示 `EXPLAIN FORMAT=TREE` 的树状视图，节点标出「走索引」与「全表扫描」两类，与课程第 07 关的判读口径一致。
- **REQ-005**：提供**结果图表**：用户手动选择 X 轴列与 Y 轴列后，把结果集渲染成柱状图或折线图；列类型不适用时明确提示而不是画一张错图。

### 数据集

- **REQ-006**：数据集分三类来源——**内置**（classpath，受信任）、**私人**（仅本人可见可用）、**社区**（所有人可见可用，含审核状态）。三者在同一个选择器里，按来源分组并标明。
- **REQ-007**：用户可**上传** SQL 文件创建私人数据集。上传必须过三道检查后才允许保存：语句白名单（只许 `CREATE TABLE`/`INDEX`/`VIEW` 与 `INSERT`）、大小与行数上限、**在沙箱里真导入一次**。
- **REQ-008**：私人数据集**只有本人能跑**。他人即使拿到 key 也必须被拒（这是 I-03 的目的，需有反向测试）。
- **REQ-009**：用户可把自己的私人数据集**发布为社区数据集**，发布后进入审核流程；作者可随时撤回。
- **REQ-010**：社区数据集支持**举报与下架**，形状照搬既有 `note_reports`：举报落表、管理员可下架、下架后不可再被运行或浏览。
- **REQ-011**：数据集详情页展示表结构、行数、作者、来源与创建时间；社区数据集额外显示举报入口。

### AI 联动

- **REQ-012**：工作台内可让 AI **现场出题**：选定数据集后生成题面 + 参考 SQL + 判定口径，参考 SQL 在沙箱里真跑一次取得期望结果集；提交后按该口径比对结果。**题不落库**（会话内用完即弃，与 WORK-032「不建题库」一致）。
- **REQ-013**：工作台内可让 AI **生成数据集**：给出 DDL + INSERT，**必须先干跑通过**才允许保存为私人数据集。
- **REQ-014**：AI 出题与生成数据集都走既有积分与 `ai_runs` 记账，新增 `RunKind` 取值；失败与超时必须返回可读原因，不静默扣费。
- **REQ-015**：工作台可**载入某一道关卡的题**（按 entryId + blockKey 定位）来试，载入后工作台仍是工作台（不计分、不写进度），并明确提示「这一题在关卡里是要计分的」。

### 助手联动

- **REQ-016**：助手能拿到**当前页面上下文**：当前数据集 key、编辑器里的 SQL 草稿、最近一次运行的错误或结果摘要。上下文**受长度上限约束**，超限时截断而不是报错。
- **REQ-017**：助手在 SQL 页可把建议的 SQL **填回编辑器**（用户点确认才生效），**不得**直接执行。
- **REQ-018**：新增只读工具 `sql_describe_dataset`：给 key 返回该数据集的表结构。它**不得**返回数据行，也不得返回隐藏数据集的内容。

### 配额与可用性

- **REQ-019**：新增**每人并发 1** 的限制（同一用户同时只能有一个运行在飞），超出时给出可读提示而不是排队。
- **REQ-020**：SQL 日上限从 20 提到 500，其角色是**熔断器**而不是预算；页面上不常驻显示剩余次数，只在接近上限时提示。
- **REQ-021**：`/sandbox/status` **不得下发隐藏数据集的 key**（已修，作为回归约束保留）。

## 验收标准

- **AC-001**：编辑器可输入、可补全；断网状态下补全仍工作（schema 来自已加载的缓存）。未进入 SQL 页时，编辑器代码不在任何已加载的 chunk 里。
- **AC-002**：多语句 SQL 返回多张结果卡，`NULL` 与空串在界面上可区分（用 `orders-public` 里 `bob` 与 `cid` 两行验证）。
- **AC-003**：表结构侧栏与 ER 图展示的表/列数与数据集实际一致（用 `orders-public` 的四张表验证）。
- **AC-004**：对一句会走索引的 SQL 与一句全表扫描的 SQL，执行计划视图分别标出「走索引」与「全表扫描」。
- **AC-005**：选两列画柱状图成功；选一个非数值列作 Y 轴时给出明确提示且不渲染图表。
- **AC-006**：上传一个合法 SQL 文件能创建私人数据集并可运行；上传一个含 `TRIGGER` 的文件被拒并说明原因；上传一个语法错误的文件被拒（干跑失败）。
- **AC-007**：**反向测试**：用户 B 用用户 A 的私人数据集 key 运行，返回拒绝而不是数据。这条必须有自动化测试。
- **AC-008**：社区数据集发布后出现在他人选择器里；管理员下架后，运行与浏览都被拒。
- **AC-009**：AI 出题的参考 SQL 在沙箱真跑过（可在审计里看到那次运行）；提交一个与口径不符的结果显示「不一致」。
- **AC-010**：AI 生成的数据集若导入失败则**不允许保存**，且错误信息可读。
- **AC-011**：助手能回答「我刚才这句为什么报错」并引用当前草稿；它给出的 SQL 只能填入编辑器，界面上没有「让助手直接运行」的入口。
- **AC-012**：同一用户并发发起两次运行，第二次被明确拒绝（不是静默排队）。
- **AC-013**：`/sandbox/status` 的 `datasets` 不含任何隐藏集 key（回归测试）。

## 不做

- **不做真正的 SQL 逐行单步**：要改沙箱协议、跨进程维持状态，成本高一个数量级（I-06）。
- **不做题库表**：AI 出的题当场用完即弃（REQ-012）。
- **不给助手执行 SQL 的能力**（I-09）。
- **不自动猜图表的 X/Y 轴**（I-11）。
- **不做数据集的版本管理**：私人数据集可删可改，但不留历史版本。
- **不做数据集的市场排序/搜索**：社区数据集只按名称与来源分组，不做热度或推荐。
