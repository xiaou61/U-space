# 提案 · SQL 工作台、数据集与 AI 联动

## 摘要

`/practice/sql` 现在只是一个暴露了沙箱能力的输入框：一个 textarea、一个下拉、一个运行按钮。本项把它升级成一个**工作台**（VSCode 式编辑器 + 表结构可视化 + 执行计划可视化 + 结果图表），同时把数据集从「两个硬编码的 classpath 文件」升级成**三源一等公民**（内置 / 私人 / 社区，含上传、AI 生成、审核与下架），最后把工作台接进助手——它能看到你的草稿和报错、能出题、能造数据，但**不能替你执行**。

四块内容合成一个工作项，因为它们在数据上互相咬合：编辑器补全要 schema、schema 来自数据集、AI 出题要在数据集上真跑、助手要看到当前数据集与草稿。拆开做会先造出四套半成品的接口。

## 分期

**S1 · 工作台本体**（不依赖任何新表）

- CodeMirror 6 编辑器 + 按 schema 补全（schema 先只来自内置数据集，用一份静态清单顶上）
- 结果表增强：多语句分卡、排序、类型对齐、NULL 弱化、分页、复制 CSV
- 表结构侧栏 + ER 图
- 执行计划可视化（`/sandbox/run` 加 `explain` 开关，同一次运行里跑）
- 结果图表（手动选轴）

S1 结束时用户拿到的是「一个真正能用的 SQL 工作台」，但数据集仍只有内置那两个。

**S2 · 数据集三源**

- 迁移：数据集元信息表 + 举报表
- 内容进对象存储（复用 `FileStorage`）
- `SqlDatasets.sql(userId, key)` 改造（**安全边界**）
- 上传 + 三道检查 + 干跑
- 发布为社区 + 举报 + 下架
- 管理端两页（数据集审核、举报处理）

S2 结束时私人数据集可用，社区数据集可发布与被举报。

**S3 · AI 与助手联动**

- AI 现场出题（参考 SQL 真跑取期望）
- AI 生成数据集（干跑通过才存）
- 工作台载入关卡题
- 助手页面上下文（数据集 + 草稿 + 最近结果）
- `sql_describe_dataset` 只读工具
- 助手「填回编辑器」动作

S3 依赖 S1 的编辑器与 S2 的数据集表。

**S4 · 配额与并发收口**

- 每人并发 1
- 日上限 500 + 提示口径

S4 很小，但它改的是 `RunSlot` 与 `SandboxQuotaService` 这两个全站共用的组件，**单独成阶段以便出问题时能独立回退**。

## 关键取舍

| 取舍 | 选择 | 代价 |
| --- | --- | --- |
| 编辑器 | CodeMirror 6，懒加载 | 新增一个前端依赖；体积约 200–300 kB，必须不进主包 |
| 数据集内容存哪 | 对象存储（`FileStorage` 端口） | 线上依赖 RustFS 可达；本地开发要有回退（已有 `LocalFileStorage`） |
| 社区审核 | 先发布后审核 + 举报下架 | 有害内容会有一段时间公开可见；换来上传不被人工瓶颈卡死 |
| 执行计划 | 只做 TREE，不做逐行单步 | 学员看不到算子级细节；换来不用改沙箱协议 |
| AI 执行权 | 只填回编辑器 | 助手少一个能力；换来与「自主只建议不动作」一致，且不会被一次误判花掉配额 |
| 图表 | 手动选轴 | 多一步操作；换来不出错图 |

## 风险

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| **私人数据集越权**（`sql(userId, key)` 改造不彻底） | 一个用户的私人数据被他人读到，且界面上看不出异常 | AC-007 的反向测试是硬门槛；改造后全仓 grep `datasets.sql(` 确认无旧签名残留 |
| **对象存储不可达时数据集全部不可用** | 线上 SQL 功能整体挂掉 | 内置数据集永远留在 classpath，不依赖对象存储；对象存储失败时私人/社区数据集明确报「暂不可用」而不是空白 |
| **社区上传成为滥用入口** | 平台为他人上传的内容负责 | 三道检查 + 举报下架 + 日上传数上限；发布时记录作者，可追责 |
| **`EXPLAIN` 输出被现有 XML 解析器处理不当** | 执行计划视图显示错乱 | S1 第一个任务就是拿真实 `EXPLAIN FORMAT=TREE` 过一遍 `SqlResultCodec`，不通过就退回表格形态 |
| **CodeMirror 体积超预期** | 主包变大，首屏变慢 | 只在 SQL 页动态 import；S1 第一个任务实测体积，超过 400 kB 就重新评估 |
| **每人并发 1 影响正常使用** | 用户连点两下就被告知"忙" | 前端在运行期间禁用按钮（已有），并发闸只兜住多标签页/脚本的情况 |
| **日上限 500 被脚本刷满** | 单个账号一天内耗掉大量容器时间 | 这正是上限存在的意义；同时监控 `code_runs` 里单账号的异常密度 |

## 与既有工作项的关系

- **WORK-032**：本项是它的直接延伸。它建了沙箱、判题与两个内置数据集；本项把数据集升成三源、把练习页升成工作台。**不修改**闯关判题逻辑。
- **WORK-015**：沙箱本体。本项只在 `/sandbox/run` 上加一个 `explain` 开关，不改隔离参数。
- **WORK-007**：对象存储。本项复用 `FileStorage` 端口，不新造存储层。
- **WORK-023**：逐步执行播放器。本项**不复用**它（它只支持 Python），但执行计划视图的交互形态参照它（键盘步进、reduced-motion 降级）。
- **WORK-006 / 010 / 013**：助手行为、harness、记忆。本项只在页面上下文与一个只读工具上扩展，不改提示词分层与记忆口径。
- **WORK-033**：题目概念关联。本项的 AI 出题**不复用**它的题目身份（题不落库），但「判定口径要显式」这条口径与它一致。
