| 编号 | 决定 | 影响 |
| --- | --- | --- |

## 背景

课程与知识库已经有 114 个条目、8 条学习轨道，题目嵌在文章里。用户答完小测只知道「这一块对了 2/3」，系统不知道「他到底哪个概念不会」，也就没法回答「我该回去补哪一关」。概念图与自评已经存在，但都停留在条目粒度，且掌握度是手工加权公式，不会随作答序列演化。

## 目标

1. 每道题有稳定身份，每次作答留痕，能重放出某个用户在某概念上的学习轨迹。
2. 题目与概念建立可解释、可修正的关联（作者确认，AI 只做候选）。
3. 掌握度从启发式改为概率模型，能随作答更新，并给出「下一次作答正确」的可校准预测。
4. 答错时能沿着前置关系指出「该回去补哪个概念/关卡」，而不是只重复推当前题。
5. 练习选题按信息增益选择，而不是随机抽题。
6. 以上效果用固定金集与线上指标度量，改一次跑一次。

## 非目标

- **不做深度知识追踪（DKT/RNN 类）**：作答序列数量不足以训练，且不可解释；将来数据足够再单独评估。
- **不重开向量检索裁决**：一期用中文 bigram 词面匹配 + 概念图传播，不引入 embedding 供应商。
- **不做自动关联的直接入库**：AI 只产候选，必须经作者/管理员确认或显式批量确认。
- **不改解锁规则**（D-03）。
- **不做跨课程题目复用/组卷**：题目仍属于所在条目。
- **不覆盖 AI 训练营的实时生成链路**：`camp_items` 复用同一套掌握度模型，但接入放到后续工作项。

## 用户与工作流程

- **学习者**：答完小测后看到每个概念的掌握档位变化；答错时看到一句「建议先补：XX」并可点进对应关卡；练习模式按系统挑的题继续。
- **管理员/作者**：在现有管理端概念页看到题目级关联；可对 AI 候选做确认/修改；可查看每题的作答数与难度估计。
- **系统**：夜间或作答后增量更新掌握状态与题目统计；复习到期时进入既有复习入口。

## 功能需求

| 编号 | 需求 |
| --- | --- |
| REQ-001 | 系统能从条目内容中解析出题目，生成稳定身份：条目 id + 块 id + 题号 + 内容指纹；内容改动导致指纹变化时，旧统计不得套用到新题 |
| REQ-002 | 每次作答必须留痕：用户、题目身份、选择、是否正确、耗时、时间；同一道题多次作答全部保留，不覆盖 |
| REQ-003 | 题目可以关联 1–4 个概念，记录来源（作者 / AI 候选 / 行为推断）与置信度；一个题目可属于多个概念 |
| REQ-004 | 系统能为未标注题目生成概念候选（词面匹配 + 概念图传播），并给出可解释的匹配依据；候选不直接生效 |
| REQ-005 | 每个「用户 × 概念」维护掌握概率，随作答按知识追踪规则更新；对外仍输出分数与四档（unknown/learning/familiar/mastered），接口与前端不改 |
| REQ-006 | 每道题维护难度估计，采用在线更新；新题在作答量不足时使用先验并显式标记「未校准」 |
| REQ-007 | 用户答错某概念后，系统沿概念前置关系找出「前置已掌握但自身未掌握」的前沿节点，作为建议补课目标，并给出理由 |
| REQ-008 | 练习模式在给定概念集合内按信息增益选题，兼顾未校准题目的探索；不得选出与当前能力严重不匹配的题 |
| REQ-009 | 答错或掌握度低于阈值的概念进入既有复习调度，按间隔重复重排；不影响关卡解锁 |
| REQ-010 | 一次性批量打标必须记录调用（模型、提示词版本、token 用量），且可重复执行而不产生重复标签 |
| REQ-011 | 账号注销时，作答记录、掌握状态、题目统计中的用户关联数据一并删除（沿用级联硬删口径） |
| REQ-012 | 系统提供评估数据导出：金集、离线回放结果、线上指标；记录模型版本与参数，保证结论可复现 |

## 质量要求

- **可解释**：任何「你没掌握 X」的结论都能追到具体作答与概念关联；不输出无法解释的黑盒分数。
- **可回滚**：新的掌握度计算与旧公式并存一个开关周期，出问题能切回。
- **稀疏数据不撒谎**：作答数为 0 时显示 unknown，不用群体均值伪装成个人结论；未校准题目明确标注。
- **性能**：一次作答后的增量更新在 200ms 内完成；概念图诊断在 100ms 内返回（14 个概念、单用户规模）。
- **纯函数优先**：更新公式与选题打分做成无 IO 的纯函数，可用单测穷举。

## 约束与依赖

- 仅 MySQL；迁移文件名用 14 位时间戳；生产迁移不写业务数据。
- 平台模型凭据走既有 WORK-009 配额链路；批量打标计入 `ai_runs`，一次调用完成，不逐题调用。
- 注销级联表清单必须同步更新，遗漏即是数据残留。
- 不新增外部服务与依赖；算法实现放在 Java 侧，不引入 Python 运行时。

## 验收标准

| 编号 | 验收标准 |
| --- | --- |
| AC-001 | 修改一道题的题干后，新作答落在新身份上；旧身份的统计仍可查询，且不参与新题难度计算 |
| AC-002 | 同一用户在同一道题的多次作答全部保留，按时间回放能复现当前掌握概率（误差 < 0.001） |
| AC-003 | 在 100 题以上的金集上，概念候选的 Recall@3 不低于 0.80，且每条候选都有可读的匹配依据 |
| AC-004 | 金集回放中，「下一次作答正确」的预测 AUC 不低于 0.70，并给出校准曲线（Brier 分数记录在验证报告） |
| AC-005 | 对一个答错「索引」相关题目的用户，诊断能输出至少一条前置概念建议，且该概念在其概念图中确实是前置（可由接口断言） |
| AC-006 | 离线模拟中，按信息增益选题比随机选题达到同一掌握阈值所需题数少 20% 以上 |
| AC-007 | 注销账号后，作答表、掌握状态表中不再存在该用户的行（SQL 断言） |
| AC-008 | 现有掌握度接口与前端在切换实现后无需改动即可显示新档位；零作答用户显示 unknown 且页面不报错 |
| AC-009 | 一次批量打标调用在 `ai_runs` 留有一条记录，包含模型与提示词版本；重复执行不产生重复标签 |
| AC-010 | 关闭新实现开关后，系统回退到旧 `ConceptMastery` 口径且学习页行为不变 |

## 假设

- `quiz` 与 `code-challenge` 块在条目内 id 唯一，且 JSON 结构稳定（现有 schema 已校验）。
- 概念表在近期不会大幅增长（当前 14 个），因此图传播可以全量在内存中完成。
- 平台配额允许每天一次批量的概念候选生成（成本与每日速递同量级）。
