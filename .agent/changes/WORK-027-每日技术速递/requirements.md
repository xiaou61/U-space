### 数据源实测（数字见 [research.md](research.md) 第二节）

- **可用**：HN Algolia（字段最全）、arXiv 官方 API、量子位 / IT 之家 / InfoQ / 掘金 / 开源中国的 RSS（量子位**无正文**，只有标题）、OpenRouter 模型库（470 个含 `pricing`）。
- **可用但不稳**：`github.com/trending` 本机三次连接被拒、生产 200 且 12 行可解析 ⇒ **必须有第二条路**。
- **不可用**：HF daily_papers（双端超时）、arXiv RSS（空壳）、机器之心（302）、Solidot（403）、LMArena（超时）、Product Hunt（TLS 失败）。
- **GitHub 限额实测**：匿名 search 10/分、core 60/时；现有 `gh` token **core 5000/时、search 30/分**。

## 实现选择

| 编号 | 选择 | 理由 |
| --- | --- | --- |
| I-01 | **不新建 Maven 模块**，放进 `paideia-ai/internal/digest` | WORK-025 已在同模块跑通「抓取 + 定时 + AI + 写库」全套；本项不对外提供模块间 API，新开模块只多一次装配 |
| I-02 | **新建 `digest_items` 表，不塞 `knowledge_entries`** | 新闻是「会过期的流」，知识条目是「策展内容」。塞进去会让全文检索被每日新闻淹没，「草稿/已发布」语义对新闻也不成立 |
| I-03 | **周报单独一张 `digest_weeklies` 表**（`week_start` + `body` markdown + 生成时间） | 周报是**跨天聚合的一段叙述**，不能从条目行推导，必须存。与 I-02「日报不建表」不矛盾：日报 = 某天那批行，周报 = 一段不可推导的文本 |
| I-04 | 抓取收在 `DigestSource` 端口后面，每源一个实现，**单源失败不影响其它源** | 与 WORK-025 同一纪律。**四组源里坏两组，剩两组照常出内容** |
| I-05 | GitHub 主通路见 I-14；**任何一条通路失败都必须留下记录**，不能静默整组为空 | 页面解析随改版必坏，Search API 语义偏，两者互补 |
| I-06 | **AI 每天只调一次**：收集后对候选池一次调用，同时做「挑哪些」与「每条一句摘要」 | 面经是「每篇一次」，新闻照抄会变成几十次。一次调用把选与写合并，成本降约 30 倍 |
| I-07 | **不把 AIHOT 的接口当数据源** | 那等于套壳别人的服务；且其条款限定商业用途。只作形态参考 |
| I-08 | 调度沿用 `@Scheduled(fixedDelay)`，**默认关闭**；周报是第二个调度（`fixedDelay=7d`） | 既有三处都是这个形态，不引新依赖 |
| I-09 | 指纹去重按**规范化 URL**（剥 `utm_*`/`ref`/`spm`）+ SHA-256 | 同一条新闻被多源转载时 URL 只差追踪参数。与 WORK-025 的题目指纹**各写一份**：一个规范化题目、一个规范化 URL |
| I-10 | 只存**标题 + 自己写的一句话摘要 + 原文链接**，不镜像正文 | 与 WORK-025 I-02 同一纪律，版权面最小 |
| I-11 | 前端一个页面 `/digest`，按日分组 + 一个「周报」页签 | 与知识库两级结构同形态，不新建前端包 |
| I-12 | **管理端加「当日条目删除」**：列表 + 删除，不做完整内容管理页 | D-07 直出的配套。没有它，一条脏数据只能进数据库删 |
| I-13 | token 放 `paideia.ai.digest.github-token`（环境变量占位），**值只进被忽略的 `application-local.yml`** | 与 AI 凭据同一位置同一纪律。**未配置时退回匿名**（60/时仍够一天一次），故是可选增强 |
| I-14 | **有 token 时主通路走 Search API，页面解析降为兜底**；无 token 时反过来 | 页面解析「语义准但不稳」（本机三次连不上），Search API「稳但语义偏」（量的是新建且涨得快）。有 5000/时没必要依赖会坏掉的解析器 |
| I-15 | **按身份筛源在前端做**：往 `identity` 配置加一项「速递分组偏好」，复用 `preferredNav` 的模式 | 日报一天几十条，全量下发成本可忽略；后端加身份分支会让查询与缓存复杂化，而身份本质是展示层偏好。**与 WORK-010「不做硬权限」一致** |
| I-16 | **转笔记是纯前端动作**：按钮带着标题/摘要/来源链接跳到 `/notes/new` 预填 | 笔记模块已有新建页与客户端；不需要新的后端接口，也不需要本项依赖笔记模块 |

## 背景

平台现在的内容全是**人工策展或半自动采集的长内容**：知识库靠管理端录入，课程靠 markdown 导入，八股文靠牛客抓取后 AI 解析。**没有任何「今天技术圈发生了什么」的位置。**

而「前沿」本身就是学习材料的一种——只是它的形态是流而不是课。一个学习者如果不知道本周出了什么模型、哪个框架在涨，学的内容会很快过期。

## 目标

- 学习者每天打开平台能看到一屏「今天值得知道的事」，不必去刷 HN、GitHub。
- 无人介入即可产出；某个源挂了也能出内容，并明确记录挂了哪个。
- 每条都能点回原文，不制造「平台说这是真的」这种无出处的断言。
- 成本可控：**每天一次 AI 调用**量级。
- 读完能带走：一条速递可以变成自己的笔记。

## 非目标

- 不做实时流（D-02）。不做推送、邮件订阅。
- 不做社区投稿、评论、点赞。
- 不镜像第三方正文。
- 不做「事件聚簇 + 热度算法」（AIHOT 的核心竞争力）。排序用**源自身信号**（HN 点数、GitHub 当日新增 star）+ 一次 AI 挑选，不做跨源合并同一件事。
- 不做向量检索（项目级约束仍生效）。X-07「与学习线联动」因此押后。
- **不做后端身份过滤**：身份只影响前端分组顺序与显示（I-15）。
- 不做条目全文检索（一期按日期浏览 + 平台现有全文检索已覆盖知识库）。

## 用户与工作流程

**学习者**：从导航栏进「每日速递」→ 默认今天 → 分组卡片（前沿新闻 / GitHub 热榜 / 社区热帖 / HN）→ 每条有中文标题、一句话摘要、来源与热度数字、原文链接 → 可点「存成笔记」带着内容跳到新建笔记页 → 可切到「周报」页签看本周主线 → 可往回翻历史日期。

**运维**：日报定时任务每天跑一次；周报每周跑一次。某源失败时该组为空并在日志点名，页面不报错。内容直出（D-07），不合适的条目在管理端「当日条目」页删除。

## 功能需求

- **REQ-001**：每天定时从多个外部源采集，一次运行覆盖「昨天至今」。
- **REQ-002**：包含**四组**源（D-05 + D-12）：前沿新闻（量子位、IT 之家、InfoQ）、GitHub 每日热榜、社区热帖（掘金、开源中国）、Hacker News 前 10。
- **REQ-003**：GitHub 热榜有 token 时走 Search API、无 token 时走页面解析并退回 Search API；**任何通路失败都要留记录**。
- **REQ-004**：按规范化 URL 去重；同一内容跨源、跨天重复只入库一条。
- **REQ-005**：每天对候选池做**一次** AI 调用，产出每条中文标题与一句话摘要；失败时降级为「原标题 + 链接」，页面仍可用。
- **REQ-006**：学习者端**导航栏**有「每日速递」入口（D-06），默认当天，可查看历史。
- **REQ-007**：每条标注来源与原文链接；正文不含第三方原文整段镜像。
- **REQ-008**：采集与 AI 摘要的失败都可观察（日志 + 条目降级状态），不允许静默失败。
- **REQ-009**：单源失败不影响其它源；单次运行条目数有上限（成本闸）。
- **REQ-010**：AI 调用计入 `ai_runs`（新增 `RunKind.DIGEST` 与 `RunKind.DIGEST_WEEKLY`）。
- **REQ-011**：管理端能按日期查看当日条目并删除单条（I-12）。
- **REQ-012**（D-13）：**每周**从该周日报聚合，一次 AI 调用生成「本周技术主线」存进 `digest_weeklies`；学习者端「周报」页签可看本周与往周。
- **REQ-013**（D-14）：**按身份调整分组**——不同身份看到的源分组顺序不同，且可有分组被隐藏；配置在前端，随身份切换立即生效，不需要刷新登录态。
- **REQ-014**（D-15）：每条速递可**一键存成笔记草稿**，预填标题、摘要、来源链接与速递日期；跳转后用户可改再保存。
- **REQ-015**：周报生成失败时不影响日报；该周周报缺失时页签给出「本周周报尚未生成」而不是报错。

## 质量要求

- 抓取失败不得影响站点其它功能，定时任务异常不得拖垮进程。
- 每日 AI 消耗有硬上限：一次调用、候选池条数上限可配置；周报每周一次独立上限。
- 抓取频率克制：**每源每天一次**，不做轮询。
- 尊重来源的访问规则：优先官方 API（GitHub Search / Algolia），只在没有 API 时才解析页面；带可识别 User-Agent。
- 存储在 UTC；SQL 只写 mapper；时间由应用写入，不调数据库 `NOW()`。
- 公开仓库纪律：抓取地址、UA、限额走配置；**GitHub token 与任何凭据只进被忽略的本地文件，仓库里只留环境变量占位**。

## 约束与依赖

- **硬依赖 WORK-025**（D-08）：八股文**前端入口**完成后本项才开工。两个列表页形态几乎一样（按时间倒序 + 来源链接），一起做省一次设计；而 WORK-025 现在后端跑着、前端点不进去，本身就是待补的缺口。
- 依赖 WORK-009 的平台凭据（AI 走平台出钱，不扣用户积分——与面经同一取舍）。
- 依赖 WORK-022 的遥测（新增两个 `RunKind`）。
- 依赖 WORK-010 的身份配置结构（I-15 往它里面加一项）。
- 与 WORK-025 **共用纪律但各自独立**：两个定时任务、两套存储、两套源实现。
- **外部源是长期风险**：RSS 会改版、GitHub 页面结构会变、限额会收紧。端口化 + 兜底通路是为此准备的。
- **GitHub token 是可选增强**（I-13）：未配置时退回匿名，功能不降级，只是限额低。

## 验收标准

- **AC-001**：定时任务按日运行，连续两个自然日都能在 `digest_items` 看到对应 `edition_date` 的批次，无需人工触发。
- **AC-002**：同一 URL（含不同 `utm_*`）在两个源各喂一次，库中只有一条。
- **AC-003**：把 GitHub 主通路改成不可达，仍产出热榜条目（来自兜底），日志点名失败通路。配置 token 时主通路是 Search API，未配置时是页面解析。
- **AC-004**：把某一个 RSS 源改成不可达，其余源照常入库，当日页面正常，缺的那组为空而非整页报错。
- **AC-005**：清空平台 AI 凭据后跑一次，当日条目仍入库（标题 + 链接），标记未摘要，页面不崩。
- **AC-006**：学习者端**从导航栏**可达「每日速递」，默认当天，能翻到前一天；每条点得开原文。
- **AC-007**：抽查当日全部条目，正文只有自己写的摘要，无第三方原文整段镜像；每条有来源与链接。
- **AC-008**：一天内 `ai_runs` 里 `kind=digest` 记录为 **1 条**。
- **AC-009**：`max-items-per-run` 调小后入库条目数随之下降（成本闸生效）。
- **AC-010**：管理端按日期能看到当日清单；删除单条后学习者端不再出现，刷新仍不在。
- **AC-011**：**去掉 `github-token` 后跑一次任务仍成功**（退回匿名 + 页面解析），证明 token 是可选增强。
- **AC-012**：社区热帖组能出现掘金与开源中国的条目，且四组同时存在时页面不崩。
- **AC-013**：周报页签能看到本周周报正文；把周报生成改成失败，日报照常、页签显示「本周周报尚未生成」不报错。
- **AC-014**：切换身份后，速递分组顺序随之变化，被该身份隐藏的分组不显示；**同一天的数据一条不少地存在于库中**（只是展示不同）。
- **AC-015**：任选一条速递点「存成笔记」，新建笔记页的标题、摘要、来源链接已预填；保存后笔记出现在「我的笔记」里且内容正确。
