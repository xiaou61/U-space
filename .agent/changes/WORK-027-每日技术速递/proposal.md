# 提案 · 每日技术速递

## 摘要

每天一次，把四个方向的公开信息源收进一张表，用**一次** AI 调用给每条写中文标题与一句话摘要，学习者端一屏看完；每周从日报聚合一次周报。读完能一键变成自己的笔记。

四组源：前沿新闻（量子位 / IT 之家 / InfoQ）、GitHub 每日热榜、社区热帖（掘金 / 开源中国）、Hacker News 前 10。

**它不做什么**：不做实时流、不做跨源事件聚簇、不做热度算法、不做向量检索、不做后端身份过滤，**也不做按身份筛源（2026-10-21 撤销，见「关键取舍」4）**。

## 为什么值得做

平台现在的内容全是**长内容**：知识库靠录入、课程靠 markdown 导入、八股文靠抓取后 AI 解析。缺的不是内容，是**「今天发生了什么」这个时间维度**。

一条 24 小时内的信号（谁降价了、哪个仓库在涨、哪篇论文被讨论）如果不在平台里出现，学习者就得自己去刷四个站点。而这件事恰好是**可以无人值守完成的**——它不需要判断力，只需要采集 + 压缩。

## 三种做法，为什么选"自己抓 + 一次 AI 压缩"

| 做法 | 优点 | 缺点 |
| --- | --- | --- |
| **自己抓 + 一次 AI 压缩（选定）** | 零外部依赖、成本可估（每天一次调用）、源可换、可每天 diff | 要写解析器；源改版会坏；GitHub 页面不稳 |
| 套壳 AIHOT 的 `/api/v1/agent/*` | 立刻能用、它已经做完聚簇与热度 | 它的条款限定商业用途需授权；用户要的是"自己做一个"；源不可控；它一变我们就断 |
| 只做 RSS 阅读器（不调 AI） | 最简单、零 AI 成本 | 英文标题不翻、一堆重复转载、没有"哪些重要"的判断，等于又一个 RSS 客户端 |

选第一条的决定因素是**"能每天 diff"**：AIHOT 给你的是成品（今天的热点），我们自己的库给你的是**时间序列**（这个模型三个月降了几次价、这个仓库从什么时候开始涨）。后者才是"平台的一部分"，前者只是一个外部页面。

## 关键取舍（四处，都有代价）

### 1. AI 每天只调一次，不做「每条一次」

面经（WORK-025）是「每篇帖一次调用」，因为帖子少（每天 3–7 条）。新闻一天 40–60 条，照抄那个形态就是几十次调用，且每次都要带提示词。

一次调用把「挑哪些」与「每条写摘要」合并成一个请求：输入约 7000 token、输出约 4500 token，**单日约 1.2 万 token**。对照「每条一次」便宜约 30 倍。

**代价**：一次调用失败就全部没摘要（降级为原标题 + 链接）；提示词要同时承担两件事，调参比单任务难。

### 2. 不做跨源事件聚簇

AIHOT 的护城河是「官网发一篇、媒体转十篇、X 吵一天 → 聚成一个事件 + 按独立来源数算热度」。它需要向量或文字重合找候选、模型判关系、写入前再复核——**三步模型调用，且随事件数增长**。

一期用**源自身的信号**排序（HN 点数、GitHub 当日新增 star），再叠一次 AI 挑选。同一件事被两个源都报道时，会出现两条 —— 这是明知的重复，换来的是"一天一次调用"这条成本线不被突破。

**代价**：会有肉眼可见的重复条目。

### 3. GitHub 热榜双通路，主次随 token 反转

实测 `github.com/trending` 本机三次连接被拒、生产 200 且 12 行可解析；`api.github.com/search` 稳定但语义偏（量的是「新建且涨得快」，不是官方热榜）。

- **有 token**（D-16，主通路走 Search API，5000/时）：稳定优先。
- **无 token**（60/时）：走页面解析，失败退回 Search API。

**代价**：页面解析器随 GitHub 改版一定会坏；Search API 的榜单与真实 Trending 不完全一致。

### 4. ~~身份筛源放前端，不做服务端过滤~~（2026-10-21 撤销）

原方案：日报一天几十条，全量下发成本可忽略；后端加身份分支会让查询与缓存复杂化，身份本质是展示偏好——与 WORK-010「不做硬权限」一致。

**撤销原因**：前提不成立。后端 `Identity.selectable()` 只对 `job_seeker` 返回 true，
另外三个身份是 `disabled` 留位，**"切换身份"这个动作当前不存在**，所以"按身份筛源"既无法实现也无从验收。
一期分组顺序固定。

**仍成立的推论**：数据全量下发到浏览器（都是公开信息，无隐私问题）；若将来单日条目过千，需要改成服务端分页。

## 一期做到哪

**做**：
- `paideia-ai/internal/digest`：`DigestSource` 端口 + 六个源实现（三个 RSS 源合并成一个实现、GitHub、社区热帖、HN）+ 编排服务 + 一次 AI 压缩 + 指纹去重
- 两张表：`digest_items`、`digest_weeklies`
- 两个调度：日报（`fixedDelay=24h`）、周报（`fixedDelay=7d`），默认关闭
- 学习者端 `/digest`：按日分组 + 周报页签 + 「存成笔记」按钮
- 导航栏入口（D-06）
- 管理端「当日条目」页：列表 + 删除
- 两个 `RunKind`：`DIGEST`、`DIGEST_WEEKLY`

**不做**：
- arXiv、OpenRouter 模型 diff、仓库版本追踪、学习线联动（四条未选的扩展点）
- 事件聚簇、热度算法、词云、图表
- 全文检索（按日期浏览足够；平台已有检索覆盖知识库）
- 邮件/推送/订阅
- 条目清理（D-11 永久保留）
- MCP 工具暴露

## 风险与缓解

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| GitHub 页面改版 | 热榜组为空 | Search API 兜底（I-14）；两条路都坏时该组空但页面正常 |
| RSS 源停更/改地址 | 少一组 | 一源一实现，单源失败不影响其它（I-04） |
| 量子位无正文 | 摘要质量取决于标题 | 提示词要求「信息不足就说标题说了什么」，不编造 |
| AI 一次调用失败 | 全部无摘要 | 降级为原标题 + 链接（AC-005） |
| 周报素材超上下文 | 周报生成失败 | 假设未实测；超限则改为按天分段两轮汇总 |
| 现有 `gh` token 带 `repo` 写权限 | 泄露后能改所有仓库 | 值只进被忽略的 `application-local.yml`；一旦进日志/提交立即轮换 |
| 一次调用质量不足 | 摘要可读性差 | **最大未验证风险**；若不行需改分组多次调用，成本上升 |

## 与 WORK-025 的关系

**硬依赖，只依赖它的前端入口**。速递的列表页形态与它几乎一样（按时间倒序 + 来源链接 + 详情），共用一次设计。

**2026-10-21 复核后的事实更正**（原文说"学习者却点不进去"，不准确）：

- 分类树里 `八股文 · 面经真题` 一直是顶级分类，**知识库卡片里点得进去**。真正缺的是**首页与导航入口**——学习者得先想到去知识库翻。
- 该入口**已于 2026-10-21 补齐**：首页新增「八股文专区」卡片，按 slug 解析分类 id（生产 20 / 全新库 900，不写死），并有 e2e 从卡片点进去断言落到该分类页。
- 因此**本项的开工前提已满足**。
- 另：「定时任务未在生产启用」已过期，线上 `enabled: true` 且已产出 5 条内容；但 5 条全是 `draft`（`publish-directly: false` 是设计），需管理端过目后发布。

代码上**不依赖**：两个定时任务、两张表、两套源实现各自独立。
