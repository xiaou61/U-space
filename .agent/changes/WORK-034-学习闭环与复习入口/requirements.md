## 背景

平台已经有阅读、自评、小测、概念掌握、复习排期和训练营，但它们之间缺一条用户能走完的路：首页告诉你「有 5 个到期」，点进去是图谱；图谱告诉你「该复习了」，下一步却是重读同一篇、重做同一批已经记住答案的题。结果是复习既没有新信息，又会把间隔刷上去。

同时，首页对所有人展示同一批最新内容，身份只改变九张卡的顺序；新用户第一屏是三个 0，没有「先做这三件」的路径。最完整的学习闭环藏在训练营里，却要求先有简历。

## 目标

1. 首页的「待复习」能直接进入一个可执行的复习流程，而不是图谱。
2. 复习用**没见过的题**检验，做完后复习排期按规则变化，且不会用旧题刷间隔。
3. 首页的推荐位按本人数据排序，并说明「为什么给你看这条」。
4. 零数据用户在第一屏拿到一条三步路径；训练营在首页有入口。
5. 以上行为在 AI 不可用、积分不足、重复提交时都有确定的降级，不出现 5xx 或错账。

## 非目标

- 不做推荐模型、bandit、embedding 或向量检索。
- 不建独立题库表；题目身份沿用 WORK-033。
- 不改关卡解锁规则（WORK-033 D-03）。
- 不做无简历训练营、不改训练营的出卷/计划算法。
- 不接入 Laya 的任何新用途。
- 不建产品行为埋点平台；只用已有 `knowledge_entry_views`、`learning_progress`、`ai_runs`。
- 不做 FSRS/BKT/IRT 等掌握度算法替换（WORK-033 的范围）。
- 不做题目↔概念候选重排（WORK-033 的 REQ-004）。

## 用户与工作流程

- **零数据用户**：进入首页 → 看到「选身份 / 选一条线 / 读第一篇」三步 → 选身份后首页排序变化 → 进入第一条学习线。
- **回访用户**：首页「待复习 5」→ `/review` 看到 5 个到期概念及承载条目 → 开始复习 → 逐题作答 → 结果页显示对错与解析 → 排期变化（答对前进，答错明天再来）。
- **AI 不可用**：`/review` 仍列出到期条目与链接；点「开始复习」时提示本次无法出题，退回「先读这篇 / 重做文内小测」，不扣积分。
- **训练营用户**：首页看到「训练营」卡片；没有简历时进入现有「先建简历」提示，不改变开营逻辑。

## 质量要求

- **数据不丢**：会话提交要么完整落库，要么完全回滚；重复提交返回 409 而不是再记一次。
- **不刷间隔**：同一概念最近已答过的题干不得再次出现；答错不前进；一次会话只推进一次。
- **成本**：一次会话最多一次生成调用、5 道题；失败不扣积分；单次生成超时 30 秒后降级。
- **延迟**：`/review` 到期列表在现有数据规模下 300ms 内返回；首页排序在前端完成，不新增串行请求。
- **可解释**：首页排序的每条理由必须来自真实信号（到期、薄弱、进行中、身份），不能写死。
- **隐私**：只读本人数据；不把答案、他人进度或积分余额带进响应。
- **可观测**：生成、降级、提交分别有日志与 `ai_runs` 记录，能回答「这次为什么没出题」。
- **兼容**：现有 `/graph`、`/learn`、训练营、知识库页面的行为不变；受影响的 `home`/`learn`/`graph` e2e 必须过。

## 假设

- WORK-033 会提供稳定的掌握度写入端口；S2 的探测任务只核对契约，不重新设计它。
- `CampItemGenerator` 能在不带训练营 `program_id` 的情况下复用；若不能，S2 抽出一个薄端口，仍复用其提示词与校验。
- 最近 20 条候选足以让首页排序产生可见差异；数据量增大后再改后端推荐。
- 到期条目一定挂在某个概念上；没有概念的到期条目仍显示，但跳过生成（沿用 `dueReviews` 的可空 `conceptId`）。
