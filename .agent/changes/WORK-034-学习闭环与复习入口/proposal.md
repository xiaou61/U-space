# 提案 · 学习闭环与复习入口

## 摘要

把已有的「到期复习 → 小测 → 掌握度 → 排期」接成一条用户能走完的路：S1 先把首页的出口修对、把推荐位按本人数据排序、把训练营放上首页、给零数据用户三步路径；S2 再做「到期概念 → 生成没见过的题 → 作答 → 按规则更新排期」。S2 的复习题是会话内临时题，掌握度写入 WORK-033 的端口，不另写一套。

## 推荐方案

**分两阶段交付，S1 先上，S2 等 WORK-033 合并。**

- **S1（不依赖 033）**：首页「待复习」指向 `/review`；`/review` 列出到期条目与承载文章；首页排序改为前端纯函数（到期 > 薄弱 > 进行中 > 身份）；零数据三步路径；训练营首页卡片。**不建表、不加迁移、不调 AI。**
- **S2（依赖 033）**：`/review` 发起 5 题会话；复用 `CampItemGenerator` 出题与校验；题目与作答按会话快照落库（`review_sessions`，不是题库）；掌握度经 033 的写入端口更新，排期按 `LearningProgressRules` 更新；失败降级到「重读承载条目」。
- **质量**：S2 同批建 20–30 条复习题金标，只验证「新题质量与不重复」，不建通用评估平台。

选择理由：S1 解决用户当下最刺眼的「点进去是图谱」，且完全不碰在飞的 033；S2 是闭环的核心，但它的数据身份必须与 033 一致，抢跑会产生两套 id 和一次迁移。分阶段能让 S1 先独立验收，同时不把 S2 的产品范围做小。

## 范围

**做**：

- 首页出口、排序、零数据路径、训练营入口。
- `/review` 到期列表与会话页。
- 新题生成、作答、排期更新的服务端流程（S2）。
- 复习题金标与一次回归（S2）。

**不做**：

- 无简历训练营（`camp_programs.resume_document_id` 非空，去简历要迁移）。
- 推荐模型、bandit、embedding、向量检索。
- 新题库表、第二套掌握度模型。
- Laya 的任何新用途（开关与度量留在 WORK-026）。
- 产品行为埋点平台。
- 掌握度算法替换（WORK-033）。

## 备选方案

**A. 一次做完，不等 033，自己建一套复习作答与掌握度。**

最强的理由：S2 可以立刻开工，不依赖另一个会话；会话与作答表按复习场景设计，语义更贴。

不选的原因：掌握度会与 033 形成两套口径，用户会看到「同一概念两种掌握」；033 合并后还要把复习结果再迁一次。这正是需求 I-02 要避免的。放弃的是「S2 立刻可做」。

**B. 拆成四个独立工作项（复习闭环、首页排序、AI 评估、训练营入口）。**

最强的理由：每项工期短、验收独立、失败影响面小。

不选的原因：用户明确要求合并（D-01）；四项共享 `HomePage`、`/review`、到期数据与同一段用户旅程，拆开会产生四次工件审批和反复对齐接口；AI 评估只为复习题服务，单独成项没有独立交付物。放弃的是「单项更小」。

**C. 维持现状。**

最强的理由：零开发、零风险。

不选的原因：首页数字是死路、复习用旧题刷间隔、训练营不可见，这三个都是用户可感知的问题；维持现状等于承认「有数据但没有行动」是最终形态。

## 风险与缓解措施

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 033 延期或接口变化 | S2 阻塞 | S1 先交付；S2 的探测任务只冻结掌握度端口，不重写 033；接口不一致时以 033 为准并改本项设计 |
| 出题重复或质量差 | 复习变成背答案 | 结合题干指纹与 `previousStems`；金标集验收；重复时跳过该概念 |
| AI 超时/积分不足 | 用户点了没反应 | 30 秒超时；失败不扣费；返回承载条目链接与「重做文内小测」 |
| 首页排序过拟合 | 推荐看起来随机 | 只用四类可解释信号；零数据退回最新；每条显示理由，便于用户判断 |
| S1 是半个功能 | 用户能看到到期但还不能做题 | S1 的列表本身有行动（进文章、看概念），不把「开始复习」做成灰色按钮；S2 上线后补全 |
| 重复提交推进两次 | 间隔被错误推后 | 服务端幂等键 + 409；数据库唯一约束兜底；反向验证 |
