# 提案 · AI训练营

## 摘要

从简历开一个 3 天或 7 天的训练营：**模型出一套单选题 → 服务端判分 → 按主题算薄弱点 → 纯函数排出每天做什么 → 走完复测一次，两次结果并排**。

关键在分工：**模型只做它擅长的（按技能画像出题），判定、聚合、排序、排期全部由代码做**。这条分工不是为了省调用费，而是为了三件代码能做而模型做不到的事——**可复现、可测试、不会编造内容**。

## 推荐方案

### 为什么是这条路

三条来自调研的硬事实：

1. **模型写计划会编造学习资源**。Jasper.ai 在 Devpost 里自报的最大坑就是这个，它的补丁是「把生成的链接抓一遍验证」。本项目有更好的解：计划项**必须**带一个库里真实存在的 `entryId`，取不到就降级成「缺口」，从结构上让编造无处落地。
2. **模型写计划不可复现**。同样输入两次得到不同结果，用户无法判断自己有没有进步，测试也无法断言。计划必须是纯函数。
3. **一个人十几道题的数据量估不出题目参数**。CAT / IRT / BKT 全部不成立（WORK-021 已在掌握度上做过同一判断）。能做且诚实的是「分档平行卷」。

### 关键机制

| 机制 | 做法 | 为什么不能省 |
| --- | --- | --- |
| **技能画像** | 只从简历提炼技术词送给模型，不送姓名/电话/邮箱/公司/学校/原文 | 既是隐私也是省 token；简历原文属于 PII，没有理由发出去 |
| **结构校验** | 四选一、答案下标在范围内、选项互不相同、解析必须提到正确选项 | 模型生成的题会坏；不校验就等于把坏题直接给用户 |
| **一次修复重试** | 违规项原样回传给模型让它改，仍失败则整次失败并退款 | 「坏了就整单失败」比「静默少给题」更可解释 |
| **分档平行卷** | 每主题 易/中/难 各约 1/3；复测同分布、不同题干 | 这是「诊断 vs 结营」可比的唯一办法，也是 CAT 的诚实替代 |
| **错一题不算弱** | 三条判据中至少两条非单点证据命中 | 一道坏题不该把整个主题打成弱项 |
| **计划锚定条目** | 读/做/复习三类必带 entryId 与已发布校验 | 让「编造资源」在结构上不可能 |
| **接入掌握度** | 得分按概念聚合，作为第四路证据喂进 `ConceptMastery` | 这是「做完这个营，图谱变了」的兑现点，也是本项区别于「出题机器人」的地方 |

### 为什么这一项值得做（而不是又一个出题器）

现在平台上有内容、有进度、有图谱，但**用户第一次进来时图上全是灰的**——因为掌握度的三路证据都需要「先在站内做过东西」。训练营是唯一能**在用户还没开始学的时候**就产出真实证据的入口：他用 15 分钟做 12 道题，图谱第一次有了颜色，计划第一次有了依据。

这也是它与「点一下让 AI 生成一个计划」的根本区别——后者产生一段文字，前者产生**状态**。

## 范围

**做**：出卷、作答与判分、按主题的薄弱点、纯函数排期、任务勾选、复测与并排对比、掌握度联动、营列表与详情、删除与注销级联。

**不做**：语音/对话式测评、主观题 AI 批改、CAT/IRT/BKT、向量检索、每日提醒、题目入库、计划手工编辑、游戏化、能力总分。

## 备选方案

### A 自建题库 + 人工审题（否决）

把模型生成的题先入一张公共题库表，管理员审过再给学生用。

- 优点：题目质量可控、可复用、多人共享时成本摊薄。
- 否决理由：**审题是个持续的人力投入，而现在线上只有两个账号**。没人审的队列会积压成死数据，审过的题又只服务极少数人。等真有多人使用、且有管理员愿意审时再改，那时改的是「题目来源」而不是数据结构。

### B 完全交给模型（一键生成计划）（否决）

一次调用同时出题、判分说明、生成计划。

- 优点：实现最省。
- 否决理由：判分让模型做就不可复现；计划里的条目会编造；每次看都要重新生成或缓存一段不可校验的文字。这正是调研里所有同类产品的坑。

### C 只做「出题 + 判分」不做计划（否决）

- 优点：范围最小。
- 否决理由：用户原话要的就是「薄弱点跟计划」。只出题等于给了一个测完没下文的体检。

## 交付拆分

| 切片 | 内容 | 可独立验收的点 |
| --- | --- | --- |
| S1 | 表 + 纯函数（排期、分档聚合、指纹、画像提炼、分钟估算） | 单测全绿，不碰网络 |
| S2 | 出题端口 + 结构校验 + 修复重试 + 计费 | 坏题被丢、空返回当失败、402 不发上游 |
| S3 | 开营 / 列表 / 详情 / 删除 | 归属 404、级联删除、注销逐表 0 行 |
| S4 | 作答与判分 | 交卷前看不到答案、伪造判定被忽略、重复交卷冲突 |
| S5 | 计划生成与任务勾选 | 纯函数可复现、锚定已发布条目、无空白日、排不完要说 |
| S6 | 复测与并排对比 | 同分布不同题、题量不一致标注、进步/持平/退步 |
| S7 | 掌握度联动 | 同一概念全错与全对分数不同、连续两次逐位相同 |
| S8 | 前端两页 + 入口 + 窄屏 + e2e | 全链路 e2e 通过（模型桩） |

## 风险与缓解措施

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| **模型出的题答案本身是错的** | 用户被判成弱项，计划方向错 | 解析必须提到正确选项（结构性锚）；错一题不判弱；页面固定披露「答案未由第三方校验」；这是**已知残留风险**，不做「精准」承诺 |
| 模型返回坏 JSON 或空内容 | 一次调用白花钱、用户看到空卷 | 一次修复重试 → 仍失败整次失败并退款；空内容与解析失败同等对待 |
| 概念表为空 | 计划的读/做任务全是「缺口」 | REQ-021 的降级已覆盖；缺口项给「让助手讲一讲」的现成出口（零新增后端） |
| 简历技能词提炼不准 | 出的题与用户实际技术栈无关 | 提炼是纯函数，可用真实简历做夹具测；提炼不出时拒绝开营（REQ-004）而不是硬着头皮出题 |
| 训练营证据与站内小测口径不一致 | 图谱分数被「训练营刷分」拉高 | 训练营证据按「该概念所有题目合并成一个答对率」进入，与站点小测同样只占一路权重，且不改 `ConceptMastery` 的任何阈值 |
| 一个用户反复开营刷调用 | 平台支出 | 最多 3 个进行中的营；题量上限 18；复测按钮标明计费 |
| 计划分钟估算偏差大 | 显示不准 | 分钟数只展示、不参与排序、不影响判定；系数写在一处并注明未实测 |
