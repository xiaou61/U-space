## 实现选择

| 编号 | 选择 | 理由 |
| --- | --- | --- |
| I-01 | 只接**一个**用途：面经帖的技术内容过滤（服务 WORK-025） | 实测这是它唯一分出胜负的场景。其它宣传用途（内容审核、提示注入防护）官方文档自己承认在文档型输入上失效 |
| I-02 | 规则在前、模型在后 | 规则零延迟零成本不会挂，先分掉大批明显的帖子；只有边界情况才花 200ms 问模型 |
| I-03 | **用 `choice` 而不是 `noul`** | 实测：同一段面经用 noul，结尾多三个字「有哪些」就从 0.243 跳到 0.675，再说一句回到 0.644。那种漂移让固定阈值不可用。换 choice 后 7 条判对 6 条，P(tech) 稳定在 0.95–0.98 |
| I-04 | 端口失败语义是**返回 empty 而不是抛异常** | 判定是"可以没有"的能力，判不了就退回规则，不该让一条内容因为判定服务挂了而丢 |
| I-05 | 默认关闭（`paideia.ai.decision.enabled: false`） | 与沙箱同一纪律：它要连外部进程，进程不在时每次判定都要等超时。打开是部署时的显式决定 |
| I-06 | 服务只绑 `127.0.0.1`，走 `LAYA_API_KEY` | 该服务除 api-key 外没有鉴权，不该暴露到公网 |
| I-07 | 容器/进程部署**本次不做** | 用户只说"集成"；现在是一个可用的 venv + 手动启动，没有 systemd、没有开机自启 |

## 背景

「决策模型」指只做判断、不生成文字的模型。它适合被用在主流程前端当过滤器：一次判断 200ms，而让生成模型写一段分析要几秒且更贵。Laya 是这个品类里唯一 Apache-2.0 且可自托管的选择。

## 目标

- 有一条可用的判定能力，能回答"这段文本是不是技术面试题"。
- 它挂了、慢了、返回垃圾时，业务照常跑，只是退回规则判断。

## 非目标

- 不用它做内容审核、提示注入防护、记忆相关性判断、场景路由。
- 不做微调、不做温度拟合。
- 不做 MCP 暴露。
- 不做容器化与开机自启（见 I-07）。

## 功能需求

- **REQ-001**：`ContentClassifier` 端口提供技术内容判定，签名不含框架类型。
- **REQ-002**：判定服务不可达 / 超时 / 返回格式异常时，返回 empty 且**不抛异常**。
- **REQ-003**：置信度低于阈值时返回 empty，由调用方降级。
- **REQ-004**：默认关闭；关闭时行为等同于"判不了"。
- **REQ-005**：`TechEssayFilter` 先按技术词种类数判定，只在边界地带才调用模型。

## 质量要求

- 失败日志**合并输出**：定时任务一次判几十条，逐条打日志会把日志冲掉。
- 不跟随重定向；连接超时 1 秒、请求超时 3 秒。
- 送进模型的文本按 `maxTextChars` 截断（默认 4000 字符）。

## 约束与依赖

- 服务需在部署环境单独启动（当前是 `/opt/laya-test` venv + `/tmp/laya-start.sh`）。
- 内存 1.7G——4 核 16G 机器上要与沙箱、AI 调用共享 CPU。
- 关联 WORK-025：它的每日抓取是这条判定的第一个调用方。

## 验收标准

- **AC-001**：关闭开关时，`TechEssayFilter` 完全按规则判定，行为与没有 Laya 时一致。
- **AC-002**：把服务地址改成不可达，判定在 3 秒内返回 empty，不抛异常，规则兜底生效。
- **AC-003**：真连服务，技术面经判为 technical（P ≥ 0.7），纯求职帖判为非技术。
- **AC-004**：一条命中 0 种技术词的帖子不触发模型调用。

## 假设

- 面经帖的技术/非技术二分能由这个模型分好。**实测 7 条命中 6 条**，样本很小，真实抓取量上去后要复测。
