## 目标

把这四个面在手机与窄屏上做到**没有将就感**：每个路由在 360px 宽下都能完整完成该页面的主要任务，不需要横向拖动、不需要放大、不会被刘海或手势条遮挡、不依赖 hover，且这套判断由自动化守着。

「最佳适配」在本项里被定义为下面四条可测标准，不含主观词：

1. **无横向溢出**：每个路由在 360×640 与 390×844 下，`documentElement.scrollWidth - clientWidth ≤ 1`；只有代码块、表格容器等显式声明 `overflow-x-auto` 的局部区域允许自身滚动。
2. **主要动作可触达**：每个页面的主要动作在 44×44 CSS px 内可点（视觉尺寸可以更小，但命中区要够），且不依赖 hover 才出现。
3. **不被系统 UI 遮挡**：所有固定定位元素与全高容器使用动态视口单位并加安全区内边距；地址栏收放不引起布局跳动或底部内容被裁。
4. **形态随宽度换，不是等比缩小**：导航、表格、弹窗、助手在窄屏换用另一种形态（抽屉/卡片/全屏/底部抽屉），而不是把桌面版压扁。

## 非目标

- **不做原生 App**：不引 React Native、Capacitor、Expo；不产出 iOS/Android 安装包。PWA 是 Web 的安装路径，不等于原生 App。
- **不改后端、不加接口、不改表**：所有内容与数据行为不变。
- **不重做视觉风格**：令牌、配色、字体、圆角、间距体系全部沿用；本项只改布局与交互形态。
- **不做平板专属三栏/横屏专属稿**：平板与横屏跟随同一套流式规则，不单独设计。
- **不把 `ui-kit` 纳入验收**：它是开发内审页，不进产品产物。
- **不做移动端性能专项**：不优化首屏 JS、不做图片格式迁移（体积只做回归检查，见 AC-011）。
- **不改桌面壳的产品形态**：只补窗口最小尺寸与窄窗口下的布局一致性。

## 用户与工作流程

**手机上的学习者**：竖屏打开 → 页头只剩品牌与头像，主导航收进抽屉（或底部栏，见实现选择）→ 点开知识库 → 分类卡片单列 → 进条目 → 正文单列、代码块自己横向滚、交互块上下堆叠 → 右侧目录变成可展开的「本页目录」→ 点「AI 助手」→ 从底部升起一个抽屉而不是盖住整屏的浮窗 → 关掉继续读。

**手机上的管理员**：打开 `/admin/` → 侧栏默认收起为抽屉，顶栏出现汉堡 → 点开抽屉选菜单 → 表格页以卡片列表呈现（每条记录一张卡，主字段在上、操作在下）→ 编辑弹窗变成全屏页（底部有保存/取消）→ 完成后关闭回到列表。

**桌面壳用户**：把窗口拖窄到手机宽度时，看到的是与手机相同的布局；窗口有最小尺寸，不会窄到不可用。

## 功能需求

### 基础设施

- **REQ-001 视口与安全区基线**：四个产品面（`app` / `admin` / `public`，`ui-kit` 可选）统一补 `viewport-fit=cover`；新增一层安全区令牌/工具类，固定定位元素（页头、悬浮入口、底部抽屉、弹窗页脚）必须让开 `env(safe-area-inset-*)`。
- **REQ-002 动态视口单位**：全高容器由 `100vh` 改为 `100dvh`（并提供 `100svh` 兜底或 `min-height` 组合），使移动浏览器地址栏收放不裁切、不跳动。
- **REQ-003 断点与布局契约**：沿用 Tailwind 默认断点（`sm 640` / `md 768` / `lg 1024`），不新增自定义断点；每页必须明确「<sm / sm–lg / ≥lg」三档的行为，并写进设计工件。
- **REQ-023 自适应行为落在共享层**：窄屏形态必须是**同一组件的另一种呈现**，而不是各页面各写一套骨架。分工固定为——导航的移动形态由外壳（`AppShell`/`LearnerHeader`、`AdminShell`）自己提供；弹窗的窄屏形态由 `packages/ui` 的 `Dialog` 决定一次，所有调用点受益；助手的窄屏形态由 `AssistantShell` 外层容器切换；**页面只负责字段与操作的差异，不负责移动端布局骨架**。新增页面时不得自带一套独立的移动端实现。

### 学习者端

- **REQ-004 移动导航**：`<md` 时三项主导航与页头搜索收进一个可开合的导航容器（抽屉或底部栏）；页头保留品牌、当前账号入口与主题开关；当前页在导航里有可感知的选中态（`aria-current`）。
- **REQ-005 首页**：hero 区在 `<sm` 收紧内边距、标题字号降一档、操作按钮换行不溢出；统计卡、最近阅读、分类、条目四组网格在窄屏全部单列。
- **REQ-006 知识库两级页**：分类卡片与条目卡片在窄屏单列；筛选/搜索栏不与标题抢行；分页与空态在窄屏可读可点。
- **REQ-007 条目页**：正文单列；右侧目录在 `<lg` 改为**可展开的本页目录**（折叠面板或抽屉），而不是直接消失；上下篇导航单列。
- **REQ-008 交互块**：`code-tour` / `code-map` / `code-challenge` / `quiz` / `learning-path` / 状态快照在 `<sm` 下上下堆叠；代码区横向滚动但页面不溢；排序题的上下按钮、小测选项的命中区 ≥44px；`code-map` 的横向滚动要有可见的滚动提示（或缩放到容器宽度）。
- **REQ-009 Markdown 正文**：表格、图片、围栏代码、长 URL 在窄屏都不撑破正文列；图片最大宽度 100%；标题与段落的字号阶梯在 360px 下仍成立。
- **REQ-010 笔记**：列表与编辑器在 `<lg` 单列；编辑/预览切换在窄屏是可发现的（分段控件或底部切换），且切走时不丢输入（复用现有未保存提示）。
- **REQ-011 我的自评与新建笔记**：筛选器、行内元信息、操作按钮在窄屏可换行、不截断关键信息；条目选择器的下拉结果宽度不超出视口。
- **REQ-012 登录/注册/分享页**：已有居中卡片在窄屏不溢出；分享页的举报表单输入框字号 ≥16px（沿用现有 `Input`）；错误与成功提示不被软键盘遮挡。

### 助手

- **REQ-013 助手窄屏形态**：`<sm`（或 `<640`）时助手改为**底部抽屉**（高度上限约 85dvh、圆角在顶部、有下拉/关闭入口），不再使用可拖动浮动窗；`≥sm` 保留现有浮动窗与拖拽/调宽。两者共享同一份会话状态与本地持久化。
- **REQ-014 助手可关闭与可返回**：底部抽屉支持遮罩点击、Esc、按钮三种关闭方式；关闭后焦点回到触发按钮；打开时正文列宽不变（沿用 WORK-011 的「覆盖不占位」语义）。
- **REQ-015 助手输入区**：软键盘弹出时输入框与发送按钮保持可见（动态视口 + 安全区）；不出现输入框被键盘盖住的情况。

### 管理端

- **REQ-016 管理端窄屏导航**：`<md` 时侧栏改为抽屉（汉堡打开、遮罩/Esc/选中后关闭），展开/收起状态与现有 `collapsed` 语义不冲突；面包屑在窄屏可截断但不丢当前页。
- **REQ-017 管理端表格**：`<md` 时四个表格页改为**卡片列表**（同一条记录一张卡：标题/主字段在上，状态与操作在下），不做"必须横向拖才能看到操作列"。桌面端表格形态不变。
- **REQ-018 管理端表单与弹窗**：`<sm` 时弹窗改为接近全屏的浮层（`max-h` 用动态视口、页脚按钮始终可见）；表单单列；富文本/预览区的编辑与预览切换在窄屏可用。

### 触控与可达性

- **REQ-019 触控目标**：主要交互控件（导航项、菜单项、图标按钮、分页、选项卡、关闭按钮）在触屏设备上命中区不小于 44×44 CSS px；`icon-sm` 这类 28px 控件在 `<md` 下必须配有等效的外层命中区。
- **REQ-020 不依赖 hover**：任何只在 `hover` 出现的信息或操作（列表行操作、卡片操作、轮播提示）必须同时有触屏可达的呈现方式。
- **REQ-021 缩放与焦点**：不禁用用户缩放（不写 `maximum-scale=1`、不写 `user-scalable=no`）；所有新形态保留键盘操作与可见焦点环；抽屉/弹窗有焦点陷阱与关闭后焦点还原。

### 桌面壳

- **REQ-022 桌面窗口边界**：Electron 主窗口设置最小尺寸（建议 360×480），保证不会出现比手机更窄的布局；窄窗口下走与手机相同的布局分支。

### PWA

- **REQ-024 可安装**：学习者端带 Web App Manifest（名称、短名、描述、`display: standalone`、`start_url`、`scope`、主题色与背景色、192/512 图标 + maskable 变体），在 Android Chrome 与桌面 Chrome 上可"添加到主屏幕/安装应用"，安装后从独立窗口启动且落在应用首页。
- **REQ-025 应用壳可离线启动**：Service Worker 预缓存构建产物（JS/CSS/HTML/图标/字体），**不缓存任何 `/api` 响应**；离线或后端不可达时打开应用能显示界面骨架与明确的"网络不可用"提示，而不是浏览器默认断网页。
- **REQ-026 更新策略**：新版本部署后用户下次打开即拿到新壳（`autoUpdate` 语义），不需要用户手动清缓存；不得出现"旧 JS 配新接口"的长期错配。
- **REQ-027 不干扰既有行为**：Service Worker 只接管同源 GET 静态资源；`/api`、`/actuator`、SSE 流式响应一律直连；开发服务器（`pnpm dev`）不注册 SW。
- **REQ-028 管理端不安装**：管理端**不提供** manifest 与 SW（内部工具，安装无收益且会缓存后台页面）；学习者端与公开页的既有构建产物不受影响。

## 质量要求

- **Q-001 一致性**：同一组件在四个应用里的窄屏行为一致（共用 `packages/ui` 的形态，不在各应用里各写一套）。
- **Q-002 不回归桌面**：`≥lg` 的现有布局、间距、字号、断点行为保持不变；改动以"窄屏新增分支"为主。
- **Q-003 依赖纪律**：不新增运行时依赖；若确实需要（例如可访问的抽屉原语），必须已在仓库里或能用现有 `Dialog`/`DropdownMenu` 组合出来。
- **Q-004 令牌纪律**：不新增硬编码颜色；安全区、触控尺寸若需要常量，作为工具类或 CSS 变量进入 `globals.css`，不散落在组件里。
- **Q-005 可测**：每条 AC 都要有对应的自动化或明确标注为人工验证的项目；不接受"看起来没问题"。

## 约束与依赖

- **与 WORK-015 的文件交叠**：WORK-015 正在给 `code-challenge` 加第四种题型（运行）。本项对 `code-challenge.tsx` 的改动必须在 WORK-015 合并之后做，或反过来；同一文件不允许两个会话同时改。

## 验收标准

- **AC-001 无横向溢出**：`app` 全部 11 条路由（含分享页、登录、注册）+ `admin` 6 个实际页面（`/`、知识分类、知识条目、举报、积分发放、积分审计；两条重定向不计）+ `public`，在 360×640 与 390×844 下 `documentElement.scrollWidth - clientWidth ≤ 1`、`body` 同值 ≤ 1（局部 `overflow-x-auto` 容器除外）。
- **AC-002 移动导航可用**：360px 下能从页头打开导航、看到并点击三项主导航与搜索；当前页有 `aria-current`；关闭后焦点回到触发按钮。
- **AC-003 条目页目录**：`<lg` 下本页目录以可展开形态存在（不是消失），展开后能跳到章节。
- **AC-004 交互块窄屏**：`code-tour` 代码与解释上下堆叠；`code-map` 不撑破页面；`quiz`/`code-challenge` 的选项与按钮命中区 ≥44×44；键盘与读屏路径仍可用。
- **AC-005 助手底部抽屉**：`<640` 打开助手时以底部抽屉呈现、高度 ≤85dvh、正文列宽不变、遮罩/Esc/按钮均可关闭、关闭后焦点回到启动按钮；`≥640` 仍是可拖动浮动窗。
- **AC-006 管理端导航**：375px 下侧栏默认不可见，汉堡打开抽屉后可到达全部菜单项，选中后自动关闭；`≥md` 行为与现在一致。
- **AC-007 管理端表格转卡片**：375px 下四个表格页以卡片呈现，每张卡片能看到桌面表格里的全部关键字段与操作，页面无横向滚动。
- **AC-008 安全区与动态视口**：固定定位元素在带刘海/手势条的设备上不被遮挡（Playwright 用 `viewport` + `env()` 无法完全模拟，采用人工 + CSS 断言双轨：断言不再出现 `100vh` 全高容器）；移动浏览器地址栏收放不导致底部按钮不可见。
- **AC-009 触控目标**：对 REQ-019 列出的控件做自动断言（读取包围盒，短边 ≥44 或外层命中区 ≥44）。
- **AC-010 测试矩阵**：`app` 与 `admin` 的 Playwright 各新增移动设备 project；每个路由至少一条冒烟用例；移动 project 全绿。
- **AC-011 桌面不回归**：现有学习者端 44 条、管理端 9 条 e2e 在桌面 project 下全绿；前端单测 227 条全绿；CSS 产物体积增量记录并说明（不设硬上限，但要量）。
- **AC-012 桌面壳**：Electron 窗口最小尺寸生效；拖到最小宽度时布局不破、不出现横向滚动。
- **AC-013 共享层承担形态**：`<md` 下导航、弹窗、表格容器、助手容器各只有一处实现；四个管理端表格页只各自提供字段与操作，不各自实现抽屉/弹窗骨架；`Dialog` 的窄屏形态在 `packages/ui` 内定义一次，调用点无需传移动端参数。
- **AC-014 PWA 可安装与可离线**：生产构建产出 `manifest.webmanifest` 与 service worker，且 manifest 的 `display/start_url/theme_color/icons` 均被浏览器解析（用 Playwright 读取 `navigator.serviceWorker` 注册与 manifest 响应断言）；断网后重新打开应用外壳仍渲染（API 请求失败只显示错误态）；构建产物体积增量记录在案。
- **AC-015 PWA 不碰 API**：对 `/api/**` 的请求不进入 Cache Storage；SSE 会话与积分预扣等既有 e2e 在启用 SW 的预览构建下仍全绿。

## 假设

- 目标设备矩阵：**360×640（下限）**、390×844、430×932；平板 768×1024 跟随流式；浏览器以 iOS Safari 与 Android Chrome 为准，微信内置浏览器为次优先级。
- 不追求设备专属像素稿；一切以现有设计令牌与 Tailwind 断点为准。
- 现有 44 条学习者端 e2e 只需在桌面 project 下保持通过；不为移动 project 复制全部用例，只做每路由冒烟 + 关键交互。
- 管理端的主要使用场景仍是桌面；手机上是"临时处理一条内容"，不承诺完整后台效率。
- 验证方式：Chromium 设备模拟（Playwright `iPhone 13` / `Pixel 7` 描述符）+ **一次 iOS Safari 真机人工走查**（安全区、地址栏收放、安装到主屏）；真机结果如实写进测试报告，不假装被自动化覆盖。
- PWA 的安装能力在 iOS 上受平台限制（只能"添加到主屏幕"、无安装提示条、`beforeinstallprompt` 不可用）；验收只对 Chrome/Edge 断言安装事件，iOS 只断言 manifest 可解析与 SW 注册成功。
- 后端地址与 CORS：PWA 安装后来源不变（仍是从服务器加载的同一 origin），因此不需要新增 CORS 白名单项。

## 实现选择

以下是为满足上述需求、基于仓库现状做出的技术选择，不需要用户逐条裁决：

- **移动导航用抽屉而不是底部栏**：用户 2026-10-18 已裁决用抽屉。三个入口不值得一条常驻底栏；复用现有 `Dialog`/`DropdownMenu` 的浮层原语，零新依赖。
- **助手底部抽屉用同一份面板内容换容器**：`ConversationPanel` 等子组件不动，只在 `AssistantShell` 外层按视口切换「浮动窗」与「底部抽屉」两种容器，避免维护两套会话逻辑。
- **管理端表格转卡片用同一份数据、两种呈现**：不复制列表逻辑，在页面层用 `md:hidden` / `hidden md:block` 切换渲染函数；卡片复用现有字段，不新增接口。
- **安全区与触控尺寸进入 CSS 层**：在 `globals.css` 增加 `.safe-*` 工具类与 `--touch-min` 变量，避免每个组件写一遍 `env()`。
- **全高容器改 `dvh`**：直接替换 `100vh` / `h-screen`，不保留 JS 测量方案。
- **Playwright 用内置 `devices['iPhone 13']` 与 `devices['Pixel 7']`**：不引入新测试依赖；移动 project 只跑标注为移动的用例集，避免 44 条桌面用例在移动下全部重跑。
- **不改现有桌面断点与类名**：新增窄屏分支为主，降低回归面。
- **移动形态挂在现有共享组件上、不新建抽象层**：不引入"ResponsiveProvider""useBreakpoint"这类运行时断点系统（CSS 断点已经够用，JS 断点会带来首帧闪烁与 SSR 不一致）；不新建 `RecordCard` 之类的通用卡片抽象（四个页面字段不同，通用卡片会变成参数怪物）。共享的只有"哪一档显示哪种容器"这个判断，它属于外壳与 `Dialog`，不属于页面。
- **管理端"仅 Web"不等于"仅桌面"**：`.agent/rules/always.md` 里的「仅 Web」指不产出桌面安装包，从未限定视口宽度；本项按窄屏可用处理，不改变该条规则含义。
- **PWA 用 `vite-plugin-pwa`**：它已把 Workbox 的预缓存、`autoUpdate`、manifest 生成三件事封装好，比手写 service worker 少一个数量级的代码，且是 Vite 生态里最常用的实现。只加到 `apps/app`，管理端不加。
- **PWA 缓存边界**：`generateSW` 的 `navigateFallback` 指向 `index.html`，`navigateFallbackDenylist` 排除 `/api`、`/actuator`；不走 runtime caching 的 `/api` 规则——**从不缓存 API**，不做 stale-while-revalidate。
- **PWA 只在生产构建立生效**：`devOptions.enabled = false`，`pnpm dev` 下没有 SW，避免开发期缓存干扰。
- **图标用 SVG + PNG 双份**：`192x192`、`512x512`、`512x512 maskable`；图标用品牌色块 + 首字母生成，不引图标库也不加图片资源管线。
