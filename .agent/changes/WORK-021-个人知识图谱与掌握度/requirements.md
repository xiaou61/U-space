# 个人知识图谱与掌握度需求

## 本项状态与本轮变化

- **2026-10-19 起草**。用户原话：「我们这个不是千人千面，那肯定对于个人来说要有一个他自己的知识学习图谱这东西的，就是他看过哪些东西，然后掌握了哪些东西，这个是一定需要记录的吧，然后再通过测试之类的巩固或者说对应的更新知识学习图片，我想弄的是一个 3d 之类的」。
- 同轮追问后用户拍了两条：**节点按概念级（B 方案）**、**主入口是 2D，3D 作为切换视角**。

### 调研事实（2026-10-19 联网核实）

- **知识追踪的主流实现都需要作答序列，不是一次测验**：`CAHLR/pyBKT`（MIT，288 星）是按"每名学生每道题的作答序列"拟合四个参数（先验、学习率、猜对、失误），其基准测试按 500 名学生、数千次作答的量级给出耗时。一个知识点只有 3 道小测题的样本量不足以拟合，且它是 Python。
- **概念级知识图谱是有现成数据形态的**：`learning-commons-org/knowledge-graph`（160 星）、`haolpku/K12-KGraph`（418 星，NeurIPS 2026）都把"知识概念 + 概念间前置关系 + 内容与概念的关联"作为最小结构，而不是把内容本身当节点。
- **图渲染库对比**（npm 当前版本）：`sigma` 4.0.3（MIT，解包 3.3 MB，WebGL，官方定位是"几千节点"）、`graphology` 0.26.0（MIT，图数据结构与算法）、`graphology-layout-forceatlas2` 0.10.1（MIT，力导向布局）、`3d-force-graph` 1.80.1（MIT，解包 15 MB，含 three.js 依赖）、`react-force-graph` 1.48.3（解包 25 MB，比直接用 vanilla 包大一截）。`@cosmograph` 系列是 **GPL-3.0**，商用授权风险，排除。
- **3D 力导向图的固有缺陷**：布局每次加载都会重新收敛，节点位置不稳定；而人对图谱的空间记忆依赖"这个点一直在那片"。所以要获得可用性，必须**持久化节点坐标**，否则每次打开都是一张新图。

## 实现选择

1. **概念是独立实体，条目是概念的载体**（`knowledge_concepts` + `knowledge_entry_concepts` 多对多）。理由：三门课可能考同一个概念，条目级节点表达不了；且用户明确选了 B。
2. **概念间关系单独建表**（`knowledge_concept_edges`），不从前置条目关系推导。理由：条目级 `prerequisite` 推导到概念级会产生 N×M 条噪音边，"所有 A 的概念都指向所有 B 的概念"没有信息量。
3. **掌握度做成服务端纯函数，档位停在 L1（加权 + 衰减），不做 BKT**。理由见调研事实：样本量不够，且 BKT 参考实现是 Python，引入跨语言服务不值得。计算集中在 `ConceptMastery` 一个类，将来换算法只改它。
4. **浏览记录单独建表，不加在 `learning_progress` 上**。理由：浏览不等于"开始学习"，混在一起会让「我还什么都没做」和「我路过看了一眼」无法区分；且 `learning_progress` 的每行都参与课程进度统计。
5. **自评维持两档，本期不加第三档**。理由：图谱需要的是"自己说懂/不懂"这一个信号，两档已经够；加档会同时改动校验、记忆桥（WORK-010 T-08 把自评转结构化记忆）与既有 e2e，收益不抵成本。
6. **2D 用 sigma + graphology + forceatlas2**，3D 用 `3d-force-graph`，两者都**动态 import**，只在进入图谱页时加载。理由：手写力导向布局需要数百行且效果更差；sigma 的交互（缩放、悬停、点选）开箱可用。
7. **节点坐标持久化**：首次进入用 forceAtlas2 算一次布局，坐标按图结构指纹存本地；后续进入直接用存档坐标，不重算。理由见调研事实；这是 3D 能否可用的前提，2D 同样受益（"Redis 那片一直在右下角"）。
8. **图谱端点一次返回节点 + 边 + 每节点最多 8 条载体条目**，不再单开概念详情端点。理由：点击节点要看"这个概念由哪几篇文章承载"，第二次请求会让点选有延迟。
9. **概念与关联的维护放管理端概念页**（概念 CRUD + 关联条目 + 概念间关系），**不做从正文自动抽取概念**。理由：自动抽取会产生一批不可控的脏概念，而图谱的质量完全取决于概念表的干净程度。

## 背景

平台现在有内容、有课程进度、有自评、有代码运行记录，但这些是**四份互不相干的表**。用户端能看到的只有一张条目列表——他无法回答"我到底会什么、哪里是空的、哪个快忘了"。

同时，"千人千面"的前提是平台知道每个人的状态。而现在每个学习者的状态只存在于三张彼此不连通的表里，没有一个共同视图，也没有"概念"这一层——所以三门课里重复出现的东西在系统里是三个孤立条目。

本项补的就是这一层：**概念**作为知识的最小单位，**掌握度**作为用户在每个概念上的状态，**图谱**作为这两者的可见形态。

## 目标

- 让每个学习者能在一张图上看到：自己接触过哪些概念、每个概念掌握到什么程度、哪些到期该复习、概念之间的先后关系。
- 让"掌握度"成为一个**有据可查、可复算、可单测**的服务端计算，而不是界面上的装饰。
- 让 AI 助手能读到同一份掌握度，从"泛泛而谈"变成"专挑你薄弱的地方"。
- 概念与关系可由管理员维护，**新增内容不需要改代码**即可挂到既有概念上。

## 非目标

- 不做自动概念抽取（从正文用 LLM 生成概念与关系）。
- 不做 BKT / DKT 等知识追踪模型。
- 不做跨用户对比、排行榜、班级视图。
- 不做概念级的独立题目（题目仍挂在条目上）。
- 不做图谱导出、分享、公开页。
- 不做"凭证 / 徽章 / 等级"这类游戏化产物。
- 不改自评的两档取值（见实现选择 5）。

## 用户与工作流程

**学习者（首次）**：进入 `/learn/graph` → 看到空状态提示"还没有概念，等管理员建立"或一张极简图 → 点任意节点 → 右侧面板显示概念说明与该概念的载体条目 → 点条目进入阅读。

**学习者（日常）**：
1. 打开条目详情，自动记一次浏览（同一篇重复打开只累加次数，不产生新行）；
2. 做完小测/动手题，分数已经由渲染器经 `ProgressPort` 上报到 `learning_progress`；
3. 回到图谱，该概念的颜色随之变化；
4. 到期未复习的概念带「待复习」标记，点击可直接跳到条目重做；
5. 问助手"我哪里弱"，助手读取同一份数据回答。

**管理员**：进入管理端「概念」页 → 新建概念（名称、说明、归属分类）→ 给概念挂条目 → 建概念间的前置/关联关系。

## 功能需求

- REQ-001：概念是独立实体，拥有名称（全局唯一）、可选说明、可选归属分类；一个条目可挂多个概念，一个概念可挂多个条目。
- REQ-002：概念之间可以建立「前置」与「关联」两种关系；前置有方向（A 是 B 的前置），关联无方向（只存一条）。
- REQ-003：学习者打开已发布条目详情时记录一次浏览；按 `(用户, 条目)` 聚合为一行，含累计次数、首次与最近浏览时间；未登录或草稿条目不记录。
- REQ-004：掌握度按概念计算，取值 0–1，输入为三路证据：该概念的载体条目的练习/小测得分、自评结论、浏览记录。
- REQ-005：掌握度在服务端计算，同一份数据在任意时刻重算结果相同；不把"掌握度"写进数据库（它是派生值）。
- REQ-006：掌握度分四档：未接触、了解、熟悉、掌握；另有独立标记「待复习」。
- REQ-007：提供学习者图谱端点，一次返回概念节点（含掌握度、档位、待复习、载体条目摘要）、概念关系边、以及整体统计。
- REQ-008：提供 2D 图谱页面 `/learn/graph`，默认进入 2D；节点按掌握度档位着色，可缩放、悬停、点选；点选后显示该概念的说明与载体条目列表，并能跳转。
- REQ-009：提供 3D 视角切换；3D 资源按需加载，不影响 2D 首屏。
- REQ-010：图谱布局在两次访问之间保持稳定；提供「重新布局」动作供用户手动重置。
- REQ-011：管理端提供概念维护面：概念的新增/修改/删除、概念与条目的关联与解除、概念间关系的新增与删除。
- REQ-012：AI 助手可以查询当前用户的薄弱概念与待复习概念；该查询只返回本人数据。
- REQ-013：注销账号时，该用户的浏览记录一并删除；概念与关系属于公共内容，不随用户删除。
- REQ-014：没有任何概念时，图谱页显示可理解的空状态并指引管理员入口，不显示空白画布。

## 质量要求

- 掌握度计算是**纯函数**且有单测覆盖：无证据、只有浏览、只有自评、只有分数、分数满分、分数为零、复习到期、多载体条目取平均。
- 图谱端点必须限制返回规模：节点上限 500，超出时按"有证据的优先"截断并在响应里标记 `truncated`，不得返回无界数据。
- 所有学习者端点归属取自令牌，路径与请求体不接受用户标识。
- 图谱页在无 WebGL 的环境下降级为提示，不白屏。
- 2D 与 3D 的图渲染库必须动态加载，图谱页的首屏不得拖累其他页面。
- 删除概念时，其条目关联与关系边一并级联删除，不留悬空引用。

## 约束与依赖

- 迁移编号取执行时的下一个（当前下一个是 V19），**不写死**。
- 时间存 UTC；`DATETIME(3)` 的默认值属于"让数据库取时间"，需要写入方自带的列一律由应用传值。
- SQL 只写在 mapper 内；手写 MyBatis，不引入 MyBatis-Plus。
- 前端新增依赖只允许 MIT 许可；GPL/AGPL 的图库（如 `@cosmograph`）不得引入。
- 概念与条目是同一模块（knowledge）内的实体，跨模块只通过已存在的端口。
- 本项不做数据迁移的存量回填：概念表初始为空，由管理员建立。

## 验收标准

- AC-001：管理员可以新建一个概念并把它关联到两个不同条目；图谱端点返回的该节点带有这两个条目。
- AC-002：同一概念挂在两个条目上时，两个条目的分数都会进入该概念的掌握度，而不是只取其中一个。
- AC-003：打开条目详情一次会新增一行浏览记录；同一用户同一篇再打开一次，行数不变、次数加一、最近浏览时间更新。
- AC-004：未发布条目的浏览请求被拒绝（404），且不产生浏览行。
- AC-005：掌握度纯函数在"无任何证据"时返回 0 且档位为未接触；在"只有浏览"时档位为了解；在"自评懂但无分数"时档位为熟悉；在"分数满分且自评懂"时档位为掌握。
- AC-006：同一份数据连续计算两次，结果逐位相同。
- AC-007：复习到期的概念返回 `reviewDue = true`，但掌握度不因此归零。
- AC-008：图谱端点在没有概念时返回空数组与零统计，不报错。
- AC-009：概念数超过 500 时响应被截断，`truncated = true`，且截断后仍保留全部有证据的概念。
- AC-010：图谱页在 2D 下可渲染，点选节点后展示其载体条目并可跳转；再次进入页面时节点位置与上次一致。
- AC-011：3D 视角可切换；关闭 3D 时不加载 three.js（用构建产物或网络面板证明按需加载）。
- AC-012：管理端可以删除一个概念；删除后图谱端点不再返回该节点，条目页不再显示它。
- AC-013：注销账号后，该用户的浏览记录为 0 行；概念表不受影响。
- AC-014：助手在被问到「我哪里薄弱」时，工具返回的内容包含掌握度最低与待复习的概念；返回中不含其他用户的数据。
- AC-015：没有任何概念时，图谱页显示空状态文案，而不是空白画布。
- AC-016：图谱页无 WebGL 时不白屏，给出可读提示。

## 假设

- 管理员会手工建立首批概念；本项不提供批量导入，也不做自动抽取。这是已知缺口：概念表为空时图谱没有内容。
- 条目页最终会把分数上报到 `learning_progress`（WORK-020 TASK-013）。在此之前，掌握度只有浏览与自评两路证据，档位上限为「熟悉」。
- 一个概念平均挂 1–3 个条目；节点数在数百量级，不需要分片加载。

## 待确认问题

无阻断需求批准的问题。以下两条只影响实现，已按实现选择记录：

1. **3D 的实际体验**：3D 力导向图在小屏幕上容易失去方位感，本项按用户决定保留为切换视角，若实测不可用会在验证报告里如实记录，不回退需求。
2. **首批概念的来源**：本项交付后概念表为空，需要管理员录入；若届时内容尚未导入线上，图谱页会是空的。
