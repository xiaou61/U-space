## 目标

- 学习者点「逐步执行」，能看到：**当前执行到第几行、每个变量的值怎么变、已经打印了什么**。
- 每一步都能停住、回退、前进；不需要重新执行。
- 复杂结构（栈、链表、树）能有**动画式的形态变化**，而不是只有一行 `"'abc'"`。
- 失败了要说得清：超时、步数超限、非法代码、变量太大。

## 非目标

- **不做真单步（执行挂起等用户点下一步）**：那要把"执行"变成可暂停的会话，跨沙箱进程边界维持状态，成本高一个数量级；一期做**录制回放**。
- **不做 Java 的完整追踪**（JDI + 双 JVM + 调试端口）：一期 Java 只做输出分片与行高亮，JDI 列为待定。
- **不做浏览器内解释器**（Skulpt / Pyodide / WebContainers）：要重做执行环境，且与现有沙箱重复。
- **不做时间旅行式修改变量再续跑**。
- **不做任意内存图渲染**（对象地址、引用图自动布局）：一期只画**作者或录制器给出的结构化快照**。
- **不改课程内容格式**：新能力是给 `run` 题型与"自由练习"用的，不要求 24 课全部改写。

## 用户与工作流程

**学习者**：打开一课 → 在运行题里改代码 → 点「逐步执行」→ 出现时间轴（第 3/9 步）→ 用 ← / → / 播放 看变量怎么变、哪一行在跑 → 卡住时点「问 AI」，助手拿到"你在第 5 步，`total=1`"。

**作者**：不需要改内容就能用（录制是运行时行为）；想让某个例子自带讲解时，仍可用 `code-tour` 手写快照。

## 功能需求

- **REQ-001 录制端点**：新增 `POST /api/v1/sandbox/trace`，请求 `{language, code, stdin?}`，返回按步排列的事件序列。走与 `/run` 相同的鉴权、配额、并发槽与审计。
- **REQ-002 事件形状**：每步至少有 `line`（源文件行号）、`locals`（名字 → 浅层 repr）、`output`（截至该步的 stdout 增量）、`kind`（`line` / `return` / `exception`）。**以 markdown 围栏块同一种语义描述**：前端复用 `state` 的渲染。
- **REQ-003 Python 首期**：用 `sys.settrace` 录制；**过滤 `__` 开头的名字**（`__builtins__` 有 157 条，教学无关）。
- **REQ-004 上限**：步数（默认 300）、每步变量数（20）、变量值长度（60 字符，超出截断加 `…`）、总录制字节（256KB）。任一触顶时**停止录制但仍返回已完成的部分**，并带 `truncatedReason`。
- **REQ-005 超时**：沿用沙箱 `timeout-ms`；超时也要返回已录到的事件，而不是只给一个 504。
- **REQ-006 播放器**：条目页与运行题里能打开时间轴：步进、回退、播放/暂停、速度、跳到首/末；键盘 ←/→ 可用。
- **REQ-007 变量面板**：显示当前步的变量；**值变化高亮**（与上一步不同的变量加标记），不靠颜色单一表达（需有文字/图标）。
- **REQ-008 输出面板**：显示截至当前的 stdout；重放时可看到输出逐段"长出来"。
- **REQ-009 栈**：多帧时显示调用栈（函数名 + 行号），当前帧高亮。
- **REQ-010 结构化快照**：事件可带 `structure`（栈/队列/链表/树/数组的节点与边），前端按快照差异做补间动画；缺省时不占位。
- **REQ-011 与 AI 联动**：播放器提供「这一步为什么这样」，预填当前步的变量与行号；**只预填不发送**（沿用 WORK-020 的纪律）。
- **REQ-012 降级**：录制不可用（沙箱关闭 / 语言不支持 / 超限）时，运行题退回现在的"一次性运行"，播放器不显示，并说明原因。
- **REQ-013 不与通过判定耦合**：观看录制**不产生学习记录得分**；只有运行题的用例通过才计入（现有规则不变）。

## 质量要求

- **安全**：录制脚本是**我们镜像里的常量**，用户代码只能作为被 `exec` 的内容；不得让用户代码读写录制器（用独立命名空间 + 过滤 `builtins` 逃逸面）。
- **性能**：录制的开销可接受（短代码 < 2 秒），且必须在沙箱超时内结束；前端播放是纯本地状态，不逐帧请求。
- **体积**：单次录制响应 ≤ 256KB；超出即截断并明确提示。
- **可访问性**：播放器键盘可用；步数变化对读屏可见（`aria-live`）；动画在 `prefers-reduced-motion` 下退化为直接切帧。
- **可维护**：事件契约集中在一处（前端 schema + 后端 DTO 各一份，字段名一致）。

## 约束与依赖

- 运行在现有 Docker 沙箱里，**不新增外部服务**。
- 复用现有配额与审计；一次录制计一次（与一次运行同价）。
- Python 用 3.12（镜像已是）；不使用预览特性。
- Java 一期只返回 `stdout` 分片与"没有行级追踪"的明确标识。
- **不引入 AGPL 代码**（Python Tutor 的 `java_jail` 与 `java_visualize` 只能读思路）。

## 验收标准

- **AC-001 能录**：对一段带循环的 Python 代码调 `/sandbox/trace`，返回的步数 > 1，且每一步的 `line` 递增/回退与真实执行一致（用一个固定样例断言具体行序列）。
- **AC-002 变量真实**：同一样例中，某变量在第 N 步的值与手工执行一致（断言具体值）。
- **AC-003 输出可重放**：返回的 `output` 分片按顺序拼起来等于一次性运行的 stdout。
- **AC-004 能停住**：播放器上点「下一步」只切换数据，不发任何网络请求（用请求计数断言）。
- **AC-005 变化可见**：变量值改变的步，对应变量有明确标记（不只是颜色差异）。
- **AC-006 上限生效**：故意写一个 10000 次循环，返回的步数等于上限、带 `truncatedReason`，且响应 < 256KB。
- **AC-007 超时可控**：写 `while True: pass`，在沙箱超时内返回（不挂死），并带明确提示。
- **AC-008 降级**：沙箱关闭时运行题仍可用（一次性运行），播放器不出现，并说明原因。
- **AC-009 Java 明确**：对 Java 代码请求追踪时，返回"仅输出分片、无行级追踪"的标识，前端据此不显示时间轴。
- **AC-010 安全边界**：用户代码无法读到录制器的内部变量（用一个尝试访问 `__builtins__` 逃逸的样例断言失败或拿不到东西）。
- **AC-011 不计分**：只看录制不改变 `learning_progress` 的任何字段。
- **AC-012 既有不变**：现有 `run` 题型与课程 e2e 全绿。

## 实现选择

以下由 Agent 依据已确认边界给出，签字时可推翻。

| # | 选择 | 理由 |
| --- | --- | --- |
| 1 | **录制回放，不做真单步** | 真单步要跨进程维持可暂停执行；回放能覆盖"看得懂"这个目标，成本低一个数量级 |
| 2 | **Python 用 settrace**（实测可行） | monitoring 的 callback 拿不到 frame；settrace 直接给 frame 与 locals。PEP 669 说它慢，但我们的代码短且有超时 |
| 3 | **值只存浅层 repr 字符串** | 存真对象不可能（要跨进程序列化）；浅层 repr 能表达"是什么、大概长什么样"，深拷贝遇循环引用会炸 |
| 4 | **新端点而不是扩 `/run`** | 两者语义不同（一个回结果、一个回过程），混在一起会让 `run` 的判定语义变复杂 |
| 5 | **前端复用 `state` 渲染** | 已有变量/栈/堆/输出四种面板与单测，播放器只是加一层时间轴 |
| 6 | **Java 一期不做行级** | JDI 要双 JVM + 调试端口 + 进程编排，成本是 Python 的 3–5 倍，而课程里 Java 的运行题价值低于 Python |
| 7 | **结构化动画用作者/快照数据，不靠录执行** | 从 repr 推不出链表形状；手写快照 + 补间更准也更好看 |

## 假设

- 录制能在现有 10 秒超时内完成短代码（教学代码 ≤ 50 行）。
- 学习者主要在运行题里用，不会对任意长程序请求录制。
