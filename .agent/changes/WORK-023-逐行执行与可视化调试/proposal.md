# 提案 · 逐行执行与可视化调试

## 摘要

给运行题加一个「逐步执行」：点一下，沙箱把代码**真跑一遍并录下每一步**（行号、变量、已打印的输出），前端拿这串事件做一个能前后拖动的时间轴。

不做"执行暂停等你点下一步"——那需要让执行变成一个可恢复的会话，跨 Docker 进程边界维持状态，成本高一个数量级。**录一次、放一次**能覆盖"我想看清它在干嘛"这个真实需求。

## 为什么这条路可行（本轮实测，不是推断）

在线上那台机器上用**与沙箱完全相同的 docker 参数**跑了两件事：

1. `print("ok", 6*7)` → exit 0，`ok 42`（Python 与 Java 都是）
2. 一段带循环的 Python，用 `sys.settrace` 录制 → 录到 **9 步**，`total` 从 0 → 1 → 3、`i` 从 0 → 1 → 2，输出分片拼起来是 `3\n`

也就是说：**沙箱已经在跑、镜像已经在、录制这条路在这台机器上真的通**。剩下的全是工程量，不是可行性问题。

顺带纠正一件事：我上一轮说"线上沙箱是关的"，那是读的仓库默认值 `enabled: false`。服务器上 `/opt/paideia-app/application.yml` 写的是 `true`，启动日志每次都打印"沙箱就绪"。**不需要开，它一直开着。**

## 三种做法，为什么选录制

| 做法 | 谁在用 | 真单步？ | 我们的成本 |
| --- | --- | --- | --- |
| 录制回放 | Python Tutor / Java Visualizer | 否 | **低**：沙箱里加一个录制器 + 前端播放器 |
| 语句级挂起（自己实现解释器） | Skulpt（仅 Python 2.x） | 是 | 高：等于重写解释器 |
| WASM 里的真 CPython | Pyodide | 勉强（会卡主线程） | 高：体积与线程都要重做 |

Python Tutor 用 `sys.settrace`（Python）与 JDI（Java，双 JVM + JDWP），前端统一吃 JSON。它的 Java 后端是 **AGPL-3.0**，所以只能学结构，**一行代码都不能进来**。

## 一期做到哪

- **Python**：行级追踪，变量、输出、栈都能看。
- **Java**：只返回输出分片 + 明确告诉前端"没有行级追踪"，播放器不出现。
- **动画**：从 repr 推不出链表形状，所以结构化动画走"作者/录制器给出快照 + 前端补间"，复用 `code-tour` 的 `state` 形状。

## 交付切片

| 切片 | 内容 | 可独立验证的结果 |
| --- | --- | --- |
| S1 录制器（Python） | 镜像内的 trace 脚本、事件 JSON、上限与截断 | 固定样例的步数与变量值可断言 |
| S2 端点 | `/sandbox/trace` + 配额/审计 + 降级 | 超时、超步数、沙箱关闭三条路径都返回可读结果 |
| S3 播放器 | 时间轴、变量变化高亮、输出重放 | 点下一步不发请求；键盘可用 |
| S4 结构化动画 | 快照格式与补间 | 一条链表的形态变化能播放 |
| S5（可选）Java JDI | 双 JVM + 调试端口 | 待定 |

## 风险

| 风险 | 处置 |
| --- | --- |
| settrace 让程序慢一到两个数量级（PEP 669 明说） | 步数上限 300 + 沙箱 10 秒超时 + 超限也返回已录部分 |
| 变量 repr 遇到循环引用/巨型对象 | 浅层 repr：容器只报类型与长度，不递归 |
| 用户代码想逃出录制器读内部状态 | 录制器在独立命名空间；过滤 dunder；**不把它当沙箱边界**——真正的边界仍是容器 |
| 录制响应过大打爆前端 | 256KB 上限 + 截断原因 |
| Java 侧成本被低估 | 一期明确不做，写进非目标 |
| 和 `run` 的配额混在一起看不出用量 | 审计行加 `kind=trace`，`caseId` 区分 |
