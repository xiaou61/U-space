## 用户决定

3. **记忆严格私有**：任何接口不返回他人记忆，不提供分享开关，助手只用本人记忆。已接受的代价：失去"别人在这条上踩过什么坑"的共享价值。
4. **会话历史服务端存**，设条数上限与会话有效期；Web 与桌面共享同一份，换端可续。已接受的代价：库里留存学生对话原文。
5. **工具取最宽**：只读最小集 + 写本人私有数据 + **由助手创建／修改个人笔记**。已接受的代价：引入写路径与越权防护面。

7. **自主依据记忆与对话，且只"建议"不"动作"**：助手可在打开内容时基于记忆给出建议，但**绝不自己发起任何写操作**。这条使本项与 WORK-004 记下的"不接受依赖学习状态的自主行为"一致——依据**不是**学习状态。
8. **做流式，思考过程默认折叠、可展开**：正文与思考两类事件分开渲染。
9. **沿用纯 BYOK**：平台不出钱、用量继续返还用户；不提供兜底 Key、不做体验额度、**不做成本记账**。已接受的代价：没配 Key 的人用不到对话能力。
10. **注销即级联硬删**：会话、记忆、笔记、已发出的分享全部删除，不保留、不可恢复；**不引入定时任务**。已接受的代价：误操作不可逆，他人收藏的分享链接会失效。
11. **举报与下架由管理员处理**（不做自动判定）；**注销后本人也不可再访问**。
12. **分享链接免登录可读**：链接即凭据、id 不可枚举（与 `GET /files/{uuid}` 同一模式）。已接受的代价：公网可达实例上新增一个免鉴权面。配套要求：分享内容**不带**记忆与学习痕迹。
13. **未注销时用户可查看并逐条删除自己的记忆**（设置内）。"编辑记忆"未选入。
14. **助手任意处可自由对话**，条目只是**可选**上下文；入口不再限于条目页。已接受的代价："通用聊天"属性上升，与知识库的结合相对变弱。

## 实现选择

以下由 Agent 在已确认边界内收口，影响数据或用户可见行为的逐条列出（有异议可直接推翻）。

- **记忆的归属轴**：以**学习者为唯一轴**（跨条目的全局记忆）。第 3 条定了严格私有后，可见性字段与校验可以省掉。
- **会话条数上限与会话有效期**：具体数值在设计里定，取值原则是"够用且不无限增长"。
- **多轮对话的限流**：数值在设计里定，沿用 WORK-005 的按用户固定窗口做法。
- **助手"建议"的出现时机与形态**：由记忆与对话触发，呈现为提示，**点击才动作**（第 7 条）。
- **思考过程是否存入会话历史**：拟**不入库**，只在本次响应内展示（折叠态）；理由是思考体积大且对后续轮次无用途。此条若用户要保留，需在设计前说明。
- **记忆只删不改**：第 13 条只选了"查看 + 逐条删除"，不做编辑。
- **举报流程细节**：下架后链接立即不可读、不单独通知作者（管理员处理，第 11 条）。
- **可观测性沿用既有暂缓（D-15）**：本项只记日志与 token 用量，不引入监控栈。
- **分享的固定有效期与撤回**：沿用 WORK-004 已记的范围（"分享有固定有效期"且"可撤回"），具体数值与操作方式属实现选择。
- **笔记挂靠知识条目**：沿用原 WORK-007 已记的范围（笔记挂在条目上）。

## 背景

WORK-005 让平台第一次调用外部模型，但那次是**一次调用、没有会话、没有记忆、没有工具**——助手只会把当前条目压成一张卡片。WORK-004 让内容可读，但平台对"这个人读到哪、卡在哪、问过什么"依然一无所知。

本项要把这条链路推到底：把助手从"一个按钮"变成**能对话的常驻入口**，让它**记住**这个学习者（但只记给自己），给它**工具**去查、去写一份属于学习者自己的笔记，并让这份笔记能被**安全地分享**出去。它同时是"千人千面"里第一块真正带用户私有数据的拼图。

原计划的 WORK-007（个人笔记与只读分享）已并入本项——因为用户裁决助手要能写笔记，两项无法再各自独立验收。

## 目标

- 学习者在任意页面可打开助手并**多轮对话**；正文流式到达，思考过程默认折叠、可展开。
- 助手**记得**这个学习者：学习状态（结构化）与"说过的话"（全文检索）两路，**只用本人记忆**。
- 学习者能在设置里**看到并逐条删除**自己的记忆。
- 助手能用工具**查**知识库与本人标记，能**写**本人私有数据与**个人笔记**。
- 助手可基于记忆**建议**下一步，但**不自己动作**。
- 学习者能创建／编辑自己的笔记，并把 AI 生成的内容放进笔记；笔记可**只读分享**（免登录可读、id 不可枚举、可撤回、有固定有效期），可被**举报**并由管理员**下架**。
- 注销即**级联硬删**全部用户私有数据，注销后不可访问。
- 全程纯 BYOK，用量返还用户。

## 非目标

- **不做依赖学习状态的自主行为**（掌握度、作答、学习路径至今无数据、无归属）——第 7 条已把自主的依据限定为记忆与对话。
- **不做平台兜底 Key、不做体验额度、不做成本记账**（第 9 条）。
- **不做向量检索与语义记忆**（既有否决未变）。
- **不做记忆的编辑**、不做记忆的分享（第 3、13 条）。
- **不做宽限期删除或恢复**：注销即硬删（第 10 条）。
- **不引入可观测性栈**（D-15 暂缓）。
- **不做多实例部署**；本项不动服务器形态。
- **不做定时任务**（第 10 条要求注销即删；会话有效期与分享到期的判定走读取时校验，不靠定时清理）。
- 不做练习题、作答、判分、掌握度、学习路径——仍无人承接。

## 用户与工作流程

**学习者 · 对话与记忆**

1. 在任意页面打开助手 → 可自由提问；若当前在条目页，该条目作为**可选**上下文自动带上。
2. 正文流式显示；思考过程另存一区、默认收起，可点开。
3. 追问若干轮 → 会话自动持久化；换到桌面端继续，同一会话可见。
4. 关闭再回来 → 助手"记得"此前说过的内容与标记过的懂／不懂。
5. 进设置 → 能看到"它记住了什么"，可逐条删除。

**学习者 · 用工具与笔记**

6. 问"把我标记为还不懂的条目找出来" → 助手调用只读工具返回列表。
7. 说"帮我记一条笔记" → 助手创建笔记（挂在对应条目上），**用户点击确认后才写入**。
8. 打开笔记页 → 可继续手写编辑；AI 生成的内容可以作为一段落进笔记。

**学习者 · 分享**

9. 对某条笔记点"分享" → 得到一条链接与固定有效期；链接**免登录**可读，但看不到作者的记忆与学习痕迹。
10. 需要时**提前撤回**；到期后链接自动失效。
11. 发现不当内容 → **举报**；管理员在管理端**下架**，下架后链接立即不可读。

**注销**

12. 注销 → 会话、记忆、笔记、已发出的分享**全部删除**，本人也无法再访问。

**管理员**

13. 在管理端处理举报、下架被分享的内容。

## 功能需求

- **REQ-001 多轮对话**：助手在任意页面可打开并保持多轮上下文；条目作为**可选**上下文。对话与 WORK-005 的精简壳共用同一入口。
- **REQ-002 流式与思考分离**：正文以流式到达；思考过程单独成区、默认折叠、可展开；两类事件在协议与渲染上都分开。
- **REQ-003 会话持久化**：会话与消息服务端存储，Web 与桌面共享；有条数上限与有效期；超限与过期按设计规则处理且对用户可见。
- **REQ-004 记忆写入与召回**：记忆分结构化与全文两路；写入发生在对话结束或系统提炼时；召回在生成前进行，两路各自可命中。
- **REQ-005 记忆只属于本人**：任何接口都不返回他人记忆；不提供分享开关；记忆不进入任何分享产物。
- **REQ-006 记忆的自我管理**：设置内可列出本人的记忆并**逐条删除**；删除后不再被召回。
- **REQ-007 工具：只读**：提供检索条目、查分类、读本人标记与本人记忆的只读工具；越权访问被拒。
- **REQ-008 工具：写本人私有数据**：助手可写本人的记忆与自评标记；**必须由用户确认后才写入**；不能写他人数据。
- **REQ-009 助手写个人笔记**：助手可创建／修改**本人**笔记；不能改他人笔记。
- **REQ-010 建议而非自主动作**：助手可基于记忆与对话给出建议，但**不自己发起写操作**——未经点击不产生任何写入。
- **REQ-011 个人笔记**：创建、编辑、持久化，挂靠知识条目；可放入 AI 生成的内容。
- **REQ-012 只读分享**：分享链接**免登录可读**、id 不可枚举；有**固定有效期**且**可提前撤回**；分享内容**不含**记忆与学习痕迹。
- **REQ-013 举报与下架**：提供举报入口；管理员可下架；下架后链接立即不可读。
- **REQ-014 注销级联硬删**：注销即删除会话、记忆、笔记与已发出的分享，不可恢复；注销后本人与任何人都不再能访问。
- **REQ-015 BYOK 与用量**：保持纯 BYOK；平台不承担成本；每次调用的 token 用量返还用户；运行时按用户限流。
- **REQ-016 工具与结构化输出并存**：在**既有工具、又需要结构化输出**的前提下仍能正确工作（须绕开"DeepSeek 工具与结构化输出不可并用"的限制）。

## 质量要求

- **越权防护是信任边界**：所有写路径与读取路径都必须校验归属；记忆、会话、笔记三者不得跨用户泄漏。要按"匿名 401 / 他人 403 或空 / 本人放行"三态分别有自动化检查。
- **免鉴权面收敛**：分享端点必须 id 不可枚举；分享产物不得携带记忆、标记、作者身份等学习痕迹。这是全项目第二处免鉴权读端点，须与 `GET /files/{uuid}` 用同一套纪律。
- **写操作可追溯**：助手发起的写必须由用户点击确认，且能分辨"用户写的"与"助手写的"。
- **失败可见不静默**：模型调用失败、工具失败、分享失效都要给出可见结果，不静默吞掉；不把上游原始报文透给用户（沿用 WORK-005）。
- **成本可见**：多轮对话的 token 消耗远大于单次摘要，用量必须继续返还用户。
- **思考与正文不混**：折叠不是隐藏实现细节，是避免把中间推理误读为正式答案。
- **不作弊的完成**：测试证据要能证明"工具真的被调用了""分享真的免登录可读且不可枚举""注销真的删干净了"。

## 约束与依赖

- **框架**：维持 AgentScope Java（D-09），业务代码不直接依赖其类型，收在 WORK-005 建立的薄端口之后。
- **模型**：默认 DeepSeek，端点与模型可改；`max_tokens` 必须给足以避开"思考 token 吃满导致静默空响应"。
- **工具 + 结构化输出**：已记的 DeepSeek 限制要求本项给出明确方案（见 REQ-016）。
- **部署形态不变**：单实例、无 Docker、仅 8081 公网可达、无定时任务基设——会话有效期与分享到期**不得**依赖定时清理。
- **公开仓库**：凭据与服务器信息不入库。
- **数据遗留**：`paideia` 与 `paideia_test` 两个库共用的迁移纪律、编号不写死（沿用既有约定）。

- **AC-009**：助手给出建议时，**未经点击不产生任何写入**（有自动化检查，证明调用次数为零）。

- **AC-011**：分享链接**免登录**可读；id 不可枚举；分享内容不含记忆与学习痕迹（有自动化检查）。
- **AC-012**：分享可提前撤回；到期后链接自动失效（有自动化检查）。
- **AC-013**：举报入口存在；管理员可下架；下架后链接立即不可读（有自动化检查）。
- **AC-014**：注销后会话、记忆、笔记与已发出的分享全部删除，且任何人（含本人）不可再访问（有自动化检查）。
- **AC-015**：无凭据用户不能触发生成；有凭据用户的 token 用量返还（有自动化检查）。
- **AC-016**：在**同时使用工具**的场景下，需要结构化输出的调用仍能正确取回并校验（有自动化检查；这是 REQ-016 的核心证据）。

## 假设

1. WORK-005 的薄端口可以在不改业务代码的前提下扩展出"多轮 + 工具 + 流式"三类能力；若不可行，须先在设计阶段调整端口形状并回填 `design.md`。

4. 本项规模很大，但用户已裁决一次做全；实施顺序按 `tasks.md` 的纵向切片推进。
