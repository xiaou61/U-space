# 任务 · 流式 Markdown 渲染（终止·增量·降级）

**选型已定**：`streamdown@2.7.0`（内含 `remend`）。**"自研四层"方案作废**（2026-10-16 用户看过调研与体积实测后确认）。所以本项不再是"实现补全/切分/增量/降级"，而是**接线 + 按需插件 + 我们自己的语料与验收口径 + 兜底降级**。

**排序原则**：先把**接线**落地、让既有 30 条 e2e 全绿（证明换渲染器没弄坏现状）；再建**语料与三条口径**（那是"稳不稳"的唯一度量，也是用户要的"大量测试"的落点）；最后接**按需插件**与**兜底降级**。体积与懒加载跟接线一起做——它是"换依赖"的直接代价。

## 验收要点（对应 AC）

- **AC-001/002**（T-02、T-01）——渲染生效、未闭合围栏不破形。
- **AC-003**（T-06）——**逐前缀等价 0 例不一致**（本项核心）。
- **AC-004**（T-07）——增量真的省。
- **AC-005**（T-09）——降级可见且不跳。
- **AC-006**（T-02/T-03）——代码块与表格在流式下不闪（e2e）。
- **AC-007**（T-08）——安全回归。
- **AC-008**（T-04）——单一实现，两端一致。

## 风险与默认处置

- **体积**：实测 +343KB（852KB→1204KB）。默认处置：**T-03 懒加载**，让主包不受影响；若懒加载后仍不可接受，退路是"只在助手面板内用 Streamdown，条目页继续用旧渲染器"——**但那会造成两套行为，与 AC-008 冲突**，所以退路要连 AC-008 一起改，须用户裁决。
- **上游演进**（它 696 commits、版本快）：**钉版本** + **我们的语料回归**是唯一的缓冲。升级命名版本时必须先跑语料。
- **`@source` 少了会静默缺样式**：T-01 要求做一次反向验证（把那一行删掉，确认能复现"样式缺失"）——否则将来有人"清理无用配置"时会把它删掉。
- **未闭合补全永远是概率性的**：AC-003 若在真实语料上无法到 0 例不一致，**那一类必须明确降级为纯文本并登记**，不放宽断言。
