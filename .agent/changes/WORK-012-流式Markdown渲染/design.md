# 设计 · 流式 Markdown 渲染（终止·增量·降级）

## 1. 谁负责哪一层

`streamdown` 已经实现了**终止（remend）/ 块切分 / 块级 memo / 处理器缓存 / 非阻塞更新**。所以我们的责任变成下面五件——**每件都有明确的验收**，不是"接上就行"：

| 我们负责 | 为什么是我们的 |
| --- | --- |
| ① **按需加载**（T-03） | 体积实测 +343KB，不能让主包白背。助手面板是**打开才用**的，天然适合懒加载 |
| ② **三处共用一套**（T-04） | 助手回答、条目页、管理端预览若各用一套，就会出现"两套 markdown 行为"。渲染器要从 `@paideia/knowledge` 挪到 `@paideia/ui` |
| ③ **语料与三条口径**（T-05..T-08） | **这是"稳不稳"的唯一度量**。上游的测试不是我们的测试 |
| ④ **兜底降级**（T-09） | remend 补不出来的输入仍要有出路（opencode 的做法） |
| ⑤ **按需插件**（T-11） | 公式 / mermaid / CJK 只在真需要时装，且必须懒加载，否则体积回到两位数 MB |

## 2. 接线点（具体到文件）

- `frontend/packages/assistant/src/conversation-panel.tsx`：**助手回答**走 `<Streamdown isAnimating={busy}>`；**用户消息**与**我们自己给的提示文案**（`emptyHint` 那条）仍走纯文本——那条提示不是模型输出，被当 markdown 解析是错的。
- `frontend/packages/ui/src/styles/globals.css`：`@source '../../../../node_modules/streamdown/dist/*.js'`。
  **这一行不给会静默缺样式**（标题没间距、代码块没底色），不报错。**T-01 必须做一次反向验证**（删掉它、确认能复现），否则将来会被当"无用配置"清理掉。
- `packages/assistant/package.json`：`streamdown` **钉版本**（不用 `^`），与项目既有风格一致。

## 3. 懒加载策略（T-03）

`Streamdown` 只在**助手面板展开且至少有一条助手消息**时才需要。用 `React.lazy` + `Suspense` 包一层，并把 `import('streamdown')` 放在懒加载的组件文件里，让打包器把它切成独立 chunk。

- **验收**：主 chunk 尺寸回到接线前的水位（≈836KB），Streamdown 独立成 chunk。
- **代价与注意**：懒加载会引入一次"首次渲染时的挂起"。用 `Suspense` 的 fallback 显示**原文**（而不是空白）——即"markdown 还没加载好时先按纯文本显示"，避免出现空白气泡。
  ponytail: 这条 fallback 不是装饰，是**必须的**：流式场景下空白比"格式晚一步"糟得多。

## 4. 语料与三条验收口径（本项的核心）

### 4.1 语料存的是**增量序列**，不是最终文本

界面收到的本来就是**增量**（`content` delta）。所以语料采集（`scripts/collect-md-corpus.mjs`）**用流式调用、把有序的 delta 数组存下来**：

```json
{ "id": "table-mixed", "prompt": "…", "deltas": ["…", "…"], "text": "拼起来的全文" }
```

回放真实增量，比"把整段按字符切开"**忠实得多**——后者会掩盖"上游一次吐一大段"这种真实分布。

**凭据只从环境变量读，不进仓库也不进日志**；产物是纯模型输出，可以提交。

### 4.2 三条口径

| 口径 | 怎么测 | 为什么是它 |
| --- | --- | --- |
| **逐前缀等价** | 对每条语料，把 delta 逐个累加，在**每个前缀**上渲染一次；取渲染结果的**顶层块**（`container.children`），断言"**除最后一块外，其余块的 DOM 完全相同**" | 这是"已完成块不变形"的直接可观测形式——**把"百分百"变成一个能红的断言** |
| **已完成块不重解析** | 通过 `components` 映射注入**计数器**（自定义 `p`/`li`/`pre` 等组件），统计每个前缀的组件调用次数；断言**已完成块的调用次数不随前缀增长** | 真正的 md 解析次数不可从外部观测，**组件调用次数是它可观测的代理**；memo 失效时它必然增长 |
| **安全** | 语料里含 `<script>` / `javascript:` 链接 / 裸 HTML / `allowedTags` 边界 | 信任边界，按项目纪律不做懒处理 |

**不是墙钟时间**：CI 上时间不稳，用计数与结构等价这类**确定性**指标。

### 4.3 语料要覆盖什么

代码块（含长代码与多语言标记）、表格、嵌套列表、引用、标题层级、行内 code/粗斜体、混合排版（标题+代码+表格+列表同一段），外加**恶劣输入**：深嵌套列表、半截围栏、HTML 与 markdown 混排、超长回答（验证性能口径）。

## 5. 降级规则（T-09）

补全**能确定**时才补；**不能确定**时走降级：

1. 找到**最后一个安全边界**（不在围栏内、不在未闭合的 HTML 内、`$$` 成对）；
2. 边界之后的那一截**按纯文本渲染**；
3. **该片段不随后续 delta 改形**——它要么保持纯文本，要么等边界确定后整块变成结构化内容（那一次变化是可接受的，因为它是"从无格式到有格式"，不是"从错到对"）。

**绝不允许**的形态：先把未完成内容渲染成一个**结构**，随后续 token 又改形（那是"跳"，也是 opencode 那些 bug 的来源）。

## 6. 安全

- 沿用 `streamdown` 自带的 `rehype-harden` / sanitize 管线；
- 补全注入的**占位 URL**（如未完成链接塞的占位）**不得成为可点外链**——要有断言；
- `allowedTags` 一旦为平台自定义元素放行，**放行清单要显式列出属性**（不能整标签放行）。

## 7. 已知缺口（登记）

1. **上游内部的补全逻辑不是我们的代码**：它错了我们只能等/绕/固定版本。**语料回归是唯一缓冲**。
2. **懒加载会带来一次挂起**：首次出现回答时可能"先纯文本、后格式化"（这是刻意选的，见 §3）。
3. **性能口径是代理指标**（组件调用次数），不是真实解析耗时。
4. **公式 / mermaid 一期不装**：它们是插件，装了要按需加载（T-11）；本项只保证"接得进来"。
